# 지식 저장소 운영 — 언제 무엇을 기록하나

요청자 지시(2026-10-15): 원자료 기록 시점과 저장소 갱신 시점을 정해 두고, 개발 일지와 사용 설명서도 만든다. 기록은 Claude 가 하고 요청자는 지시와 확인만 한다. 저장소 `.claude/CLAUDE.md` 에도 같은 규칙 한 줄을 둔다.

## 원자료를 넣는 때

| 사건 | 원자료 종류 | 파일 | 시점 |
|---|---|---|---|
| 요청자가 말한다(결정 · 지시 · 지적 · 질문) | 대화 | `원자료/대화/YYYY-MM-DD_대화_세션기록.md` — 훅이 턴마다 요청자 메시지와 답 전문을 덧붙인다(자르지 않는다, 비밀값 꼴은 가린다). 파일이 `RULES` 의 크기(500KB)를 넘으면 같은 날짜의 `-2` · `-3` 파일로 이어 쓴다. 컨텍스트 정리 직전과 세션 끝에 빠진 것을 보충한다. 사람도 LLM 도 손대지 않는다 | 자동 |
| 설계 브레인스토밍에서 무언가 정해진다 | 대화 | 자동 세션기록이 원문. 결정은 ingest 때 [[90_AI/프로젝트/momo-english-academy/위키/결정/결정-목록\|결정-목록]] 과 닿는 쪽으로 | 정리 때 |
| 검토자 · 편집자 에이전트가 보고를 낸다 | 검토 | `YYYY-MM-DD_검토_<회차>-<A·B·브리프·반영-기록>.md`, 저장소 파일의 사본 | 보고가 나온 즉시 |
| 외부 조사가 끝난다 | 조사 | `YYYY-MM-DD_조사_<대상>.md`, 저장소 docs/research 의 사본 | 조사 완료 즉시 |
| intent · spec · plan 이 승인되거나 검토 회차가 반영된다 | 산출물 | `YYYY-MM-DD_산출물_<문서>-<판>.md` — 커밋 해시 · 경로 · 줄 수와 "이 판에서 바뀐 절" 요약만. 전문은 복사하지 않는다(요청자 결정 2026-10-15 07:4x, 전문은 저장소 git). 그 전에 넣은 spec-v1 · v2 전문 사본은 그대로 둔다 | 승인 · 커밋 직후 |
| 저장소에 커밋한다 | — | 커밋 장부(포인터)는 만들지 않는다(요청자 결정 2026-10-15 08:38: "한 일은 따로 정리하는데 커밋을 굳이 정리할 필요가 있을까"). 한 일은 일지에, 위키가 시점을 말해야 하면 커밋 해시를 글자로 적는다. 그날 만든 포인터 v1~v5 · 당일 파일은 원자료로 남는다 | 커밋 턴에는 일지 · 이어하기 |
| 영상 · 목업 같은 소개 자료가 만들어진다 | 산출물 | 제작 기록(명령 · 문제 · 결과)과 포인터 | 제작 완료 뒤 |
| 구현에서 API · 스키마 · 설정 파일이 생긴다 | 산출물 | 경로 · 커밋 해시와 요약. 코드 자체는 복사하지 않는다 | plan 완료 때 |
| 파이프라인 · 스크립트를 돌린다 | 산출물 | 실행 기록(입력 · 명령 · 결과 · 막힌 것) | 실행 끝난 뒤 |

원자료는 고치지 않는다. 틀린 것을 알면 새 원자료를 더하고 위키에서 바로잡는다. 수기 원자료의 시각은 추정("04:5x")으로 적지 않고 `date` · `git log --date=format-local:%H:%M` 으로 적는다(2026-10-15 검토 K-08). 요청자 메시지 원문이 볼트(iCloud · LiveSync)에 남으므로 비밀값 · 아이 이름은 대화에 적지 않는다. 훅이 키 꼴(`sk-` · `ghp_` · JWT · password=)은 `[가림]` 으로 바꾼다(K-18 · U-11).

## 위키를 고치는 때 (ingest)

요청자 결정(2026-10-15 08:21, "미처리가 있으면 안 된다"): 턴마다 한다. 턴 끝에 세션기록에 옮길 결정 · 지시 · 지적이 있으면 위키에 넣고, 없어도 `--mark-ingest` 로 이번 턴까지 표시한다. 같은 날 새벽의 "세 때에 몰아서" 결정을 뒤집은 것이다([[90_AI/프로젝트/momo-english-academy/원자료/대화/2026-10-15_대화_세션기록\|2026-10-15_대화_세션기록]]). 아래 세 때는 턴마다 정리에 더해 묶어서 점검하는 때다.

| 때 | 왜 |
|---|---|
| 이정표가 생겼을 때(커밋, 검토 회차 반영, intent · spec · plan 승인, 구현 차수 완료) | 판본과 결정이 확정되어 정리할 거리가 분명하다 |
| 세션을 마무리할 때(`/wrap-up`) | 그날 맥락이 머리에 있을 때 정리해야 품질이 좋다 |
| 다음 세션 시작(지난 세션에서 정리 안 된 턴이 남았으면) | 세션이 비정상으로 끊긴 경우의 안전망. SessionStart 훅이 목록을 알리고, 첫 턴에서 먼저 정리 · 표시해야 Stop 훅이 턴을 끝내 준다(요청자 결정 08:21. 05시 검토 뒤 잠시 "알림만"이었는데, 그때 불편은 거짓 경보 K-10 탓이었다) |

검토 보고 · 조사의 사본과 판본은 예외로 그 턴에 넣는다(복사나 포인터라 가볍다). 순서는 여섯 단계다.

| 순서 | 하는 일 |
|---|---|
| 1 | 원자료를 읽고 어느 분류(제품 · 방법론 · 매뉴얼 · 소개 · 공통)의 어느 쪽에 닿는지 정한다. "이 문서는 만드는 것인가, 만드는 방식인가, 쓰는 법인가, 남에게 보여 주는 것인가"로 가른다 |
| 2 | 닿는 쪽을 고치고, 새 개념이면 쪽을 만든다. 쪽의 `sources` 와 본문 링크에 원자료를 단다 |
| 3 | 기존 문장과 어긋나면 지우지 않고 "충돌 · 미확정" 절에 둘 다 적는다 |
| 4 | `index.md` 의 한 줄 요약과 원자료 표를 고친다 |
| 5 | `log.md` 에 `날짜 · ingest · 원자료 → 바뀐 쪽` 한 줄을 남긴다 |
| 6 | `python3 ~/.claude/hooks/vault_check.py --mark-ingest` 로 마지막 ingest 시각과 세션기록에서 정리한 턴 수를 상태 파일에 적는다. 미처리 판정은 이 기록을 기준으로 한다(log.md 수정 시각 하나에 걸지 않는다). 진행 중인 턴의 메시지도 정리한 턴으로 센다. 옮길 것이 없는 턴은 이 단계만 한다 |

## 새 프로젝트에서 시작하기

저장소를 열었는데 볼트 `프로젝트/<이름>/` 이 없으면 SessionStart 가 알린다. "기록 시작해"라고 하면 Claude 가 `python3 ~/.claude/hooks/vault_check.py --init` 를 돌려 템플릿대로 폴더와 `claude/INDEX.md` 한 줄을 만들고, 그 턴부터 다른 프로젝트와 똑같이 기록한다. 기록 안 할 저장소는 그대로 두면 알림 한 줄 말고는 아무 일도 없다(09:15 요청자 결정).

## 묻는 때 (query)

위키에 물을 때는 [[90_AI/프로젝트/momo-english-academy/index\|index]] 를 먼저 읽고 닿는 쪽을 열어 출처(원자료 링크)와 함께 답한다. 여러 쪽을 합쳐 새로 만든 통합이면 그 내용을 가장 가까운 쪽에 되돌려 넣고 `log.md` 에 `날짜 · query · 물음 → 넣은 쪽` 한 줄을 남긴다. 위키에 없는 것은 없다고 말한다.

## 점검하는 때 (lint)

| 때 | 하는 일 |
|---|---|
| 검토 회차가 끝났을 때 | 반영본 spec 과 제품 쪽(시스템-구성 · 데이터-모델 · AI-호출 · 수업-생성 · 사다리와-승급)을 절마다 대조해 낡은 문장을 고치고 프론트매터 `basis` 를 새 판으로 올린다. 대조는 쪽을 쓴 에이전트가 아니라 검토자(analyst)가 한다(첫날부터 틀린 통합이 생겼다) |
| 저장소에 커밋했을 때 | 일지에 한 일을 적고 문서-관계 표를 다시 만든다 |
| 작업 세션이 끝날 때 | `--lint --fix`: 끊긴 링크, 볼트 전체에서 이름이 겹치는 기본 이름 링크, 들어오는 링크 없는 쪽(어느 쪽에서도 가리키지 않아 목차로만 닿는 쪽), `sources` 가 비어 있는 쪽, 어느 쪽에도 인용되지 않은 원자료, 제품 쪽 `basis` 가 최신 spec 사본보다 낡은 것, 일지 링크 꼴, `미커밋` 같은 낡은 문장 후보를 찾는다. 교차표를 다시 만든다 |
| 주 1회 | 충돌 절에 남은 것 가운데 요청자 결정으로 닫힌 것을 정리한다 |

## 이어하기를 고치는 때

커밋한 턴, 코드 작업이 45분 넘게 기록 없이 이어진 턴, 세션 마무리(`/wrap-up`)에 볼트 `이어하기.md` 의 세 절(지금 하던 것 · 다음 한 걸음 · 열린 질문)을 지금 기준으로 고친다. Stop 훅이 검사한다. 설계 문서만 바뀐 턴은 log 한 줄로 족하다(2026-10-15 검토: 작업 턴마다 세 절을 손대는 것은 과했고 자동 절이 빈틈을 메운다). 맨 아래 자동 기록 절은 SessionEnd · PreCompact 훅이 쓴다. Stop 훅은 답을 끝낼 때마다 돌고, `/clear` 와 종료 때는 SessionEnd 가 돈다. 그래서 사람이 쓰는 세 절과 훅이 쓰는 자동 절을 겹쳐 두어, 어느 쪽으로 끊겨도 다음 세션이 이어 간다. 사용량 한도로 턴 중간에 끊기면 Stop · SessionEnd 가 돌지 않을 수 있는데, 그때는 다음 SessionStart 가 상태 파일로 끊김을 알아내 자동 절을 복구하고 끊긴 지시를 세션기록에 넣는다.

## 일지를 쓰는 때

작업 세션이 끝날 때 `일지/YYYY-MM-DD.md` 를 쓴다. 하루에 세션이 여러 번이면 같은 날 쪽에 절을 더한다. 틀은 [[90_AI/프로젝트/momo-english-academy/일지/README\|일지 쓰는 법]] 에 있고, 바이브 코딩 교육에 쓸 수 있도록 "사람이 한 것과 AI 가 한 것"을 갈라 적는다.

## 그림을 그리는 때와 방식

쪽이 구조 · 흐름 · 관계를 설명하면 그림을 붙인다. `vault-diagram` 스킬의 생성기를 쓰고, 영역(탭 라벨) · 번호 카드 · 아이콘 타일 · ERD 표처럼 틀이 있는 요소를 쓴다. 단순 박스 나열은 피한다. 저장 전에 실제 엔진으로 렌더해 관통 · 겹침 · 글자 가로지름 0 과 글자가 박스 안에 드는 것을 확인하고, 위키 쪽에 임베드한다. 기준과 환경은 [[90_AI/프로젝트/momo-english-academy/위키/매뉴얼/개발-환경-설명서\|개발-환경-설명서]].

## 공개하는 때

`90_AI/` 노트는 [[90_AI/지식저장소/위키/공개-사이트\|공개-사이트]] 규칙대로 웹에 나간다(요청자 결정 2026-10-22). 노트를 만들거나 옮긴 뒤 `python3 90_AI/지식저장소/도구/dg-mark.py --apply` 로 `dg-publish` 표시를 맞추고, 발행은 요청자가 Obsidian 명령 "Digital Garden: Publish Multiple Notes" 로 한다. 원자료 · 운영 파일 · 도구는 규칙상 나가지 않으므로, 공개가 곤란한 내용은 원자료에 둔다.

## 강제 장치 (요청자 지시 2026-10-15 "확인할 수 있는 강제력")

사용자 수준 `~/.claude/settings.json` 의 훅 6개가 `~/.claude/hooks/vault_check.py` 를 부른다(정본은 `지식저장소/도구/`, 설치는 [[90_AI/지식저장소/도구/설치\|설치]]). 훅은 열린 저장소 이름으로 볼트 `프로젝트/<이름>/` 을 찾고, 없으면 git 저장소일 때 세션 시작에 `--init` 안내 한 줄만 낸다. 메모리는 세션을 연 디렉터리에 묶이므로 믿지 않는다. 처음에는 저장소마다 `.claude/` 에 복사했는데 2026-10-15 09:15 요청자 결정으로 한 벌로 바꿨다.

| 훅 | 하는 일 |
|---|---|
| SessionStart(새 세션 · `/clear` · 컨텍스트 압축 뒤) | 기록 규칙 요약, `이어하기.md` 전문, 밀린 일지(지난 세션에 쓰지 않은 일지), 차단 한도를 넘겨 미뤄진 요구, 지난 볼트 접근 실패, 미처리 원자료 목록(마지막 `--mark-ingest` 뒤 생긴 것)을 세션 컨텍스트에 넣고, 있으면 첫 턴에서 먼저 정리하라고 알린다. 지난 세션의 마지막 턴이 답 없이 끊겼으면(사용량 한도 · 강제 종료. 턴 시작 시각이 마지막 Stop 시각보다 뒤) 그 지시를 세션기록에 넣고, 이어하기 자동 절을 다시 쓰고, 그 턴 뒤 바뀐 저장소 · 볼트 파일을 "끊긴 턴"으로 알린다. 압축 뒤 재시작은 끊김으로 보지 않는다(요청자 "종종 사용량 때문에 작업이 중단된다", 08:51) |
| UserPromptSubmit | 턴 시작 시각과 요청자 메시지를 `~/.claude/vault-state/<이름>/turn.json` 에 적는다. 직전 턴이 끝나지 않은 중간 메시지면 턴을 합친다 |
| PostToolUse(Write · Edit · MultiEdit · NotebookEdit · Bash) | Claude 가 쓴 파일 경로를 적는다. 그래서 LiveSync · iCloud 가 내려받은 볼트 변경은 "볼트 변경"으로 세지 않는다. Bash 가 볼트를 건드리면 그 턴은 수정 시각 기준으로 본다 |
| Stop | 요청자 메시지 · 답 전문을 자동 세션기록에 덧붙인다(비밀값 꼴은 가린다). 그 다음 턴을 끝내기 전에 검사한다. 요구 조건은 아래 "얼마나 자주" 표. 조건에 걸렸는데 안 됐으면 차단(`decision: block`)하고 이유에 바뀐 파일과 할 일을 적는다. 짧은 턴이라도 변경이 있으면 검사한다. 정리 안 된 세션기록 턴 · 원자료가 있으면(지난 세션 것 포함) 변경이 없어도 막는다. 한 턴에 차단 한도(`RULES`)를 넘기면 요구를 `debt.json` 에 남기고 통과하며, 다음 턴 · 다음 세션 시작에 다시 올린다 |
| PreCompact(컨텍스트 정리 직전) | 자동 세션기록을 보충하고 `이어하기.md` 자동 기록 절을 쓴다. 정리 뒤 SessionStart(압축)가 그것을 다시 넣어 준다 |
| SessionEnd(`/clear` · 종료 · 로그아웃) | 자동 세션기록을 보충하고 `이어하기.md` 의 자동 기록 절(세션 끝 이유 · 마지막 지시 · 마지막 답 요지 · 커밋 · 커밋하지 않은 변경 · 바뀐 볼트 파일)을 다시 쓴다. 세션에 변경이 있었는데 오늘 일지가 없으면 `debt.json` 을 남기고 다음 세션 첫 턴에서 Stop 훅이 그 일지를 요구한다 |

볼트 접근(glob · 읽기 · 쓰기)이 실패하면 삼키지 않고 `errors.json` 에 남겨 다음 SessionStart 가 알린다(iCloud 가 파일을 내보낸 경우).

## 얼마나 자주 기록하나 (요청자 지적 2026-10-15 "너무 자주 도는 것 아니냐")

검사는 턴마다 돌지만, 기록을 요구하는 것은 기록할 가치가 있는 사건이 있을 때와 시간 간격뿐이다.

| 턴에서 생긴 일 | 요구 |
|---|---|
| 파일 변경 없음(질문 · 답) | `--mark-ingest` 표시(옮길 결정 · 지시가 있으면 위키에도). 짧은 턴이라도 변경이 있으면 검사한다(10초 만에 끝난 커밋 턴도) |
| 코드 · 설정만 바뀜(src · 테스트 등) | 없음. 마지막 기록 뒤 45분이 지났으면 log 한 줄 + 이어하기 |
| 프로젝트가 빼 둔 경로만 바뀜(`RULES` 의 SKIP_REPO_PREFIXES — 모모는 `seed/`) | 저장소 변경으로 세지 않는다. 시드 생성 결과는 저장소 커밋 · seed/manifest · 검토 보고로 남는다(요청자 결정 2026-10-23, 모모 H9) |
| 설계 문서 · 규약 · 검토 장부가 바뀜(intent · specs · plans · .claude · docs/research · .superpowers) | log 한 줄 |
| 검토 보고 · 조사 파일이 새로 생김 | 위에 더해 원자료 사본과 닿는 위키 쪽 |
| 커밋 | 위에 더해 오늘 일지, 이어하기 세 절. intent · spec · plan 판본이 바뀌었으면 산출물 원자료(커밋 해시 + 바뀐 절 요약) |
| 볼트 원자료 · 위키를 Claude 가 고침(동기화로 내려온 변경은 세지 않는다) | log 한 줄 |

표시(`--mark-ingest`)는 모든 턴에 든다. 구현 단계에서 코드를 고치는 턴이 이어지면 그 밖에는 45분마다 한 줄이 전부다. 설계 결정과 커밋은 그 자리에서 남긴다. 수치(차단 한도 · 간격 · 남기는 글자 수)는 `vault_check.py` 머리의 `RULES` 상수가 정본이고 `--rules` 가 표로 찍는다. 이 쪽과 CLAUDE.md 의 숫자는 그것을 옮겨 적은 것이라 어긋나면 상수를 따른다.

| 확인 | 명령 |
|---|---|
| 상태표(log 갱신 시각 · 오늘 일지 · 이번 턴 변경 · 밀린 일지 · log 보다 새 파일) | `python3 ~/.claude/hooks/vault_check.py --report` |
| 끊긴 링크 · 이름 겹침 · 들어오는 링크 없는 쪽 · sources · 인용 안 된 원자료 · basis · 일지 링크 · 낡은 문장 후보 검사와 교차표 재생성 | `python3 ~/.claude/hooks/vault_check.py --lint --fix` |
| 규칙 상수 표 | `python3 ~/.claude/hooks/vault_check.py --rules` |
| 이번 턴까지 정리했다고 표시(턴마다) | `python3 ~/.claude/hooks/vault_check.py --mark-ingest` |

절차는 스킬 `/vault-ingest` · `/vault-lint` · `/journal` · `/wrap-up` 에 있고, 규약 `.claude/CLAUDE.md` 에는 짧은 두 줄(기록 · 꺼내 쓰기)만 두고 이 쪽을 가리킨다(요청자 지시 08:25: CLAUDE.md 는 간결하게, 자세한 것은 참조). 훅은 settings.json 을 고친 뒤 세션을 새로 열어야 걸린다. 공식 문서 확인: Stop 은 stdout JSON `decision: block` + `reason`, SessionStart · UserPromptSubmit 은 exit 0 의 평문 stdout 이 컨텍스트에 들어가고(요청자 화면에는 안 나온다. 훅이 도는지는 `--report` 로 본다. 화면 표시는 안 하기로, 요청자 결정 09:47), SessionEnd 는 Claude 에게 말을 걸 수 없어 밀린 일지를 debt.json 에 적어 다음 세션에 넘긴다. Claude Code 자체도 연속 계속을 8회로 막는다.
