세 사이트가 답을 다르게 낸 질문은 하나다 — **"기록을 누가, 어느 시점에, 어떤 비용으로 넣는가."**

- 치바데: **넣지 않는다.** 진행만 돕고 끝.
- 기록실: **진행하는 김에 넣는다.** 도구가 입력기라서 추가 비용 0.
- 치즈스톰: **끝나고 넣되 AI가 대신 읽는다.** 진행 도구가 없으니 사후 입력밖에 없고, 그 비용을 OCR로 깎았다.

dbdzzk는 치바데와 같은 자리(진행만)에 있으면서 v3에서 기록실 자리로 가려다 멈췄다.

## dbdzzk가 가져올 것

### 1. 신뢰 경계를 구조로 만든다
기록실은 `스트리머 입력 = 즉시 / 시청자 입력 = 승인 후`로 나눠 놓고도 "기록 오염 사용자 임시조치" 공지를 냈다. **공개 통계를 열면 오염은 반드시 온다.**
dbdzzk는 지금 익명 인증 + 방 소유자만 쓰기다. 진행 도구로는 충분하지만 공개 전적으로 가는 순간 부족하다. 최소한 `치지직 OAuth → 본인 확인된 스트리머 = 즉시 / 그 외 = 승인 대기`가 필요하다.

### 2. 진행 → 기록 자동 승격
기록실 경기 데이터에 `source: "helper"`가 박혀 있다. 도구에서 나온 기록임을 데이터가 스스로 증언한다.
dbdzzk도 방이 이미 라운드를 다 갖고 있으니, **방 종료 시 라운드를 전적으로 승격하는 경로**만 만들면 된다 (v3의 `freezeRoom`이 이 자리였다).

### 3. 집계는 스냅샷이어야 한다
기록실 티어표는 `2026-08-07 22:00 기준` 같은 **버전을 골라 볼 수 있다.** 레이팅 알고리즘을 고치면(실제로 08-14, 08-24 두 번 고쳤다) 과거 티어가 통째로 흔들리기 때문이다.
dbdzzk v3의 Elo 재생 결정성 논의와 같은 문제다. 재계산 가능한 지표는 **찍은 시점을 함께 저장**해야 한다.

### 4. 오버레이는 채널 단위로
dbdzzk는 `/room/{코드}/overlay` — 내전마다 OBS 소스를 갈아야 한다.
기록실은 채널 주소를 한 번 등록하면 **내전이 열리면 자동으로 뜨고 끝나면 사라진다.** 스트리머 입장에서 이 차이는 크다. 구조 변경 비용도 크지 않다 — 채널 → 현재 활성 방을 찾는 인디렉션 한 겹.

### 5. 자동 지표를 스스로 불신한다
치즈스톰은 Elo를 만들어 놓고 "내전은 의도적으로 밸런싱되므로 실력 지표로 보지 말라"고 못 박았다. 기록실도 "표본" 대신 분모를 매번 적어 둔다("밴율은 밴이 기록된 14개 라운드 기준").
dbdzzk가 티어를 낸다면 같은 정직함이 필요하다. [[90_AI/프로젝트/dbdzzk/README\|README]]의 "근거 없는 S티어 차단" 방침과 같은 맥락.

## 냉정한 판단

기록실이 **DBD 내전의 기록·레이팅을 사실상 표준화**했다. 62명·614경기·게시판 피드백·공지 3건이 쌓여 있고, 진행 도구까지 자기가 소유해 입력 경로를 잠갔다.

dbdzzk v3(공개 전적·티어·맞밸)를 그대로 재개하면 **정면 충돌이고 데이터가 없는 쪽이 진다.** 남는 선택지는 셋이다.

1. **진행 UX 특화** — 기록은 포기하고 치바데/기록실 도구보다 나은 진행 경험만 판다. dbdzzk의 블러드웹 그래프·드래그 팀편성·치지직 프로필 자동 매칭은 이미 그 방향이다.
2. **기록실 API 소비** ← **채택 (2026-09-01)** — `/api/*`가 무인증으로 열려 있다. 진행 도구는 dbdzzk, 전적은 기록실 데이터를 읽어 온다.
3. **종료** — 현재 상태(2026-08-19 중단)를 유지.
