## 실시간 연동 — RTDB 보안 규칙이 설계도다

`database.rules.json` 최상단이 `.read: false / .write: false`. 열린 건 `scoreboardRooms/$roomId` 하나뿐.

```
scoreboardRooms/$roomId
  version(=1) · ownerUid · status(='active') · createdAt · updatedAt · expiresAt
  hostDisconnectedAt · hostConnections/$connectionId
  scoreboard/
    mode · thomasCount · adaCount · thomasName · adaName · firstAttackerId
    fearlessEnabled · killerBans/$killerId
    pickerUi/{ sel, selSeq, fb/{k,kind,t} }
    thomas/$index/{ id, name, kills, played, killer, killerPicks/$pickIndex/{killerId} }
    ada/$index/{ ... }
```

> [!info] 팀 이름이 내부적으로 `thomas` / `ada`다
> 화면엔 `A팀` / `B팀`으로 나오지만 데이터 모델과 코드 전역이 DBD 캐릭터 이름(Thomas = 슬래셔, Ada = 에이다 웡)을 쓴다. `type Team = "thomas" | "ada"`.

### 규칙에서 읽히는 보안 설계

| 장치 | 규칙 |
|---|---|
| 방 ID | `$roomId.matches(/^[a-f0-9]{48,128}$/)` — 최소 48자리 hex |
| 초대 토큰 전달 | `#room=<hex>` **URL 프래그먼트** (`INVITE_TOKEN_HASH_RE`) → 서버 로그·리퍼러에 안 남는다. 읽고 나서 `clearInviteTokenFromUrl()` |
| TTL | `ROOM_TTL_MS = 3 * 60 * 60 * 1000` (3시간). `expiresAt <= now + 10805000` 으로 규칙이 상한을 강제 |
| 읽기 | `status === 'active'` **그리고** `expiresAt > now` **그리고** 호스트 끊긴 지 3시간 이내 |
| 쓰기 | `ownerUid === auth.uid` — 뷰어는 규칙 레벨에서 못 쓴다. UI 제한이 아니다 |
| 불변 필드 | `ownerUid`·`createdAt`은 `newData.val() === data.val()` 로 고정 |
| 시계 조작 방지 | 모든 타임스탬프가 `<= now + 5000` |

**"점수 조작은 제한됩니다"가 UI 문구가 아니라 서버 규칙이다.** dbdzzk의 Firestore 규칙(방 소유자만 쓰기)과 같은 사상인데, 치바데 쪽이 TTL·호스트 이탈·필드 불변까지 규칙에 밀어 넣었다.
테스트도 있다 — `tests/database.rules.test.ts`를 `firebase emulators:exec --only database`로 돌린다.

## 콜드게임 계산기 — dbdzzk "확정 최소 점수"의 확장판

`lib/cold-warning.ts`. dbdzzk와 **완전히 같은 킬 점수 체계**를 쓴다.

```ts
export const VALID_4V4_STEPS = [1, 2, 3, 3.5, 4] as const
export function toValid4v4Step(rawNeed: number): number   // 실제 득점 가능 단위로 올림
```

`computeCold()`가 내는 상태:

```
none | warning | cold | gameover
```

- `tMax = 현재점수 + 남은주자수 × 4` 로 도달 가능 최댓값을 계산 → 상대 현재 점수에 못 미치면 **콜드게임 확정**
- 확정 직전엔 `warning` + **연계 조건**을 붙인다: `survive_all` / `survive_min` / `survive_and_next_kill`
- `opponentMustSurviveName` — 지금 차례 팀이 1킬만 해도 상대가 콜드 확정되는 경우, **상대팀에게 "이번 판 전원 생존" 경고**를 같이 띄운다. 단 `myRem === 1 && oppRem === 1` (7세트 벼랑끝)일 때만 — "남은 경기가 4경기 이상인 중간 세트에서는 여러 경기를 건너뛰어 혼란을 주므로 표시하지 않음"
- 마지막 한 판만 남으면 콜드 대신 `isGeneral` 경고로 전환, 역전 가능 여부(`isWinPossible`)와 역전승 문구 여부(`isComebackWinNotice`)를 따로 낸다

dbdzzk README의 "확정 최소 점수: 상대의 남은 판을 전부 만점으로 가정" 과 정확히 같은 계산인데, **경고 문구의 경우의 수까지 타입으로 갈라놨다.**
