# 개발 환경 설명서

이 프로젝트에서 사람(요청자)과 Claude 가 일하는 방법이다. 앱 실행 · 테스트 · 배포 명령은 구현 1차에서 생기면 더한다.

## 저장소 열기

| 항목 | 내용 |
|---|---|
| 위치 | `~/workspace/momo-english-academy`(git, main) |
| 세션 시작 | 저장소 안에서 Claude Code 를 연다. 바깥(`~/workspace`)에서 열면 `.claude/agents/` 가 로드되지 않아 `opus-xhigh` 에이전트에 정의 파일을 읽으라고 지시해야 한다 |
| 폴더 | `intent/`(의도) · `specs/`(정본 spec) · `plans/`(구현 계획) · `docs/research/`(조사) · `docs/media/`(소개 영상 스크립트) · `.claude/`(규약 · 에이전트 · 스킬) · `.superpowers/sdd/`(검토 루프 장부) |

## 에이전트 쓰기

| 정의 | 역할 | 쓰는 법 |
|---|---|---|
| analyst | 읽기 전용 검토 · 분석 | 브리프 파일(읽을 것 · 관점 · 보고 형식)을 쓰고 `Agent` 로 띄운다. 보고는 파일로 받는다 |
| curriculum-designer | 단계 can-do · 단원 규격 · 어휘 밴드 초안 | 출력 형식(JSON · TS 시드)과 스키마를 브리프에 |
| implementer | plan 대로 구현 | 한 plan 에 하나. 검토자와 분리 |
| code-reviewer | 코드 검토 | 구현자가 아닌 새 에이전트 |
| design-reviewer | 화면 · 설계 검토 | 스크린샷을 직접 본다 |

모두 최신 Opus · effort xhigh 이고 동시에 2~3개까지다. 브리프와 보고는 파일로 주고받아 대화 컨텍스트에 기대지 않는다.

## 설계 검토 루프 돌리기

| 순서 | 하는 일 |
|---|---|
| 1 | `.superpowers/sdd/<날짜-주제>/progress.md` 장부를 만든다 |
| 2 | 검토자 A(학습 설계 · 사용자) · B(기술 · 데이터 · AI · 운영) 브리프를 쓰고 둘을 동시에 띄운다. 읽기 전용, 보고는 `round-N-a.md` · `round-N-b.md` |
| 3 | 두 보고의 결정 필요 항목을 모아 잠정 결정표를 만들고 `task-rN-apply.md` 브리프에 넣는다 |
| 4 | 편집자 에이전트를 띄워 반영한다. 변경 기록 `round-N-applied.md` |
| 5 | diff 를 점검하고 커밋한다. 볼트 원자료에 보고 · 반영 기록 사본을 넣는다 |
| 6 | Critical · Important 가 0 이 될 때까지 반복하고 3회차마다 요청자에게 잠정 결정표와 함께 보고한다 |

## 소개 영상 다시 만들기

| 순서 | 명령 · 내용 |
|---|---|
| 1 | 목업 `*.dc.html` 을 한곳에 둔다(지금은 세션 스크래치패드 `momo-mockups/project/`, 저장소로 옮길 것) |
| 2 | Python venv 에 playwright · imageio-ffmpeg 를 설치하고 `playwright install chromium` |
| 3 | `python docs/media/capture-mockup-states.py` 로 상태별 캡처와 버튼 좌표 |
| 4 | `python docs/media/build-intro-demo-video.py` 로 프레임 · 내레이션(`say -v Yuna`) · 4K 조립. 15분쯤 걸린다 |
| 5 | 웹용 1440p 판만 전송한다(30MiB 한도). mp4 는 git 에 넣지 않는다 |

## 도표 만들기

| 항목 | 내용 |
|---|---|
| 도구 | `vault-diagram` 스킬. `exgen.py` 로 Excalidraw 파일을 만들고 `exrender.mjs` 로 렌더 · 검사한다 |
| 생성 스크립트 | 저장소 `docs/diagrams/mkdiag.py`(제품 · 방법론 그림 6장) · `mkdiag_kb.py`(지식 저장소 그림 2장). 그림을 고칠 때는 이 스크립트를 고쳐 다시 만든다(볼트 파일을 손으로 고치지 않는다) |
| 요소 | 영역 `region(tab=True)`, 번호 카드 `card`, 아이콘 타일 `icon_node(tile=True)`, ERD `tablebox`, 직각 화살표 `orth`, 번호 `badge`. 단순 박스 나열은 피한다 |
| 글자 | 카드 제목 24px 는 6자 안, 설명 17px 는 15자 안. 아이콘이 있으면 제목을 더 짧게 |
| 렌더 환경 | `~/node_modules/playwright`(1.62)와 짝이 맞는 chromium-headless-shell 이 필요하다. 없으면 `node ~/node_modules/playwright/cli.js install chromium-headless-shell` |
| 확인 | 렌더 PNG 를 눈으로 보고(관통 0 · 겹침 0 · 글자 가로지름 0, 글자가 박스 안) 위키 쪽에 그림 이름 뒤에 .excalidraw 를 붙인 임베드 링크로 넣는다 |

## 지식 저장소에 기록하기

규칙은 [[90_AI/지식저장소/위키/지식저장소-운영\|지식저장소-운영]]. 저장소에는 절차 스킬 넷과 훅 여섯이 있다.

| 것 | 쓰는 법 |
|---|---|
| `/vault-ingest` | 턴에 생긴 결정 · 지시 · 검토 · 조사 · 산출물을 원자료에 넣고 위키 · index · log 를 고친다 |
| `/vault-lint` | 끊긴 링크 · 이름 겹침 · 들어오는 링크 없는 쪽 · sources · 인용 안 된 원자료 · basis · 일지 링크 · 낡은 문장 후보 검사, 교차표 재생성, 회차 · 커밋 · 세션 끝 대조 |
| `/journal` | 오늘 일지를 쓰거나 더한다(커밋한 턴, 세션 끝) |
| `/wrap-up` | 세션 마무리. 상태표 → 자동 대화 기록 읽고 ingest → 일지 → 이어하기 → log → lint → 메모리 → 보고 |
| Stop 훅 | 기록할 사건(설계 문서 · 검토 보고 · 커밋 · Claude 가 고친 볼트)이 있거나 코드 작업이 45분 넘게 기록 없이 이어진 턴을 끝낼 수 없다. 이유에 바뀐 파일과 할 일이 나온다. 조건은 [[90_AI/지식저장소/위키/지식저장소-운영\|지식저장소-운영]] 의 "얼마나 자주" 표. 차단 한도를 넘기면 요구가 `debt.json` 으로 다음 턴에 넘어간다 |
| SessionEnd · PreCompact · SessionStart 훅 | 세션 끝(`/clear` 포함)과 압축 직전에 세션기록을 보충하고 마지막 상태를 `이어하기.md` 에 자동 기록하며, 새 세션 · `/clear` · 압축 뒤에 그 파일과 미처리 원자료 · 밀린 일지를 컨텍스트에 넣는다 |
| PostToolUse 훅 | Claude 가 쓴 파일 경로를 적어, 동기화로 내려온 볼트 변경을 기록 요구에서 뺀다 |
| 상태 확인 | `python3 ~/.claude/hooks/vault_check.py --report`(상태표 · 규칙 상수 · 오늘 집계 · lint) · `--rules` · `--mark-ingest`(ingest 끝났다고 표시) |

볼트 경로가 다르면 환경 변수 `MOMO_VAULT` 로 지정한다. 볼트 위치는 `~/Library/Mobile Documents/iCloud~md~obsidian/Documents/infiray/90_AI/프로젝트/momo-english-academy/`. 볼트는 iCloud 와 LiveSync 로 이중 동기화되므로 많은 파일을 옮기거나 지울 때는 계획을 먼저 보여 준다.
