| 시드 생성 | Claude Code 세션이 만든다. 검증을 통과한 것만 seed/ 에 커밋한다([[90_AI/프로젝트/momo-english-academy/위키/제품/파이프라인/수업-생성\|수업-생성]]) | 개발 때 |
| 시드 적재 | main 작업이 마이그레이션 → 시드 검증 → 적재 → 신고 판단 기록과 다시 계산을 돈다. 끝나야 새 배포가 승격된다 | main 에 커밋이 들어올 때 |
| Cron | 원문 삭제와 DB 크기 검사(db.size_alert_mb 400MB). 1-나부터 돈다(C50) | 매일 한 차례 |

## 접근 제어

| 대상 | 규칙 |
|---|---|
| 기기 | 부모가 가족 접근 코드를 넣으면 장기 httpOnly 쿠키를 준다(access.cookie_days 365일). 접근 코드는 영문 · 숫자 10자 이상이고(2026-10-23 C147 — 처음 12자), 더 짧은 코드는 설정되지 않는다(10절, AC-1a). 코드는 서버 환경 변수에 해시로 둔다. 바꾸면 모든 기기가 무효다 |
| 실패 · 잠금 | parent.pin_max_attempts(5)번 틀리면 parent.lock_minutes(15분) 잠근다. 접근 코드는 요청 IP 마다, PIN 은 집 전체로 센다. 등록된 기기는 잠금과 관계없다 |
| 구현(P3b, C55 · C57) | proxy 는 쿠키 없는 페이지 요청을 /access 로 다시 쓰고 그 페이지가 unauthorized() 로 401 을 낸다. 서버 액션 · Route Handler 는 첫 문장 requireAccess(). 쿠키 momo_access 는 HMAC 토큰이고 열쇠는 ACCESS_CODE_HASH 에서 파생한다(코드를 바꾸면 전부 무효). 제출은 Route Handler /access/submit, 해시는 argon2id. 화면 문구는 4절(C57). 출처 [[90_AI/프로젝트/momo-english-academy/원자료/검토/2026-10-16_검토_P3-하위-plan-계획자-보고\|2026-10-16_검토_P3-하위-plan-계획자-보고]] |
| 요청 | proxy.ts 가 페이지 요청을 먼저 거른다. 서버 액션 · Route Handler 는 첫 줄에서 같은 확인 함수를 다시 부른다 |
| 부모 화면 · Cron | 부모 화면은 PIN 세션(parent.session_minutes 30분)을 더 본다. Cron 경로는 CRON_SECRET 으로 본다 |
| DB | 모든 테이블에 RLS 를 켠다. anon · authenticated 를 거부하고 권한을 회수한다. Data API 는 가능하면 끈다 |
| 비밀값 | 운영 DB 접속 정보는 Vercel Production 환경 변수와 GitHub Actions 운영 환경 비밀값에만 둔다 |

## 오류 처리의 뼈대

AI 를 쓸 수 없는 때는 'AI 쉬는 중' 한 상태로 다룬다(S9). 상태는 ai_status 한 행이다. 호출 하나의 실패와는 나눈다.

| 'AI 쉬는 중' | 규칙 |
|---|---|
| 들어가기 | 넷 가운데 하나다. (1) 하루 안전 상한(ai.safety_daily_calls 1,000회 · ai.safety_daily_cost_usd 15달러). (2) 콘솔 지출 한도 오류(400)나 조직 상한 오류(429, enforced_spend_limit_reached). (3) 연결 · 서버 오류(연결 실패 · 5xx · 529 · 타임아웃)와 콘솔 한도가 아닌 429 가 성공 없이 ai.down_after_failures(3)번 이어짐. 이어진 실패 수는 턴마다 세고, 앱의 1회 다시 부름까지 실패한 한 차례가 하나다(C18). (4) 계정 오류(401 · 402 · 403) 한 번. 까닭은 '계정 확인 필요'다(C1) |
| 동안 | 앱은 확인 호출 밖의 AI 를 부르지 않는다. AI 가 필요한 활동(쓰기 4단계부터, 말하기 3단계부터의 질문 답 · 그림 보고 말하기 · 발표, 회화, 생각 꺼내기, AI 문항이 든 단계 평가 세션)은 시작하지 않는다. 고르면 '토리가 잠깐 쉬어요. 다른 공부를 해 볼까요'와 '홈'을 보인다(C16). 하던 활동 도중에 들어가면 세션을 진행으로 두고 같은 안내를 보인다. 말하기 3~8단계는 예외로, 질문 답을 건너뛰고 세션을 끝까지 한다 |
| 그대로 되는 것 | 읽기, 쓰기 1~3단계, 따라 말하기, 듣기, 복습, 배치 평가, AI 가 필요 없는 수업의 다시 하기, 토리 이야기. 말하기 1~2단계 세션은 질문 답까지 그대로 한다(앱 판정, C38). 말하기 9~12단계 세션은 시작하지 않는다 |
| 풀리기 | 하루 안전 상한은 다음 학습일에만 풀린다. 확인 호출을 보내지 않고, 그 시각이 지난 뒤 ai_status 를 읽는 첫 요청(홈 · 부모 화면 · 카드 누름)이 시각만 보고 푼다(C46). 나머지는 확인 호출이 한 번 성공하면 풀린다. 버튼은 없다(T1) |
| 확인 간격 | 연결 장애는 ai.down_retry_minutes(5 · 15 · 30분) 간격이다. 콘솔 한도 · 계정 확인 필요는 ai.probe_interval_minutes(60분) 간격이다 |

| 상황 | 처리 |
|---|---|
| 호출 하나의 실패 | 대화형은 ai.timeout_seconds.realtime(10초)이다. 첫 바이트 전 연결 오류에만 앱이 1회 다시 부른다 |
| 다시 보내도 같은 오류 | 400(콘솔 한도가 아닌 것) · 404 · 413 · 모델 은퇴는 이어진 실패 수에 넣지 않는다. 같은 호출 목적에서 한 학습일에 ai.down_after_failures 번 나면 부모 알림 '호출 설정 확인 필요'를 만든다(C17) |
| 첨삭 실패 | 다음 앱 진입 때 다시 부른다. ai.feedback_max_attempts(5)번 실패하면 '첨삭 못 함'이다 |
| 회화 턴 실패 | 첫 문장 전 실패는 같은 말로 한 번 다시 부른다. 그래도 실패하면 1~3단계는 카드 대사로 대화를 잇고, 4단계부터는 토리가 쉬겠다고 말한 뒤 수업 목록으로 간다 |
| 시드 빈 칸 · 검증 실패 | CI 가 배포를 막는다. 아이 화면에는 수업 생성 실패가 없다 |
| 비용 알림 기준 | 호출은 그대로 한다. 부모 메뉴 점과 부모 화면 첫 줄로 알린다 |

## 구현 차수

학습 규칙은 모두 첫 운영 배포에 들어간다(S4). 첫 운영 배포까지는 1-가 · 1-나 두 묶음이다(S8).

| 차수 | 내용 | 끝나면 |
|---|---|---|
| 1-가 | iPad Safari 실기 확인이 먼저다. 뼈대 · 접근 제어, 어휘 배정 함수 · 시드 Zod 규격 · 검증기 · 풀이 검사, 로컬 시드 보기 화면, 시드 확정 · 적재 · 완전성 검사, 개발용 DB 적재 작업, 첫 실행 · 배치 평가 · 홈 · 수업 목록, 읽기 · 쓰기 · 말하기 세션과 실시간 호출, ai_calls · 안전 상한 판정 · parent_alerts, 복습 · 단원 통과 · 단계 평가 · 별. 회화 카드를 누르면 '토리가 준비 중이에요. 곧 만나요'와 '홈'만 보이고 세션을 열지 않는다(C50). 안전 상한에 닿으면 그 학습일의 실시간 호출을 막고 'AI 쉬는 중'과 같은 안내('토리가 잠깐 쉬어요. 다른 공부를 해 볼까요'와 '홈')만 보인다(C50) | 요청자가 개발용 DB 의 프리뷰 배포에서 써 본다. 이 끝 사용에는 배치 평가 가 벌 전부, 읽기 · 쓰기 · 말하기 1단계 단원 5개 전부(정규 · 보강 · 변형), 1단계 단계 평가 1벌 이상의 실시드가 있어야 한다(C50). 나머지 1~6단계 본 생성은 1-나와 나란히 간다. 이 기록은 운영 DB 로 옮기지 않는다 |
| 1-나 | 회화 전부, 1차 부모 화면, 'AI 쉬는 중' 상태와 확인 호출, 신고 · 정정 · 다시 계산, 원문 삭제, Cron 과 함께 DB 크기 검사 · 옛 개정 정리 작업(AC-8j, C50), 회화 시드 본 생성 | 1~6단계 시드(seed.complete_through_level 6)가 다 차면 운영 배포를 한 번 한다. 매일 학습과 성공 기준은 그날부터 센다 |
| 2차 | 7~12단계 시드 · 평가(seed.complete_through_level 12), 재배치 평가(둘째 벌 나)와 평가 결과 상세 화면, 단계 올리기 · 내리기 추천, 단원 미리보기, 설정 화면(기본 · 고급), 이번 주 요약, 배지, 부모 화면 나머지, 오늘의 한 문장, 아이의 관심 주제 묶음 바꾸기 | 12단계까지 이어 배운다 |
| 3차 | 프로필 2~3개, 아바타 꾸미기, PWA(Serwist), 연습지 PDF, 타자 게임. 시작 전에 알림 기준 · 안전 상한 · 콘솔 한도를 다시 정한다 | 형제가 같은 기기에서 쓴다 |

## 운영 준비

| 항목 | 규칙 |
|---|---|
| 요금제 | Supabase Free 와 Vercel Hobby 를 쓴다(2026-10-15 잠정). 앱 안에는 월 상한이 없다(R4) |
| Anthropic 콘솔 | 운영 전용 워크스페이스와 키를 둔다. 키 만료는 '없음'이다. 월 지출 한도는 ai.console_limit_usd(70달러)와 같게 둔다. 키를 바꿀 때는 새 키로 다시 배포한 뒤 옛 키를 지운다(C1). 모델 은퇴 알림을 받으면 ai.model.* 과 model_prices 를 바꾸고 AI 계약(수동) 시험을 돌린다(C17) |
| 개발용 | 풀이 검사 같은 개발용 호출과 프리뷰는 다른 워크스페이스 키를 쓴다. 거기에도 월 지출 한도를 건다. 프리뷰 배포는 개발용 Supabase 에 붙는다. 콘솔 한도 오류 표본도 여기서 받는다. 아주 낮은 월 지출 한도를 걸어 실제 한도 오류 응답(상태 코드 · 오류 코드 · 문구 · 풀리는 시각 꼴)과 그 호출이 콘솔 사용량에 과금되는지를 받아 고정 표본으로 두고, 8절 분류 규칙을 그 표본으로 검증한다. 1-나 확인 호출 구현 전 한 번, 모델 · SDK 판을 올릴 때 다시 한다(9절 AI 계약(수동), C46) |
| DB 크기 | db.size_alert_mb 를 넘은 날 부모 알림이 난다. 어떤 기록도 가리키지 않는 낮은 개정의 시드 행을 지우는 정리 작업(수동)을 돌린다. 그래도 넘으면 유료 전환을 요청자가 정한다 |
| 백업 · 배포 | 암호화 키는 GitHub 운영 환경 비밀값과 요청자의 비밀번호 관리자 두 곳에 둔다. 석 달마다 복원을 점검한다(C26). 운영 주소는 사용자 지정 도메인이다 |
