# AI 호출

정본은 `specs/05-AI-호출.md` 6.1 · 6.2 · 6.5 · 6.6절이고 이 쪽은 정본 열세 장(커밋 e4ee079, 13절 C50 까지) 기준이다. 잠정 값은 [[90_AI/프로젝트/momo-english-academy/위키/결정/결정-목록\|결정-목록]]에 있다. 시드 생성과 검증(6.3 · 6.4)은 [[90_AI/프로젝트/momo-english-academy/위키/제품/파이프라인/수업-생성\|수업-생성]]에 있다. AI 호출은 서버 코드(서버 액션 · Route Handler)에서만 한다. 키는 서버 환경 변수에만 둔다. 운영 중 호출은 아이 답에 반응하는 실시간 호출과 확인 호출뿐이다(요청자 결정 2026-10-15 10:15, T1). 응답은 Zod 스키마의 structured outputs(`output_config.format`)로 받는다. 6.5 배치 흐름은 지웠다.

## 호출별 구성

| 호출 | 모델 | effort · 생각 단계 | 방식 | 타임아웃 · 최대 출력 |
|---|---|---|---|---|
| 쓰기 첨삭(6단계부터) | claude-opus-5-5 | medium · adaptive(끌 수 없음) | 초고 제출 서버 액션의 응답 뒤(after()). 스트리밍하지 않는다 | ai.timeout_seconds.feedback(60초) · ai.max_tokens.writing_feedback(8000) |
| 쓰기 확인(4~5단계) · 말하기 평가(3단계부터) · 생각 꺼내기 | claude-sonnet-5-5 | low · adaptive. 표본 평가 뒤 정한다 | 아이가 기다린다 | ai.timeout_seconds.realtime(10초) · `ai.max_tokens.<호출>`(4000) |
| 회화 턴 1~3단계 | claude-sonnet-5-5(C112, 요청자 2026-10-23 — 전에는 Haiku) | low · between_tools | 스트리밍. 토리 말을 문장마다 검사하며 흘려 보인다 | ai.timeout_seconds.realtime(10초) · ai.max_tokens.talk_turn(1000). 끝맺음 턴은 ai.timeout_seconds.feedback(60초) · ai.max_tokens.talk_closing(2000) |
| 회화 턴 4~12단계 | claude-sonnet-5-5 | low · between_tools | 위와 같다 | 위와 같다 |
| 확인 호출 | 쉬는 상태에 들게 한 마지막 실패 호출의 모델. 콘솔 한도 · 계정 오류면 Haiku 5.5 | 그 모델이 받는 가장 가벼운 조합 | 'AI 쉬는 중'에서 응답 뒤에 보낸다 | ai.timeout_seconds.realtime(10초) · ai.max_tokens.probe(1) |

모델 · effort · 생각 단계는 `ai.model.<호출>` · `ai.effort.<호출>` · `ai.thinking.<호출>` 에서 읽는다. 회화 턴은 `talk_turn.<구간>` 키로 구간마다 바꾼다(R3). 확인 호출은 이 키를 쓰지 않는다. 생각 단계를 끄는 값은 Sonnet 5.5 between_tools, Haiku 5.5 disabled 다. Opus 5.5 는 끌 수 없다. xhigh · max 와 생각 끄기를 함께 보내면 400 이다. temperature · top_p · top_k 는 보내지 않는다. 생각 토큰은 출력으로 과금되고 최대 출력에 함께 센다. 조합 표는 model_prices 와 같은 시드이고, 받지 않는 조합은 설정에 저장하지 않는다.

## 입력과 출력

| 호출 | 입력 | 출력 |
|---|---|---|
| 확인 호출 | 고정 한 단어 'ok'. 아이 정보가 없다(C46, NFR-4) | 규격 없음. HTTP 200 이면 성공이고 본문은 쓰지 않는다 |
| 쓰기 확인 | 과제, 아이의 문장들, 단계, 이번 · 이전 단원 학습 요소 | 칭찬 한 줄, 문장마다 맞음 여부(성적용), 고칠 곳 최대 1개(원문 · 바른 표현 · 헷갈리는 보기 · 이유) |
| 쓰기 첨삭 | 과제, 초고, 단계, 생각 꺼내기 요약 | 칭찬 1, 교정 최대 writing.max_corrections 개, 모범 답안, 채점표 점수 3개(1~4). 단계 평가 쓰기 과제도 이 호출로 채점한다 |
| 말하기 평가 | 질문 · 그림 과제의 장면 설명 또는 발표 주제(확인 질문 답이면 발표 인식 글과 그 질문), 인식 글, 단계 | 3단계는 판정 · 한 문장 · 바른 답 문장. 4~8단계는 문법 지적 최대 1개를 더한다. 9~12단계 발표는 내용 · 문법 점수(각 1~4), 피드백 한 문장, 확인 질문 3개다. 확인 질문 답은 같은 호출로 하나씩 내용 · 문법 점수와 피드백 한 문장을 낸다. 확인 질문이 비거나 검사에 걸리면 시드의 예비 확인 질문을 쓴다. 단계 평가의 발표 문항에는 확인 질문을 내지 않는다 |
| 생각 꺼내기 | 과제, 대화 기록, 단계, 이번 수업 배정 새 단어 | 한국어 질문과 보기 3개, 생각 요약, 영어 단어 4~6개, 문장 시작 틀 2개, 종료 여부. 턴 상한은 writing.thinkout_max_turns(3) |
| 회화 턴 | 단계 규격, 시나리오 카드, 새 단어, 아직 '안다'가 아닌 단원 단어와 그 가운데 이미 만난 단어, 지난 대화 요약(talk.memory_summaries 3개), 친한 정도, 대화 기록, 아이 말과 입력 방식(말 · 모름), 토막(인사 · 인사 끝 · 대화 · 더 이야기하기), 힌트 종류와 쓴 힌트 단, 들은 도움(1단계 답 두 개 · 답 예시), 같은 질문에서 '모름'이 몇 번째인지, 목표 턴 도달 · 끝맺음 여부, 평가 대화 여부, 1~3단계는 '더 이야기할 거리'를 다 썼는지 | tori_en, tori_ko(1~4단계), 되풀이한 바른 문장, 설명, 이번 턴에 나온 새 단어, 스스로 쓴 단원 단어(기록용), 미션 체크(5~7단계), 막힘으로 볼 말(C36). 4단계부터는 카드 질문 번호(이어 묻는 질문이면 0, C19) · 다음 턴 힌트 · 다음 턴이 노리는 단원 단어 · 답 예시. 4~9단계는 다음 턴의 한국어 뜻 힌트를 따로 한 필드로 내고, 힌트 필드에는 영어 단만 둔다(C20). 1~3단계는 '더 이야기할 거리'를 다 쓴 '더 이야기하기' 턴에서만 다음 질문(영어 · 한국어 뜻) · 다음 턴 힌트 · 노리는 단원 단어 · 답 예시를 내고, 그 밖의 턴과 평가 대화에서는 빈 값이다. 끝맺음 턴은 끝인사 · 잘한 말 · 다음엔 이렇게 · 요약 |

회화 턴 고정부 첫머리에 아이가 고른 회화 선생님 블록이 들어가고(C130 — [[90_AI/프로젝트/momo-english-academy/원자료/산출물/2026-10-23_산출물_spec-v9-회화-선생님-C130\|2026-10-23_산출물_spec-v9-회화-선생님-C130]]), 회화 턴 출력은 막힘으로 볼 말(stuck)을 tori_en 보다 먼저 낸다 — 서버가 흘려 받는 처음에 막힘을 알아, 앱이 붙일 답 두 개와 겹치는 토리 문장만 잡아 두고 바른 말 되풀이 같은 첫 말은 곧바로 흘린다(C127, 코드 검토 [[90_AI/프로젝트/momo-english-academy/원자료/검토/2026-10-23_검토_P13-회화-느낌-고침-코드\|2026-10-23_검토_P13-회화-느낌-고침-코드]] I-3). 회화 턴에는 판정 필드가 없다(R2). 1~3단계와 평가 대화의 tori_en 은 반응만 쓰고, 질문은 앱이 카드에서 붙인다(S5). 스키마의 모든 필드는 required 이고 null 을 쓰지 않는다. 회화 턴과 끝맺음 턴은 같은 스키마다. 말하기 1~2단계 질문 답은 이 호출을 부르지 않는다(C38).

## 앱이 AI 없이 하는 것

쓰기 1~3단계, 읽기 문제, 듣기 이해, 복습, 배치 평가, 토리 이야기 질문은 앱이 정답과 비교한다. 따라 말하기와 회화 말해 보기는 앱이 일치율을 센다. 말하기 1~2단계 질문 답은 허용 답과의 일치율이 speaking.answer_match_pass(0.8) 이상이면 맞음이다(C38). 회화 단계 평가는 talk.test_match_pass(0.8)와 힌트 단 점수 talk.test_hint_scores(1 · 0.5 · 0)로 앱이 센다. 회화 정리 토막의 되짚을 말도 앱이 만든다(C33). '말했다'는 AI 가 돌려준 단어를 앱이 힌트 종류와 인식 글로 다시 걸러 센다. 일치율은 목표 단어 가운데 순서를 지켜 맞은 비율이다. 소문자 · 문장 부호 제거 · 숫자 영어화 · 축약형 펼치기 · 동음이의어 시드를 거친다. 덧붙인 말은 감점하지 않는다.

## 프롬프트와 캐시

| 부분 | 내용 |
|---|---|
| 고정부 공통 | 영역 규칙, 아동용 내용 기준, 설명은 한국어로. 개인 식별 정보를 묻지 않고, 아이가 쓰면 되묻지 않는다 |
| 고정부 호출별 | 생각 꺼내기는 학습 요소 범위로 좁히는 질문을 한다. 확인 · 첨삭은 이번 · 이전 단원 요소에서 먼저 고른다. 말하기 평가 · 회화 턴은 인식 오류로 보이는 것을 지적하지 않는다 |
| 회화 턴 고정부 | 공통 규칙은 한마디 반응 · 바른 말 되풀이 · 짚어 하는 칭찬 · 재촉하지 않기다. 인사 끝 턴의 응답은 반응과 다음 토막으로 넘어가는 짧은 말만 쓰고 질문을 쓰지 않는다(C19). 질문에는 그 턴이 노리는 단원 단어를 넣지 않는다. 아이가 토리의 바로 앞 말에 나온 단어를 그대로 받아 말한 것은 스스로 쓴 단원 단어로 돌려주지 않는다(A4-03). 끝인사는 '내일' · '다음에 만나'처럼 오늘 대화가 끝났다는 말을 하지 않는다. 4단계부터는 선생님처럼 이끈다. 문장으로 다시 묻기는 talk.reask_sentence_every_turns(3)턴에 한 번까지다. 이어 묻는 질문은 talk.follow_up_min_every_turns(3)턴에 하나 이상이다(C44). 1~3단계는 반응과 연결 말만 쓴다 |
| 가변부 | 단계 can-do, 단원 어휘와 학습 요소, 이번 시드 수업(회화는 카드) |
| 보내지 않는 것 | 아이 이름(한글 · 영어 이름과 그 변형은 {NAME} 으로), 관심 주제. 전화번호 · 주소 형태는 가린다 |
| 캐시 | 회화 턴 · 생각 꺼내기는 대화 끝까지 자동 캐시를 건다. 턴마다 바뀌는 값은 마지막 사용자 메시지에 넣는다. 보낸 메시지 전문과 다시 쓸 토리 차례를 저장해 글자 그대로 다시 쓴다. 단발 호출에는 걸지 않는다(캐시 수명 5분) |

대화 도중 모델 · effort · 생각 단계를 바꾸지 않는다. 바꾸면 캐시가 새로 시작된다. Haiku 거절 뒤 그 턴만 Sonnet 으로 부르는 것이 예외다.

## 실패 · 재시도 · 검증

| 경우 | 처리 |
|---|---|
| 첫 바이트 전 연결 오류 | 앱이 대화형 호출만 1회 다시 부른다. SDK 기본 재시도는 끈다(max_retries 0, C1) |
| 콘솔 지출 한도(400, 'You have reached your specified … API usage limits') · 조직 상한(429, enforced_spend_limit_reached) | 다시 부르지 않고 바로 'AI 쉬는 중'으로 간다. 이 분류는 개발용 워크스페이스에 아주 낮은 월 지출 한도를 걸어 받은 실제 한도 오류 표본(상태 코드 · 오류 코드 · 문구 · 풀리는 시각 꼴)으로 검증한다. 1-나 확인 호출 구현 전 한 번, 모델 · SDK 판을 올릴 때 다시 받는다(9절 AI 계약(수동), C46) |
| 그 밖의 429 · 연결 · 서버 오류 | 호출 하나의 실패다. 이어진 실패 수에 턴마다 하나를 더한다(C18) |
| 다시 보내도 같은 오류 | 콘솔 한도가 아닌 400 · 404 · 413 · 모델 은퇴다. 다시 부르지 않는 호출 하나의 실패이고 이어진 실패 수에 넣지 않는다. 같은 호출 목적에서 한 학습일에 ai.down_after_failures 번 나면 부모 알림 '호출 설정 확인 필요'(호출 목적 · 모델 · 오류 코드)를 그날 한 번 만든다(C17) |
| 거절(refusal) | 같은 모델로 다시 부르지 않는다. 설정으로 Haiku 를 고른 회화 턴은 첫 문장 전이면 Sonnet(low · between_tools)으로 한 번 부른다. 같은 입력이 두 번 거절되면 더 부르지 않는다 |
| 서버 측 대체 모델 재시도 | Sonnet · Opus 실시간 호출에 `fallbacks: "default"` 를 켠다. Haiku 에는 보내지 않는다. 답한 모델과 그 단가를 ai_calls 에 적는다 |
| end_turn 아님 · Zod 실패 | 1회 다시 요청한다(회화 턴 제외). 다시 실패하면 개수 초과는 앞에서부터 자르고 점수는 범위 안으로 자른다. 필수 필드가 없으면 호출 하나의 실패다 |
| 출력 검사 | 길이 · 금지어 · 개인 정보 질문 · 메타 문장을 본다. 걸리면 안전한 대사로 바꾼다(6.4) |

structured outputs 는 개수 · 길이 · 최솟값 · 최댓값을 강제하지 않는다. 그 제약은 정규화 함수가 맡는다. 기다림은 타임아웃의 두 배를 넘지 않는다. 확인 호출에는 정규화를 쓰지 않는다.

## 확인 호출과 기록

| 항목 | 규칙 |
|---|---|
| 확인 호출 | 'AI 쉬는 중'에서 홈 · 부모 화면 요청 때 다음 확인 시각이 지났으면 응답 뒤 하나 보낸다(C1 · C29). 다음 확인 시각을 먼저 미룬 요청 하나만 보낸다. HTTP 200 이면 성공이다 |
| 간격 | 연결 장애는 ai.down_retry_minutes(5 · 15 · 30분) 간격이다. 콘솔 한도 · 계정 확인 필요는 ai.probe_interval_minutes(60분) 간격이다. 하루 안전 상한은 확인 호출을 보내지 않고 다음 학습일에만 풀린다. 그 시각이 지난 뒤 ai_status 를 읽는 첫 요청(홈 · 부모 화면 · 카드 누름)이 시각만 보고 푼다(C46) |
| 부모 화면 칸 · 문구 | 하루 안전 상한은 풀리는 시각과 다음 확인 시각이 둘 다 다음 학습일 시작이다. 연결 장애 · 계정 확인 필요는 풀리는 시각 칸이 비어 있다. 콘솔 한도의 풀리는 시각은 오류 메시지의 시각이고, 없으면 다음 달 1일 09시(한국 시간)다. 이 기본값은 콘솔의 달 경계라 설정 키를 두지 않는다. 콘솔 한도 문구의 '한 시간 안에'는 ai.probe_interval_minutes 값으로 채운다(C46). AC-8p 가 이 칸 값과 문구를 본다 |
| 풀린 뒤 | 그때 만든 'AI 쉬는 중' 알림에 풀린 시각을 덧붙이고 확인 필요 표시를 내린다. 알림은 목록에 남는다(C46). 이어진 실패 수와 확인 차례는 0 으로 되돌린다(C17) |
| ai_calls | 목적, 요청 · 답한 모델, 입력 · 출력 · 캐시 쓰기 · 캐시 읽기 토큰, 비용, 지연, 결과 상태, 세션 id. 회화 턴은 첫 문장 시간도 남긴다. 본문은 저장하지 않는다 |
| 알림 | 하루 기준은 ai.daily_call_alert(150회) · ai.daily_cost_alert_usd(1달러)다. 월 알림은 ai.monthly_cost_alert_usd(12달러)의 ai.monthly_alert_multiples(1 · 2 · 4)배에서 난다. 그달 비용이 ai.console_limit_usd(70달러)의 ai.console_alert_ratio(0.8)에 닿으면 '콘솔 한도 근접' 알림이다 |
| 안전 상한 | ai.safety_daily_calls(1,000회) · ai.safety_daily_cost_usd(15달러)에 닿으면 'AI 쉬는 중'이다. 대화 하나가 talk.safety_max_turns(80턴)에 닿으면 그 대화만 닫는다. 사용 시험 4주의 ai_calls 로 프로필 하루 최대 호출 수와 가정 하루 최대 비용을 두 상한과 견주어 기록하고, 상한에 든 날이 0 인지 본다(AC-8o, C48) |

비용 · 횟수로 아이의 진행을 끊지 않는다(요청자 결정 2026-10-15 10:17). 앱 안에는 월 상한이 없다. 달 단위 마지막 방어선은 Anthropic 콘솔 월 지출 한도다(R4). 확인 호출은 profile_id 를 비워 남기고 호출 수 · 비용 합계와 안전 상한에 넣지 않는다.

## 비용 모델

사용량 가정과 비용 추정은 설정값이 아닌 가정값(12절 끝 문단)이다. 사용 시험의 ai_calls 로 확인한다. 단가는 100만 토큰당 Opus 5.5 4 · 20, Sonnet 5.5 2 · 10, Haiku 5.5 0.10 · 0.50달러다. 1회 비용은 첨삭 약 0.05, 짧은 실시간 약 0.011, 회화 턴 1~3단계 약 0.013(C112 — Haiku 였을 때 0.0006), 4단계부터 약 0.014~0.015달러다. 1~3단계 회화 한 대화는 약 0.21달러(캐시가 맞으면 0.08), 낮은 단계 월 비용은 '적게' 약 4.7~5.7 · '많이' 약 45~49달러다([[90_AI/프로젝트/momo-english-academy/원자료/대화/2026-10-23_대화_세션기록\|2026-10-23_대화_세션기록]]).

| 월 비용(프로필 1개) | 적게 | 많이 |
|---|---|---|
| 가정 | 월 22일, 영역마다 하루 1수업, 회화 하루 1대화 · 목표 턴만 | 월 30일, 하루 3수업, 회화 하루 3대화 · 목표 턴의 두 배 |
| 낮은 단계 | 약 0.2~1.2달러 | 약 2.2~6.2달러 |
| 중간 단계 | 약 8~10달러 | 약 73~98달러 |
| 높은 단계 | 약 11.5달러 | 약 104달러 |
| 캐시가 맞을 때 | 높은 단계 약 5.5달러 | 중간 약 23~27달러, 높은 약 33달러 |

월 알림 12달러는 높은 단계 '적게'를 올림한 값이고 성공 기준 S-5 의 값이다(C6). 4단계부터는 회화가 운영 비용의 4분의 3 이상이다. 캐시가 맞지 않으면 '많이'의 중간 · 높은 단계는 콘솔 한도도 넘는다. 그런 달은 한도에 닿은 날부터 'AI 쉬는 중'이 된다. 한도 앞 알림은 월 4배(48달러)와 콘솔 80%(56달러)다(C42). 캐시 읽기는 100만 토큰당 Sonnet 5.5 0.10 · Haiku 5.5 0.01달러다. 시드 본 생성은 구독 사용량이라 API 비용이 없다. 개발 때 API 비용은 풀이 검사뿐이다(약 50달러 이하, 잠정). 프로필이 셋이 되는 3차 전에 기준을 다시 정한다.
