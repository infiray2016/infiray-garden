묶음마다 검증 · 풀이 검사 · 사람 표본 검토를 마친 뒤 다음 묶음으로 간다. 부모(요청자)는 영역 · 단계마다 수업 2개를 아이 화면 그대로 읽는다. 결과는 '알맞음 · 쉬움 · 어려움 · 오류'로 `seed/reviews/<영역>-<단계>.json` 에 남는다. '오류'가 하나면 표본을 5개로 늘린다. 같은 종류 오류가 둘 이상이면 프롬프트를 고쳐 다시 만든다.

## 검증기

같은 검증 함수를 시드 검증 스크립트 · 단위 테스트 · CI 완전성 검사가 쓴다(6.4).

| 검사 | 기준 |
|---|---|
| 칸 검사 | 분량이 단계 규격 안이다. 배정표대로 새 단어가 들어갔다. 정답 번호가 보기 안이고, 쓰기 1~3단계 문항에 허용 정답이 있다. 그림 키가 그림 카탈로그(images)에 있다. 말하기 그림 보고 말하기와 1~3단계 회화 카드의 그림 키도 보고, 그림 보고 말하기 과제에는 장면 설명이 있다(C27 · C32). 지문의 기능어 밖 단어가 글로서리에 모두 있다 |
| 말하기 수업 | 따라 말하기 단어 · 문장 수, 듣기 이해 문항 수, 질문 답 수가 3.3 말하기 단계표와 같다. 1~2단계 질문의 허용 답은 셋 이상이고, 1~4단계 질문에 한국어 뜻이 있다. 9~12단계 수업에 발표 주제 · 쓸 말 세 개 · 예비 확인 질문 3개가 있다(C47, AC-5h) |
| 범위 | 어휘 범위 밖 단어가 seed.max_offband_ratio(5%) 이하다. 문장 길이 상한과 형태 표(3.6)를 지킨다. 보강 수업이 단원 단어를 `seed.remedial_coverage.<구간>` 번 이상 덮는다 |
| 금지 내용 | 금지어 목록과 정규식(폭력 · 개인 정보 요구 · 연락처 형태). 개인 정보 질문 패턴은 영어 · 한국어 두 벌이다 |
| 회화 카드 | 필수 칸이 다 있다. 1~3단계는 질문 수 합이 목표 턴과 같고, 처음 묻는 턴이 대화 앞쪽 절반에 있다. 배정 수업 카드는 새 단어를 모두 처음 묻는 턴에서 묻고, 그 턴의 영어 문장 힌트가 새 단어를 담는다. 1단계는 턴마다와 인사 질문에 답 두 개가 있고, 두 답은 같은 꼴 문장에서 낱말 하나만 다르며 적어도 하나가 그 턴의 새 단어를 담는다. 3단계는 턴마다 영어 틀이 있다(C31). 4단계부터 카드 질문 목록이 목표 턴 − 인사 턴 수 이상이다. 질문에 노리는 단원 단어가 없다. 같은 질문은 두 번까지다. 다시 묻는 턴은 단어마다 talk.known_days 번 이상, 서로 다른 수업에 있다. 주제 변형마다 정규 카드의 다시 묻는 턴 자리 수가 단원 단어 수 × talk.said_ratio × talk.known_days 이상이다(3.2 관계 표, B5-M-03) |
| 변형 · 평가 | 변형끼리 새 단어 · 학습 요소 · 분량이 같다. 평가 문항은 벌끼리 겹치지 않고 수업 지문 · 문항과 같지 않다. 회화 평가 카드는 수업 카드와 같은 질문이 장마다 3개 이하다. 단원마다 4문항이고 회화 카드는 장마다 단원별 2턴이다. 회화 평가 허용 답은 셋 이상이고 틀 자리 품사를 적는다 |
| 단계 분포 | 단원 평균 차이가 규격 폭의 절반을 넘으면 경고한다. CI 는 막지 않고, 요청자가 묶음 검토 때 '그대로 · 다시 만들기'를 남긴다 |
| 풀이 검사 | 정답이 있는 문항을 claude-sonnet-5-5(low · between_tools)가 정답 없이 푼다. 다르거나 '둘 이상 맞음' · '답 없음'이면 사람 확인에 넣는다. 결과는 seed/checks/ 에 두고 내용 해시가 바뀔 때만 다시 푼다 |

실패한 칸은 seed.max_retries(2)번까지 다시 만들고, 그래도 안 되면 사람이 고친다. 완전성 검사는 seed.complete_through_level(6)까지 모든 칸이 차고 사람 확인 목록이 비었는지 본다. 어긋나면 main 작업이 실패해 배포하지 않는다(S-4). 빈 칸으로 막는 완전성 검사는 main 작업(운영 적재)과 개발용 적재 작업에서만 한다. 그 밖의 CI 는 있는 칸의 검증만 막고 빈 칸 수는 보고만 한다(9절, B5-20). CI 는 저장된 풀이 결과만 읽고 API 를 부르지 않는다. 사람 확인은 1-가의 시드 보기 화면(로컬 전용)에서 '정답 맞음 · 고침'으로 적는다.

## 적재

main 작업은 마이그레이션 → 시드 검증 → 적재 → 신고 판단 기록과 다시 계산을 돈다. Vercel Deployment Checks 의 필수 검사라서 적재가 끝나야 새 배포가 승격된다. 개발용 DB 는 수동 작업으로 적재하고, seed.complete_through_level 을 작업 입력 값으로 받는다. 판 규칙은 [[90_AI/프로젝트/momo-english-academy/위키/제품/데이터/데이터-모델\|데이터-모델]]에 있다.

## 신고 · 정정 · 개정

| 단계 | 규칙 |
|---|---|
| 신고 | 아이의 '이 문제 이상해요'(1차), 부모의 '문제 있음'(2차), 개발자의 표본 검토 · 풀이 검사. 모두 seed_reports 에 모인다 |
| 받기 · 판단 | `pnpm seed:reports` 가 GitHub Actions 수동 작업으로 접수 신고를 seed/reports/inbox.json 에 받는다. 이 파일은 커밋하지 않는다. 판단은 seed/reports/decisions.json 에 적어 커밋한다 |
| 다시 계산 | 사유 '정답 틀림' · '보기 둘 다 맞음'만 대상이다. 판정은 한쪽으로만 바꾼다. 이미 넘은 단원 · 단계는 그대로 둔다 |
| 정정 판 | 문제와 정답 표시만 고친다. 진행 중 단원에 바로 쓴다(R5). 커밋하기에 앞서 풀이 검사를 다시 돌린다. 신고한 아이 홈에 '알려 준 문제를 고쳤어요. 고마워요'를 한 번 보인다 |
| 개정 판 | 규격 · 프롬프트 · 어휘가 바뀐다. 다음 단원부터 쓴다. 다시 만든 칸은 처음과 같은 검증을 거친다 |

시드를 다시 만들어야 하는 키가 있다(12절). unit.regular_lessons · unit.new_words_per_lesson 같은 키다. 이 키를 바꾸면 그 구간 시드 전체가 새 개정이 된다.
