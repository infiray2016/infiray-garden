# 그래프 엔지니어링 (AI 코딩의 흐름 설계)

요청자가 쓴 말은 AI 코딩 현장의 그래프 엔지니어링이다(2026-10-16 05:0x). 조사 원문은 [[90_AI/프로젝트/momo-english-academy/원자료/조사/2026-10-16_조사_그래프-엔지니어링-AI-코딩\|2026-10-16_조사_그래프-엔지니어링-AI-코딩]](318줄, 출처 59건 · 원문 읽음 52 · 검색 요약만 5 · 접근 실패 2. 출처 번호 [n] 은 그 사본의 출처 표). 첫 조사 [[90_AI/프로젝트/momo-english-academy/원자료/조사/2026-10-16_조사_그래프-엔지니어링\|2026-10-16_조사_그래프-엔지니어링]]은 이 뜻을 네 갈래 가운데 하나로 두고 "개발 과정은 이미 그 모양"이라 밀어 뒀는데 그 판단이 틀렸다. 자료 그래프 제안 P1~P10 만 그대로 쓴다. 저장소 스킬은 `.claude/skills/graph-engineering/SKILL.md`. 세 방법론의 자리는 [[90_AI/프로젝트/momo-english-academy/위키/방법론/AI-SDLC\|AI-SDLC]].

## 한 줄 요지

코딩 일을 점(node)으로 나누고, 점 사이의 길(선, edge)과 넘길 공유 상태를 미리 그려, **길은 에이전트가 아니라 설계자가 정한다.** 에이전트의 자유는 점 안에 둔다. 켜는 때는 에이전트 여럿이 차례 · 조건으로 이어지는 일(검토 루프 · 반영 편집 · 시드 생성 · 구현과 검토 · 워크플로)을 짤 때다. 2026-07-18 피터 스타인버거의 X 글 한 줄이 불씨이고, 새 기술이 아니라 이름이 붙은 사건이라는 비판이 맞다. 프롬프트 → 컨텍스트 → 하네스 → 루프 → 그래프로 쌓이는 층이고 아래 층을 없애지 않는다. Claude Code 에서 점은 서브에이전트, 반드시 가는 선은 훅, 절차는 스킬, 길을 코드로 쥐는 쪽은 동적 워크플로다. 좋은 그래프는 루프로 시작해 신호가 있을 때만 점을 더하고, 검증을 선 위에 코드로 두며, 쓰기는 한 줄기로 한다. 코드베이스 지식 그래프(Graphify 류)는 묻는 것이 다른 별개의 그래프다.

## 요소

| 요소 | 뜻 | 출처 |
|---|---|---|
| 점(node) | 한 가지 일을 하는 단위. 전문 에이전트, 결정 코드, 도구 호출, 라우터, 사람 승인. 모델이 필요 없으면 코드로 둔다 | [4][8][17] |
| 선(edge) | 다음에 어디로 갈지. 직선 · 조건 · 되돌림 | [4][17] |
| 갈라 보내기 · 모아 받기 | 한 점이 여러 점을 동시에 시작하고(fan-out) 결과를 하나로 합친다(fan-in). 합치는 자리는 모두 끝나길 기다리는 장벽 | [4][28] |
| 공유 상태 | 선을 따라 흐르며 모든 점이 읽고 쓰는 기록. 값의 종류와 병합 규칙을 먼저 정한다 | [4][8] |
| 점검 지점 | 상태를 저장해 둔 자리. 멈췄다 이어 가고 실패한 점만 다시 한다 | [8][24] |
| 게이트 | 선 위에서 결과를 검사해 통과 · 되돌림을 정하는 자리. 코드 · 모델 · 사람 | [3][17][18] |
| 사람 게이트 | 되돌리기 어려운 행동 앞에서 사람이 승인. 흐름을 멈추고 상태를 저장한 뒤 재개 | [8][18] |
| 노드 안의 루프 | 점 하나가 스스로 돌며 일한다. "a loop is just a single-node graph with an edge back to itself" | [4][10] |

## Claude Code 에서의 수단

| 수단 | 길을 정하는 쪽 | 중간 결과가 사는 곳 | 규모 | 한계 |
|---|---|---|---|---|
| 서브에이전트(`.claude/agents`) | Claude, 턴마다 | Claude 의 컨텍스트 | 턴마다 몇 개 | 중첩 기본 3층, 동시 20 |
| 스킬(SOP) | Claude, 지침을 따라 | Claude 의 컨텍스트 | 같음 | 지침이라 강제가 아니다 |
| 훅 | 코드, 사건마다 | 종료 코드와 피드백 | 이벤트 33종 | 판단은 못 한다 |
| 에이전트 팀 | 리드 에이전트 | 공유 작업 목록 | 팀원 서너 명 | 실험 기능. 같은 파일을 쓰면 덮어쓴다 |
| 동적 워크플로(`Workflow`) | 스크립트 | 스크립트 변수 | 수십~수백 | 실행 중 사용자 입력 없음. 동시 16, 한 번에 총 1,000 |

| 그래프 요소 | Claude Code 의 수단 |
|---|---|
| 점 | `.claude/agents/*.md`(name · description · tools · model · effort · hooks · maxTurns), 스킬의 context: fork, 워크플로의 `agent()`(agentType · schema · model · effort · isolation). 노드 안의 루프는 에이전트의 작업 루프 · 스크립트의 while · maxTurns |
| 선 | 모델이 정하는 선은 메인 세션의 위임과 스킬 지침. 코드가 정하는 선은 워크플로의 `pipeline` · `parallel` · 조건문 |
| 반드시 가는 전이 | 훅. "make it a hook, not a polite instruction" [5] |
| 공유 상태 | 산출물 파일(JSON · MD), 스크립트 변수, 공유 작업 목록. 파일은 쓰는 점을 하나로 |
| 코드 게이트 | 훅 종료 코드 2, `schema` 검증(다섯 번 재시도), 테스트 · 린트 |
| 모델 게이트 | 새 컨텍스트의 읽기 전용 검토 에이전트 |
| 사람 게이트 | 워크플로는 실행 중 입력을 못 받는다. "For sign-off between stages, run each stage as its own workflow" [24]. 다른 에이전트가 전한 승인은 승인이 아니다 |
| 점검 지점 · 갈라 보내기 · 모아 받기 | 같은 세션 재개(끝난 에이전트는 저장 결과). `parallel` 은 장벽, `pipeline` 은 장벽 없음이 기본 [28] |

고르는 기준: 사람 승인이 단계마다 있으면 스킬 + 훅, 같은 단계를 여러 건에 되풀이하면 워크플로, 곁일 격리면 서브에이전트, 반드시 지킬 전이는 훅. 실무 글의 구현은 단출하다. Masterclass 는 에이전트 셋이 JSON 파일을 이어받고 사람이 끝났다는 문구를 본 뒤 다음 세션을 연다 [10]. ContractGraph 는 점마다 믿을 것(컨텍스트)과 내놓을 것(계약)을 정하고 실패한 점만 고친다 [6].

|---|---|---|---|---|
| LangGraph | StateGraph 의 노드 | 정적 · 조건 엣지, Send(동적 갈라 보내기) | 타입 있는 상태와 병합 규칙(reducer) | checkpointer · thread_id, interrupt() · Command(resume=) |

## 좋은 그래프의 규칙과 흔한 실패

| 규칙 | 근거 | 출처 |
|---|---|---|
| 루프로 시작하고 신호가 있을 때만 점을 더한다 | 신호 다섯: 전문성 다름, 갈라 보낸 뒤 합침, 단계마다 다른 모델 · 도구, 감사할 제어 흐름, 검증자 하나의 과부하. "One node per signal you actually have." | [5] |
| 점 하나에 일 하나 | 이름 두세 단어, 수행 서너 문장, 입력 · 출력 · 다음 · 실패 정의. 단계마다 정해진 입력 · 산출물 · 다음 단계가 "explicit ownership" | [20][11] |
| 모델이 필요 없는 점은 코드로 | "if a node does not need a model, do not use one." | [8][18] |
| 검증은 선 위에 코드로 | "A model can argue that its work is complete. A deterministic validator can prove that a required field is missing." | [6] |
| 쓰기는 한 줄기, 읽기 · 검토는 여럿 | 검토는 새 컨텍스트에서 읽기 전용. "clean context leads to a notable improvement" | [23][5] |
| 공유 상태를 먼저 설계 | "State is the contract between every node." "State drift is the #1 way graphs rot." | [8][4] |
| 상한은 코드에 | "cap in code, never in a prompt". 사람 게이트는 되돌리기 어려운 행동 앞에 하나 | [8] |

| 흔한 실패 | 모습 |
|---|---|
| 루프 모양 문제에 그래프 | "most people reaching for a graph have a loop-shaped problem and a verifier they never bothered to strengthen" [5] |
| 약한 점을 이어 붙임 | "A graph of weak nodes is just slop produced in parallel." [5] |
| 독립성을 프롬프트에 기댐 | 읽지 않는다고 쓰고 읽으라고 지시한 시연 [11] |
| 저장을 내구 실행으로 착각 | "Checkpoints are not durable execution." [8] |

## 코드베이스 지식 그래프(Graphify)는 다른 그래프

다섯 말을 가르는 글 [9]: 온톨로지 · 지식 그래프 · 컨텍스트 그래프 · 코드 그래프는 시스템이 아는 것, 그래프 엔지니어링은 시스템이 행동하는 방식이다.

| | 코드 지식 그래프 | 에이전트 흐름 그래프 |
|---|---|---|
| 점 · 선 | 파일 · 함수 · 경로 · 문서 / 가져오기 · 호출 · 참조 | 탐색 · 구현 · 테스트 · 검토 / 허용된 전환 |
| 묻는 것 | "What connects this route to the database?" | "What runs after the tests fail?" |
| 위험 | 빠졌거나 낡았거나 추정된 관계 | 조율 비용, 불분명한 책임 |
| 만드는 법 | 코드에서 뽑는다. 파생물 | 설계자가 그린다. 정본 |

| Graphify [30][31][32] | 내용 |
|---|---|
| 하는 일 | 코드 · 문서 · SQL 스키마 · 설정 · PDF 를 질의할 수 있는 지식 그래프로. 벡터 저장소 없음. 코드는 tree-sitter 로 로컬 파싱(LLM 없음), 문서 · 이미지는 모델이 읽음. 공개 2026-04-05, 0.9.53(2026-08-30) |
| 설치 · 명령 | `uv tool install graphifyy`, `graphify install`, 에이전트에서 `/graphify .`. `query "<질문>"` · `path A B` · `explain "<이름>"` · `extract`(코드만 오프라인) · `update .` · `hook install`(커밋 때 재빌드) |
| 산출물 | `graphify-out/` 의 graph.json · GRAPH_REPORT.md · graph.html. Claude Code 는 훅이 검색 전에 그래프를 권하고 스킬을 쓴다 |
| 출처 표시 | 선마다 EXTRACTED(소스에 명시) · INFERRED(해석해 도출). 리뷰는 AMBIGUOUS 까지 |
| 절감 수치 | 조건이 다르다. README 의 80% 는 유료 Cloud 문구, 71.5배는 큰 모노레포 한 질의의 천장, 벤치마크는 ERPNext 질문 6개에서 핵심 사실 포함률 70.8 → 82.0%(저자 자체 측정). 리뷰 결론은 "pilot 은 정당하지만 ROI 주장은 아니다" |
| 비용 | 코드 파싱은 크레딧 0, 문서 · 이미지는 모델 필요. 설치 · 규칙 · 보안 검토 · 교육 · 유지보수. 작은 코드베이스는 그래프 만드는 시간이 버그 찾는 시간보다 길었다는 경험담 |
| 대안 | CodeGraph(실시간 MCP), codebase-memory-mcp(158개 언어), code-review-graph(SQLite). 각사 수치는 비교 불가. 도구 없음(grep + 심볼 검색 + 계층 CLAUDE.md)이 Anthropic 권고 [27] |

들일 조건 셋: 소스 파일이 수백 개(글쓴이 기준 500+)를 넘고 모듈 의존이 깊다, 에이전트가 같은 구조를 다시 찾느라 턴을 많이 쓴다, 15분 시험(실제 질문 하나를 grep 과 그래프로 풀어 토큰 · 호출 · 정확도 비교)에서 이긴다. 우리는 코드가 없어 지금 들이지 않는다. 1-가 뼈대 뒤 파일 수와 탐색 턴을 재고, 그 전까지는 dependency-cruiser 규칙 · 계층 CLAUDE.md · 심볼 검색으로 간다. 정본 문서(spec · 볼트)는 대상에서 뺀다. 번호 정규식(P3)이 결정적이고 모델이 뽑은 선은 정본을 하나 더 만든다.

네 그래프의 자리: 지식(왜)은 볼트 index → 쪽 → 원자료, 추적(맞나)은 specs 번호 그래프 P3, 코드(무엇)는 dependency-cruiser 와 나중에 Graphify, 흐름(다음)은 위 표 · 스킬 · 훅 · 워크플로. 흐름 그래프의 설명은 볼트가, 집행은 저장소(스킬 · 훅 · 워크플로)가 맡는다.

## 하지 말 것 · 조심할 것

| 항목 | 이유 |
|---|---|
| 그래프가 검증을 대신하지 않는다 | "The graph didn't eliminate mistakes. It gave every mistake an address." [6] |
| 점을 늘리기 전에 목표와 성공 기준 | 단발 작업인가, 분기 · 병렬 · 중간 검증 · 사람 승인 가운데 둘 이상이 필요한가 [20][5] |
| 상태 파일 충돌 | seed/manifest · progress.md · 장부를 여러 에이전트가 동시에 고치지 않는다. 쓰는 점 하나, 병렬 쓰기는 파일 소유를 나누거나 worktree |
| 비용 | 갈라 보내기 폭 × 재시도 × 컨텍스트. 연구 시스템은 채팅의 약 15배 [22]. 경고는 에이전트 25 또는 150만 토큰 [24] |
| 사람 게이트를 모델 승인으로 대신하지 않는다 | 에이전트 팀의 계획 승인은 리드가 바로 승인한다. 다른 에이전트가 전한 "승인했다"는 승인이 아니다. 외부 글을 읽는 점과 쓰는 점을 나눈다 [25][8][13] |
