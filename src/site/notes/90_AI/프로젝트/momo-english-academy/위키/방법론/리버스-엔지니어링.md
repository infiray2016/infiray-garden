# 리버스 엔지니어링 정리

요청자 지시(2026-10-16 03:3x)로 조사 담당(Sonnet · high)이 심층 조사했다. 원문 사본은 [[90_AI/프로젝트/momo-english-academy/원자료/조사/2026-10-16_조사_리버스-엔지니어링\|2026-10-16_조사_리버스-엔지니어링]](갈래 6 · 원문 32 · 제안 10). 어제의 제품 조사 [[90_AI/프로젝트/momo-english-academy/원자료/조사/2026-10-15_조사_영어-프로그램-리버스-엔지니어링\|2026-10-15_조사_영어-프로그램-리버스-엔지니어링]]은 아래 분류로 '공개 자료만 읽는 제품 분해'다. 저장소 스킬은 `.claude/skills/reverse-engineering/SKILL.md`. 세 방법론의 자리는 [[90_AI/프로젝트/momo-english-academy/위키/방법론/AI-SDLC\|AI-SDLC]]. 법 조문은 원문 · 공식 요약으로 확인했지만 법률 자문이 아니다.

## 한 줄 요지

리버스 엔지니어링은 **이미 있는 것을 살펴 구성 요소와 관계를 알아내고 더 높은 추상으로 다시 그리는 일**이다. 정의상 살펴보는 일이지 고치거나 복제하는 일이 아니다(Chikofsky · Cross 1990). 선은 분명하다. 공개 자료 읽기와 내 기기 · 내 계정 · 내 키로 정상 이용하며 보는 것은 하고, 디컴파일 · 보호 조치 우회 · 남의 서버 자동 요청 · 남의 표현 복사 · 아이나 타인 계정 사용은 하지 않는다. 한국 저작권법 제101조의4 의 역분석 예외는 호환 목적뿐이라 경쟁 분석은 기댈 수 없다.

## 여섯 용어(Chikofsky · Cross 1990)

| 용어 | 요지 | 우리에게 |
|---|---|---|
| 앞으로 가는 개발 | 요구 → 설계 → 구현 | intent → spec → plan → 코드 |
| 리버스 엔지니어링 | 구성 요소 · 관계를 찾아 더 높은 추상으로 표현. 바꾸지 않음 | 이 쪽의 주제 |
| 문서 다시 만들기 | 같은 추상 수준의 다른 표현(구조도 · 상호 참조) | 코드에서 식별자 표를 뽑아 정본과 맞대기 |
| 설계 복원 | 코드 밖 지식과 추론을 더해 '왜'까지 | '왜'의 정본은 13절 결정 기록 |
| 구조 다듬기 | 모양만 바꾸고 동작은 그대로 | 코드 정리 |
| 고쳐 짓기 | 리버스 뒤 새로 만듦 | 해당 없음 |

## 여섯 갈래와 우리와의 거리

| 갈래 | 방법 | 거리 |
|---|---|---|
| 제품 분해(teardown) | 제품 고르기 → 범위 → 자료 · 분석 → 기록 → 종합 | 가깝다(어제 함, 직접 써 보기는 아직) |
| 통신 관찰 · 프로토콜 복원 | 개발자 도구 · HAR · mitmproxy | 우리가 쓰는 API 에 쓴다. 경쟁 서버는 안 함 |
| 코드 리버스 엔지니어링 | Ghidra · jadx · Frida | 하지 않는다 |
| 소프트웨어 고고학 | 현장 점검 · 지도 · 용어집 · 추적 · 테스트로 증명 | 코드가 생긴 뒤 차수마다 |
| 명세 복원(코드 → 문서 · 테스트) | 식별자 표 · 규칙 목록 · 동작 기록 테스트(Feathers) | spec ↔ 코드 동기화의 몸통 |
| AI 에이전트의 복원 | 개요 → 구조 → 자료 모형 → 용어집, 읽기 전용 에이전트, 주장마다 코드 위치 · 확신도 | 우리 방식. 복원문은 '왜'를 못 담고(연구 결과), 근거 없는 줄은 빈칸 |

## 깊이와 판정

| 깊이 | 하는 일 | 판정 |
|---|---|---|
| 1 | 공개 자료 읽기 | 한다(어제 했다) |
| 2 | 요청자 기기 · 계정으로 직접 써 보기(약관의 캡처 · 녹화 · 계정 공유 금지 먼저 확인) | 한다 |
| 3 | 화면 흐름 메모 · 소량 캡처(표현은 옮기지 않음) | 한다 |
| 4 | 우리 키 · 기기로 우리가 쓰는 API · 브라우저 기능 관찰 | 한다 |
| 5 | 경쟁 서비스의 통신 관찰 | 하지 않는다(대법원 2021도1533 은 무죄였지만 부정경쟁 · 약관 위험이 남는다) |
| 6 | 앱 분해 · 디컴파일 · 인증서 고정 우회 · 자동 수집 · 유료 벽 우회 | 하지 않는다(제101조의4 밖, 제104조의2) |

## 우리 프로젝트에 비추면(제안 10)

| 단계 | 제안 | 비용 | 효과 |
|---|---|---|---|
| Plan | 1 참고 서비스 직접 써 보기 질문표(아동 AI 대화의 글 표시 · 턴 수 · 통과 문턱 · 복습 양 · 부모 보고 · 가격) · 2 가격 · 구성의 시간 변화(웹 보관소) · 3 분해 노트 규칙과 하지 말 것 | 서비스당 1~2시간 | 어제 '바깥'으로 판정한 여덟 곳을 추정에서 사실로 |
| Design | 4 음성 인식 이벤트 기록표(iPad 실기와 같은 관찰 페이지, 가짜 음성 대본) · 5 Anthropic 호출 관찰표(세 모델 × 호출 종류, 'AI 쉬는 중' 오류 응답, 구조화 출력 제약, 모델별 요청 제약 → 고정 표본) | 반나절 + 기기당 30분, 호출 1달러 안쪽 | 가짜 API 와 실제가 어긋나는 일, 쉬는 중 오분류, 스키마 불일치를 운영 전에 잡음 |
| Build · Review | 6 식별자 대조 스크립트(설정 키 · 테이블 · 스키마 · 라우트 ↔ 정본, 박힌 숫자) · 7 서술 대조(analyst 가 코드에서 규칙을 뽑아 정본과 맞댐) · 8 순수 함수 동작 기록 테스트 | 반나절~하루, 차수마다 | '정본을 먼저 고친다' 규칙을 기계가 봄 |
| 시드 | 9 아이 눈 순회 체크 목록(인지 순회 네 질문 + 우리 질문 넷) · 10 어휘 배정표를 CEFR-J 목록(7,801 항목, 무료)과 대조 | 단원당 30분, 스크립트 반나절 | 판정 기준이 흔들리지 않음, 어휘 범위의 CEFR 어긋남을 본 생성 전에 |

더 알아볼 것: 경쟁 서비스 약관 원문, 약관이 법의 예외를 없앨 수 있는지(한국), 제104조의2 단서 여덟 호 전문, 부정경쟁방지법 (파)목 민사 결과, 구조화 출력 문서 끝부분과 지출 한도 오류 페이지, 클린룸 한국 판결.
