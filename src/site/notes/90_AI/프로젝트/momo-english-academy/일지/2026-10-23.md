- Playwright 단추 찾기는 짧은 한국어 이름('다음' · '홈' · '힌트')이 긴 이름('다음 이야기' · '힌트 문장 듣기')에 부분 일치로 걸린다 — e2e 도우미에서 exact 를 기본으로.
- 마이그레이션이 든 가지를 프리뷰에 올리면 같은 개발용 DB 를 쓰므로 `drizzle.__drizzle_migrations` 를 먼저 견준다 — 배포 READY 만으로는 회화처럼 새 열을 쓰는 화면이 열리는지 모른다.

- 요청자의 질문 · 반응은 결정 · 판정 근거로 적지 않는다. 결정 목록에는 요청자가 정한 것만, 질문에 한 답은 일지 '한 일'에만.
- 결정 시각은 어림하지 않고 세션기록 줄에서 옮긴다.
- 모델을 바꾸는 결정은 같은 차례에 비용 표 · 기술 표 · CLAUDE.md 까지 찾아 고친다(`grep` 으로 모델 이름 전수).
- 화면 검토 기준에 '같은 종류 종이 크기 일관 · 같은 줄 아래 끝'을 둔다(C114 — 여러 번의 검토가 놓침).
- 볼트 검사 스크립트는 저장소 뿌리에서 돌린다 — 하위 폴더(.superpowers/…)에서 돌리면 폴더 이름을 저장소로 읽어 다른 상태 폴더에 표시한다(06:5x 한 번 겪음).
- 프리뷰를 보여 줄 때 '시험용 자료'를 한 줄로만 적으면 놓친다 — 무엇이 지어낸 낱말인지 화면 예(bababa)와 함께, 진짜 수업이 언제 들어가는지를 먼저 말한다.
- 맥락 요약 직후에는 내보내는 글의 언어를 먼저 본다 — 생각은 영어여도 답 · 상태 줄 · 표는 한국어 해요체.
- 검토자가 '헛걸림'이라 적은 예시는 규칙에 한 번 대 보고 브리프에 옮긴다('리온' = 리오 + ㄴ).
- 세션 중에 에이전트 정의를 고치면, 그 판이 실제로 쓰였는지 보고에서 확인할 길을 호출에 넣는다.
- 도구 동작은 관찰 하나로 일반화하지 않는다 — 두 번째 '정의 확인' 줄을 보고 정했으면 C137 을 고칠 일이 없었다.
- 구현 · 검토 브리프의 관문 목록은 CI 작업 목록과 같게 둔다(이번엔 check:deps 가 빠져 CI 에서야 걸림).
- 규칙의 출처를 말할 때는 결정 기록(13절 · 결정 목록 · git log)을 먼저 확인한다. '정해 두신 규칙'이라고 단정하지 않는다.
- 목표가 정해진 일에서는 제약을 선택지 질문으로 넘기지 말고 가장 빠른 길로 풀어 진행한 뒤 결과만 알린다(13:2x 요청자 '안 돼요 이러지 말고').
- 번호는 늘 '회화 1단계 단원 4'처럼 단계와 단원을 같이 쓴다. 요청자 말의 숫자가 갈리면 그 자리에서 한 줄로 되묻는다(메모리 feedback-level-unit-numbers).
- 중간 프리뷰는 첫 문장에 '중간 단계 — 요청하신 X 는 아직(언제)'을 둔다. 완성이 아니면 '됐어요'로 열지 않는다(메모리 feedback-show-scope-before-demo 보충).
- 조사 · 웹 요청 브리프에는 '요청 머리(User-Agent 등) · 본문에 요청자 이메일 · 이름 같은 개인 정보를 넣지 않는다'와 '큰 PDF 파싱은 크레딧을 먼저 어림'을 적는다(10-23 res-cefrj).
