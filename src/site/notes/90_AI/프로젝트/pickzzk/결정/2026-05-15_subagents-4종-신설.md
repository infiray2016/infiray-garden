# Subagents 4종 신설 — pickzzk 자동화 인프라

> `.claude/agents/` 박음 — 자주 반복되는 검증/grep 패턴 자동화. 다음 세션부터 `Agent` tool 의 `subagent_type=` 으로 호출 가능.

## 배경

R21 시리즈 진행 중 매 commit 마다 반복 패턴 발견:
1. UI 변경 시 dev server 띄우고 Playwright 3 viewport 매뉴얼 (~5분/commit)
2. 새 작업 진입 시 design doc / memory grep 로 박힌 결정 확인 (~10분/작업)
3. R20 C14 시리즈 multi 검증 = user 가 manual 시각 검증 (~15-30분/시나리오)
4. Codex 큐 갱신 시 design doc cross-check + 분류 (~10분/항목)

이 4 패턴을 subagent 로 자동화하면 시간 절약 큼. user 가 "서브에이전트 만들고 싶어" 요청 시 가장 가치 큰 4종 추천 → 다 박음.

### 공통 룰 박힘

- **model = sonnet** — Playwright / grep / 분류 작업에 충분. opus 과함.
- **HARD GATE = 코드 수정 X** — 검증 / 분류 / 추천 만. 실 처리는 메인 세션이 결정.
- **자기 발견 (self-discovering)** — agent 가 자체 grep + read 로 codebase 패턴 파악. selector / URL 하드코드 X (drift 방지).
- **`.gitignore` policy** — `.claude/agents/` 는 개인용 default (line 52). 이 4개만 `git add -f` 로 예외 force-track (Codex / 다음 Claude 세션 참조 위해).

## 의사결정 옵션

### 어떤 subagent 박을지

후보:
- spec-grepper, visual-regression, codex-review-handler (강추 3종)
- mock-test-runner (multi 자동화 가치 큼, 별 결정 묶음)
- deploy-prep, dead-code-hunter, memory-curator (덜 자주, 후순위)

**선택: 강추 3종 + mock-test-runner = 4종.** deploy-prep / dead-code-hunter / memory-curator 는 가치 입증 후 추가.

**근거:**
- 강추 3종은 매 작업 / commit 마다 발동 — ROI 큼.
- mock-test-runner 는 multi 자동화 가치 (R20 C14 user 시간 큼).
- 후순위 3종은 단발성 가치 — 필요 시점에 만들기.

### `.claude/agents/` policy (force-track 여부)

**옵션 A** (선택): git add -f 로 4개만 예외 commit. .gitignore 정책 유지.
**옵션 B**: .gitignore 수정 — agents/ 제거. shared 자원 정책 전환.
**옵션 C**: 그대로 두고 개인용으로.

**근거: A**
- solo 개발자라 팀 공유 고려 minimal.
- 다음 세션 / Codex 참조 가치 큼.
- B 는 정책 일관성 깨뜨림. A = case-by-case override 만.

## 시각 검증 agent 의 확장된 scope (visual-regression)

user 요청 verbatim: "디자인 최적화 pwa, 모바일 편의성도 체크, 사용자친화적인지도 같이"

→ 단순 스크린샷 매트릭스 넘어서 4축 종합:
1. **시각 회귀** — 3 viewport + console 0 + overflow / clipping
2. **디자인 톤 v10** — 검은 배경 audit, raw uid / `#N` / `UNDEFINED` 노출 X (R5)
3. **PWA + 모바일 편의** — safe-area, bottom-nav 노출, 탭 hit area ≥ 44px (iOS HIG), standalone emulation
4. **사용자친화도** — hierarchy (h1 / h2), terminal glyph 과밀 audit, 빈 상태 카피, primary CTA
