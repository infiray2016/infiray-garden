# 선수 상세 모달을 옛 DraftPick 수준으로 + 솔로랭크 데이터 파이프라인 3단계

> 2026-05-24 세션. "모달 구성을 옛 DraftPick 사이트처럼 해달라"는 요청으로, 선수 상세 창을 5개 탭의 풍부한 형태로 다시 만들고, 그 탭들을 채울 솔로랭크 데이터를 새로 수집하도록 만들었다.

## 배경

선수 상세 창이 단순했다(롤 계정 / 티어 / 모스트 챔프 / AI 평가 한 줄). 옛 DraftPick 사이트의 선수 상세는 훨씬 풍부했다 — 프로필 + 5개 탭(요약 / 지표 / AI 인사이트 / 챔피언 / 최근 경기). "그 구성처럼 해달라"는 요청.

문제는 두 가지였다: ① 옛 사이트는 어두운 테마인데 픽지직은 밝은 톤(v10)이라 그대로 못 베낀다. ② 그 풍부한 탭(킬관여·데스 분포·최근 경기·AI 점수 등)은 그 데이터를 먼저 수집해야 채워지는데, 픽지직은 그 세부 지표를 안 모으고 있었다.

## 결정

세 단계로 나눠서 만들었다.

- **A. 모달 화면** — 옛 사이트 구성(프로필 + 5탭)을 픽지직 밝은 톤으로 옮겼다. 먼저 시안(HTML mockup)으로 구성을 잡아 확정받고 컴포넌트로 만들었다. 데이터가 아직 없는 선수는 "수집 후 표시" 안내가 뜨게 해서 안 깨진다. 홈에서는 보기 전용(픽 버튼 없음), 모의 드래프트에서는 픽 버튼이 있게 같은 컴포넌트를 재사용.
- **B. 데이터 수집(fetch-riot)** — 경기마다 킬관여·분당 CS·솔로킬·분당 딜·시야·데스 시간대·최근 경기 기록 등을 뽑아 저장하도록 확장. 옛 사이트의 수집 코드를 옮겼다.
- **C. AI 분석(fetch-ai)** — AI가 그 지표를 보고 한 줄 평가·강점/약점·드래프트 활용·팀 적합도 + 점수(포지션 수행/기복/캐리력)·플레이 스타일 분포까지 만들도록 프롬프트를 다시 썼다.

화면에 이름을 옮기는 것처럼, 선수의 풍부한 지표를 모의 화면으로 옮기는 것도 한 곳(`playerStats.js`)으로 모아 중복을 없앴다.

## 검증 결과

- 코드: 단위 테스트 회귀·빌드 통과. 1명(뱅) 먼저 수집해 새 필드(데스 분포·최근 경기 등) 저장 확인 후, 27명 전체 수집 + AI 분석 완주.
- 화면: 5탭 전부 실제 데이터로 뜨는 것 직접 확인(티어·킬관여·데스 분포·최근 경기·AI 점수). 콘솔 오류 0.
- 모바일/디자인 검증(visual-regression): 375px에서 탭이 잘리던 것·터치 영역이 작던 것·안내 문구에 내부 명령어가 노출되던 것을 잡아 수정. 이어서 흐름 검증(qa)도 버그 0으로 통과.

## 결과 / 영향 / 다음에 조심할 것

- 시청자 입장: 선수를 누르면 전적 사이트 수준의 상세(전적·지표·AI 분석·챔피언·최근 경기)를 본다. "지표 보기" 비전의 선수별 통계를 모달 형태로 먼저 맛본 셈.
- 운영: 활성 시기 직전 `fetch:riot` + `fetch:ai` 한 번 돌리면 최신화. Riot 키는 24h 만료라 그때 갱신.
- 다음에 조심할 것:
  - "DraftPick"(옛 사이트)과 "드래프트"(모의 드래프트 화면)를 헷갈리지 말 것. 이번에 "드래프트 픽처럼"을 모의 드래프트로 오해했다가 정정받았다.
  - 안내 문구에 `fetch:riot` 같은 내부 명령어를 쓰지 말 것(시청자 화면). visual-regression이 잡았다.
  - 풍부한 화면은 "어떤 데이터가 있어야 채워지나"의 사슬(수집 → 분석 → 표시)을 먼저 그려야 한다. 화면만 만들면 빈 칸이 남는다.
