# 2026-06-07 viewer 제보 흐름 끝까지 동작

## 무엇

운영자가 아닌 익명 시청자가 `/scrim/submit` 에서 스크린샷 한 장 올리고 → OCR → 매핑 → 제보 버튼 한 번으로 firestore submissions 큐까지 실제로 박히는 흐름을 끝까지 통과시킴. 동시에 픽밴/선수/챔프 OCR 결과 확인 UI 세 영역의 시각 패턴을 하나로 통일 (`OcrRowBase`) 하고, 아카이브 페이지의 가짜 데이터(호종컵 4기 fixture) 를 빈 상태로 정리. 지표 화면(`/stats`) 챔프 펼침에 "분당 골드 / 골드당 딜 / 팀 골드 비중" 세 메트릭 추가.

## 왜

사용자가 한 마디로 "지금 게임 결과 올리면 에러남" 보고. 동시에 "픽밴/선수/챔프 OCR 영역이 다 달라서 통일성이 부족하다" + "아카이브에 가짜 데이터(호종컵 4기) 가 보이는데 지워달라" 같은 부수 요청. 처음엔 단일 버그처럼 보였지만 진단 결과 viewer 제보 흐름이 **4 층으로 동시에 깨져 있었음**:

1. **vite HMR stale module** — 사용자가 띄워둔 dev server 가 새 import 인식 못해 `filterTestDocs is not defined` runtime 에러
2. **v-model 의 ref.value 패턴** — `v-model:winner="state.winner.value"` 가 Vue 3 compiler 에서 setter 인식 못함. user manual click (winner 선택 등) 이 silent fail. OCR 으로 자동 채워지는 fields 만 동작
3. **vite-only dev 환경** — `bun run dev` 로는 vercel serverless function (`/api/scrim-submit`) 안 띄움. `vercel dev` 또는 production 배포에서만 동작
4. **client/server schema mismatch** — client `toGameData()` 는 `teamA/teamB/winner` (이름 기반) 박는데 server `handleScrimSubmit` 는 `teamAId/teamBId/winnerTeamId` (id 기반) 필수. 400 reject

각 층을 fix 할 때마다 다음 층이 드러나는 양파 구조. 한 마디 보고가 결국 12개 commit 으로 풀림.

## 어떻게

### 1차 — Codex 큐 #2 P1 (경기 카드 클릭 → 상세)
`scrimDays/{date}/games/{gameId}` 의 doc id 가 payload 안 `id` 필드로 박혀있지 않아서 `collectionGroup` fallback query 가 동작 안 함. 4 저장 경로 (admin saveGame, viewer submit consensus, admin queue approveCluster/approveSubmission) 모두 `doc(collection())/setDoc` 패턴으로 doc id 선생성 후 payload 에 박음. `ScrimDaySoloCard` / `ScrimDaySeriesCard` 의 game-row 에 click + Enter/Space 핸들러 (role=button + tabindex). commit 70e9060.

### 2차 — 아카이브 fixture 제거
`useArchive` 와 `useArchivedTournament` 가 firestore archived doc 0건일 때 `mock-tournament-archived.json` (호종컵 4기) 을 fallback 으로 보여줘서 viewer 가 "이게 진짜인지 가짜인지" 헷갈림. fixture 코드 제거. archived doc 0건이면 isEmpty=true → "아카이브 시즌 없음" 빈 상태. `useActiveTournament` 의 `lastTournament` 는 CLOSED 페이지 last 시즌 표시 용도라 scope 한정 유지. commit e6f9a28. memory [[feedback_archive_fixture_removed_2026-06-07\|feedback_archive_fixture_removed_2026-06-07]] 박힘.

### 3차 — 익명 viewer rules (옵션 D1)
시청자가 익명 상태로 스크린샷 올리려고 하면 storage `auth != null` 가드로 403 + firestore submissions read 가 admin only 라 duplicate scan 401. viewer = 익명 시청자 frame ([[user_role_viewer\|user_role_viewer]]) 정합. storage.rules 의 `scrim-screenshots` write 조건에서 auth 제거 (size 5MB + image/* contentType 가드만 유지). firestore.rules 의 submissions read 익명 허용 (submitter 가 viewer 면 clientId/nickname 만, uid 노출 risk 없음). `firebase deploy --only firestore:rules,storage` 즉시 적용. commit b6fa4c2.

### 4차 — OcrRowBase 통합 (C1~C4, 시각 통일)
3 OCR 영역 (벤/선수/챔프) 의 row 패턴이 2종 (legacy BanToolSlotRow 의 grid + chip-always vs 신규 LineupNameInput/ChampionField 의 row + drawer toggle) 으로 갈라져 있었음. 사용자가 "셋 다 다르다 통일해줘" 명시. 풀 base 컴포넌트 `OcrRowBase` 만들어 layout/status pill/drawer toggle/crop mount 모두 담당, caller 는 slot 으로 input/before-input/after-pill/drawer-extra/dropdown 만 채움. 5 slot + props 13개. ban 의 slot crop 시각화는 `showCropInline` 옵션. 선수의 cross-team 시각, chip 안 TXT/ICN source 라벨도 정리 (score % 만 유지). legacy `BanToolSlotRow.vue` 폐기. 4 commits (C1 base+tests / C2 선수+챔프 migration / C3 ban+legacy 폐기 / C4 source noise 제거 — 보정 commit 포함하면 e26f65b/aa38dc2 두 개). source: `.claude/PLAN_2026-06-07_ocr-row-base.md`.

### 5차 — winner v-model fix (4 층 중 2 번째 층)
사용자가 viewer 흐름 직접 시도 → 24/24 필드인데 winner 클릭이 등록 안 됨. `v-model:winner="state.winner.value"` 처럼 ref 의 `.value` accessor 를 v-model expression 으로 박은 6 곳 모두 explicit form (`:winner=` + `@update:winner=`) 으로 풀어 setter 보장. OCR 으로 채워지는 case 는 `applyRecognition` 가 ref.value 직접 박아서 v-model 안 거침 → 영향 없었음. user manual click 만 회귀였음. commit b6a0eca.

### 6차 — vercel dev 환경 + Codex 큐 #1 P0 (normalizer)
winner fix 후 submit 시도 → `/api/scrim-submit` 404. vite 만으로는 vercel serverless function 못 띄움. user 가 `npm i -g vercel` + `vercel login` 후 background 띄움. 재시도 → 404 가 400 으로 바뀜 (server 도달). server reject 사유 = "gameData missing teamAId/teamBId/winnerTeamId" — Codex 큐 #1 P0 의 정확한 증상. `src/utils/normalizeGameData.js` (신규) 가 client toGameData 결과를 받아 legacy + 신규 두 형식 동시 박음 (teamAId=teamA name fallback, players[10] 으로 lineup 변환, role 매핑 Jng→Jungle, damageToChamps→totalDamage 등). 4 저장 경로 (submit/saveGame/approveCluster/approveSubmission) 모두 normalizer 통과. e2e Playwright 로 "✓ 제보 완료" alert + server 200 OK confirm. commits abbff89 + 8531713.

### 7차 — Codex 큐 #6 P2 (지표 메트릭 + 풀어쓰기 라벨)
DraftPick legacy 의 GPM/DPG/GOLD% 메트릭이 빠져있어 추가. `aggregateGamesByStreamer` 에 `acc.goldShareDen` 누적 + `avgGpm` (분당 골드) / `avgDpg` (골드당 딜) / `avgGoldShare` (팀 골드 비중) 3종. `/stats` 챔프 펼침 footer 에 풀어쓰기 라벨 line 추가 — 약어 (GPM/DPG/GOLD%) 대신 "분당 골드 / 골드당 딜 / 팀 골드 비중" 으로 표시. user 의 풀어쓰기 룰 ([[feedback_doc_plain_language_2026-05-18\|feedback_doc_plain_language_2026-05-18]]) 정합, 데이터 key 는 약어 base. commits 04fdc8e + c22aae5.

### 8차 — B 단계 OCR text 챔프 화이트리스트
4-2 스크린샷 OCR 결과에 "자연 / 오릭 / 벡토르" 같이 한글 챔프 이름과 비슷하지만 실제 존재 안 하는 invalid string 이 status=auto 박혀서 viewer 가 잘못된 채로 저장 시도하는 회귀. `mergeChampionRecognition` (export 추가) 에 `isValidChampion` 검증 박음. text invalid + visual 일치 → candidate 강등, text invalid + visual 없음 → unknown 강등. `championList` lazy load 이전엔 `isValidChampion` 가 true (lenient default) 라 회귀 영향 0. commit 998d60e.
