# 프로필 사진을 우리 쪽에 저장 — 결과 화면 "이미지 저장"에 실사진 나오게

> 2026-05-22 세션. 모의 드래프트/경매 결과 화면의 "이미지 저장"(PNG 내보내기)에 스트리머 프로필 사진이 안 나오던 문제를 해결했다. 치지직 사진을 우리가 미리 받아 스트리머 정보에 저장해두는 방식.

## 배경

결과 화면에서 "이미지 저장"을 누르면 팀별 명단이 PNG로 저장되는데, **프로필 사진이 전부 빈 동그라미**로 나왔다. 화면에서는 멀쩡히 보이는데 저장된 이미지에서만 안 보였다.

원인은 치지직 사진이 **다른 사이트(naver) 주소**라서다. 브라우저가 화면에 그릴 땐 문제없지만, 그 화면을 이미지 파일로 캡처하는 기술은 보안 규칙(다른 사이트 이미지)상 그 사진을 캡처에 못 담는다. 그리고 이름이 두 줄로 깨져 팀명과 겹치는 문제도 같이 있었다.

## 결정

- 치지직 사진을 **우리가 미리 받아 스트리머 정보(`streamers/{id}.profileImageData`)에 작게(약 120px) 저장**해둔다. 그러면 외부 요청이 없어 이미지 저장에 100% 담긴다.
- 사진 받기는 **두 경로**: ① 스트리머를 새로 등록/갱신할 때 우리 백엔드가 자동으로 받아 저장(별도 작업 불필요), ② 기존 누적분은 `bun run fetch:profiles` 스크립트로 일괄.
- 사진 변환은 **서버에서만** 가능하다(브라우저는 같은 보안 규칙으로 막힘). 그래서 스트리머 DB 화면(클라이언트)이 아니라 백엔드/스크립트에서 처리.
- 이미지 저장에는 실사진이 안 담기는 다른 옵션(저장소 업로드)보다 이 방식(작은 사진을 정보에 통째로 저장)이 추가 서버/설정 없이 가장 단순해서 채택. 시청자 수가 적어 용량 부담도 없다.
- 이름 겹침은 글자가 한 줄로 나오게 고치고, 사진 못 받은 경우엔 빈 동그라미 대신 색깔 이니셜이 나오게 했다.

## 검증 결과

- 호종컵 28명 전원 사진 저장 성공(평균 ~15KB).
- 결과 화면 "이미지 저장" 캡처를 직접 받아 확인: 감독/팀장 + 선수 전원 **실제 프로필 사진**이 나오고, 이름은 한 줄, 빈 동그라미 0.
- 화면 표시·반응형(폭 375/768/1440)·콘솔 오류 0.
- 실제로 새 스트리머(괴물쥐·풍월량)를 등록해보니 사진이 자동 저장되는 것 확인(테스트 후 삭제).

## 결과 / 영향 / 다음에 조심할 것

- 시청자 입장: 모의 결과를 이미지로 저장해 친구에게 공유할 때 프로필 사진까지 제대로 나온다.
- 운영: 스트리머를 새로 등록하면 사진은 자동. 기존/누락분만 가끔 `fetch:profiles` 한 번.
- 주의: 화면용 고화질 주소(`chzzkProfileImageUrl`)와 저장용 작은 사진(`profileImageData`)을 둘 다 둔다. 아바타는 저장용을 우선 쓰되 없으면 주소로 fallback.
