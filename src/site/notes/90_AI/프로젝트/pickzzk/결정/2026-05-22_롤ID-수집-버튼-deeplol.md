# 스트리머 DB "롤 ID 자동 찾기" 버튼 — DeepLOL 한글검색 + 부계정 전부

> 2026-05-22 세션. 스트리머 편집 화면에서 버튼 한 번으로 그 사람의 롤 계정(부계정 포함)을 찾아 채우는 기능. 기존엔 명령줄 스크립트(map:deeplol)만 있었다.

## 배경

스트리머 DB의 4명(앰비션·뱅·플레임·서새봄냥)이 롤 ID가 비어 있었다. DeepLOL로 자동 매핑하는 스크립트는 이미 있었지만 명령줄 전용이라, 운영자가 편집하다 바로 못 쓴다. 그래서 편집 화면에 "🔎 롤 ID 자동 찾기" 버튼을 붙이기로 했다.

진행하면서 DeepLOL 데이터의 까다로운 점들이 드러났다.

## 결정 (몇 번의 정정 포함)

- **편집 화면 버튼 + 백엔드 조회.** 치지직 조회가 우리 백엔드를 거치므로(보안 우회), 거기에 DeepLOL 조회를 붙였다. 스크립트/엔드포인트/버튼이 **같은 lookup 코드** 공유.
- **한글 닉 → 프로 검색 (정정).** 처음엔 이름 직접 조회를 썼는데, DeepLOL은 전 프로를 영문 핸들("Ambition", "Flame")로만 색인해서 한글 닉("앰비션")으론 빈 응답이었다. 웹사이트 검색창이 쓰는 **자동완성 API(한글닉→핸들+채널)** 를 먼저 거치게 바꿔서 프로도 한글로 찾아진다.
- **puuid는 라이엇이 권위 (정정).** DeepLOL이 주는 puuid는 라이엇의 실제 puuid가 아니라 신뢰 못 한다. 롤 ID(이름#태그)만 DeepLOL에서 받고, puuid는 라이엇 API로 받는다.
- **"정답 강제" 가드 폐기 → "제안+사람 확인" 모델 (정정).** DeepLOL puuid와 라이엇 puuid를 비교해 다르면 막는 가드를 뒀다가, 그게 항상 발동해서 맞는 계정도 다 막는 걸 발견(멋사 사례). 정확성은 puuid 비교가 아니라 **티어/최근게임을 같이 보여주고 운영자가 보고 저장**하는 걸로 담보한다. 버튼은 저장 전 사람이 확인하므로 틀린 건 운영자가 거른다.
- **부계정 전부 수집.** 메인 1개만 고르지 말고 그 사람의 모든 계정을 라이엇 검증해 다 추가(메인 먼저 정렬). 운영자가 보고 필요한 것만 남긴다.
- 못 찾으면 "수동 입력하세요" 안내. DeepLOL이 닉으로 색인 안 하는 사람은 손으로.

## 검증 결과

- 앰비션 = `mctambition#mct`(MASTER) + 부계정 2개 전부 라이엇 puuid 포함해서 나옴. 플레임 = `아오플쌤#kr1`(MASTER) + `goldtec#flame`.
- 매칭 로직(치지직 주소에서 채널 id 뽑기)은 방송 ON(`/live/...`)/OFF 둘 다 처리.
- 한참 헤맨 진짜 버그: 후보의 주소(문자열)를 객체 받는 함수에 넘겨서 매칭이 항상 실패하던 것 → "이 채널 연결 없음"이 계속 뜬 원인. 인자 처리 고쳐 해결. (중간에 DeepLOL 요청 제한(throttle)으로 오진해 시간을 많이 썼다 — 디버그 출력으로 잡음.)

## 결과 / 영향 / 다음에 조심할 것

- 운영자: 편집하다 버튼 한 번이면 그 사람 롤 계정(부계정 포함) 후보가 뜨고, 티어/최근으로 맞는지 보고 저장.
- **DeepLOL은 비공식**이라 요청을 빨리 여러 번 하면 빈 응답(throttle)이 온다. 버튼은 띄엄띄엄 단발이라 괜찮지만, 디버깅하느라 연속으로 두드리면 막힌다 — 다음엔 throttle 가능성을 먼저 의심하지 말고 **순수 로직부터(네트워크 없이) 검증**할 것.
- puuid는 안정적, 롤 ID(이름#태그)는 바뀌거나 재사용될 수 있다 — by-riot-id 결과를 맹신하지 말 것(메모리에 기록).
