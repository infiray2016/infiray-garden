# 기술 스택

> pickzzk 의 기술 선택 + 이유 + 사용 패턴.

## 프런트엔드

### Vue 3 — `<script setup>` Composition API

- Composition API only. **Options API 금지** (R 룰).
- `<script setup>` SFC 형식 (Single File Component).
- composable 으로 로직 추출 (`use*.js`).

**왜 Vue 3?**
- legacy draftpick 이 Vue 였어서 마이그 비용 ↓
- Composition API = composable 재사용성 좋음
- 한 화면 = 1 SFC, 상태는 composable 로 빠짐

### Tailwind 4

- `@import "tailwindcss"` (Tailwind v4 신 import)
- **`tailwind.config.js` 없음** — design token 은 CSS variables (`--color-bg` 등) 로
- v10 톤은 CSS variables 박음 (참조: [[90_AI/프로젝트/pickzzk/위키/v10-톤\|v10-톤]])

**왜 Tailwind 4?**
- utility-first → 빠른 prototyping
- v4 의 CSS-first config = JS 빌드 의존 감소
- 한국어 폰트 (`Pretendard`) 와 영문 (`JetBrains Mono`) CSS variable 로 박음

### 폰트

| 용도 | 폰트 | 변수 |
|---|---|---|
| 한글 본문 | Pretendard | `var(--font-sans)` |
| 영문 / 모노 / 라벨 | JetBrains Mono | `var(--font-mono)` |

## 백엔드 / 데이터

### Firebase — `draftpick-63456` 프로젝트 공유

legacy draftpick 과 **같은 프로젝트** 사용 (재이용).

| 서비스 | 용도 |
|---|---|
| Firestore | tournaments / streamers / mockResults / scrimDays / scrimSubmissions 등 | 
| Realtime DB (RTDB) | `rooms/*` (멀티 모드) + scrim 집계 (legacy) |
| Auth | super admin / sub admin (역할 기반) |

**왜 Firebase?**
- legacy 와 공유 → 마이그 비용 ↓
- onSnapshot = real-time UI (모의 결과 누적, 멀티 룸 등)
- RTDB = 빠른 update 자주 일어나는 데이터 (입찰 등)
- Admin SDK = 서버 사이드 (rules 우회) — `/api/scrim-*` 엔드포인트

자세히는 [[90_AI/프로젝트/pickzzk/위키/데이터-모델\|데이터-모델]] (예정).

### Claude API — fetch 직접 호출

- **SDK 안 씀** (`@anthropic-ai/sdk` 의존 X)
- `fetch` 로 직접 호출 (`/api/scrim-parse` 등 서버 엔드포인트)
- prompt 는 한국어 자연어 ([[90_AI/claude/개념/메모리\|메모리]] `ai_prompt_conventions`)

**왜 SDK 안 씀?**
- 클라이언트 측 API key 노출 X (서버 endpoint 만)
- SDK 사용 시 unnecessary 의존
- fetch 단순 + 가벼움

### 치지직 비공식 API

- 채널 정보 fetch
- 정책 변경 모니터링 필요
- 공식 권한 X — 비공식

## 런타임 / 빌드

### Bun

- 런타임 + 패키지 매니저 + 테스트 러너
- `bun run dev` / `bun run build` / `bun run lint` / `bun run regression` / `bun run verify`

**왜 Bun?**
- 빠름 (npm 대비 install / build / test 3-5x)
- 단일 binary (Node + npm + vite 통합)
- `--bun` flag = native Bun runtime (Node 호환 모드 X)

> [!warning] Build 시 Node 이슈 가능
> `bun run build` 가 Node 모드 fallback 가능. `bun --bun run build` 로 native 강제.

### Vite

- Bun 안에서 Vite 빌드
- HMR (개발 시)
- Plugin: `@vitejs/plugin-vue` + Tailwind 4 plugin

### Vitest

- 단위 테스트 (`tests/unit/*.test.js`)
- jsdom 환경
- `bun run regression` = 회귀 (전체 vitest)

### Playwright MCP

- 브라우저 검증 (mobile 375 / tablet 768 / desktop 1440 matrix)
- 1440 screenshot + console 0/0 가 verify 룰

## 디렉토리 컨벤션

```
src/
├── components/<feature>/*.vue        ← 컴포넌트 (PascalCase.vue)
├── views/*.vue                       ← 라우터 view
├── composables/use*.js               ← 로직 (camelCase.js)
├── utils/*.js                        ← 순수 함수
├── data/*.json                       ← fixture / mock
├── router.js                         ← Vue Router
├── firebase.js                       ← Firebase 초기화
└── styles/                           ← CSS variables / global
```

자세히는 [[90_AI/프로젝트/pickzzk/위키/구조\|구조]] (예정).

## 명명 규칙

- 컴포넌트: `PascalCase.vue` (예: `MockAuctionBoard.vue`)
- 로직 / utils: `camelCase.js`
- composable: `use<Name>.js` (예: `useMockAuctionState.js`)
- 라우터 view: `<Name>View.vue` (예: `HomeView.vue`)
- 스킬: `.claude/skills/<kebab-case>/SKILL.md`
