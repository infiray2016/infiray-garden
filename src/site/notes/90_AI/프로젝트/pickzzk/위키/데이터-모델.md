# 데이터 모델

> pickzzk 의 Firestore / RTDB 스키마. v2 박힌 후 합의된 모델 (2026-05-08 lock).

## 두 DB 분리 이유

| DB | 특성 | pickzzk 용도 |
|---|---|---|
| **Firestore** | document-oriented / 강한 인덱스 / 큰 쿼리 | 토너먼트 / 스트리머 / 결과 누적 |
| **RTDB (Realtime DB)** | tree / 빠른 update / 작은 payload | 멀티 룸 / 실시간 입찰 |

→ 한 프로젝트 (`draftpick-63456`) 안에서 둘 다 사용.

## Firestore 컬렉션

## Realtime DB (RTDB)

### `rooms/{code}` (snake multi — legacy)

```
rooms/ABCDE
├── status: "lobby" | "drafting" | "done"
├── hostId: clientId
├── captainOrder: [N, N, N, N]
├── timeLimit: 0 | 30 | 60 | 90
├── members/{clientId}
│   ├── captainIndex: N (-1 = 관전자)
│   ├── nickname: string
│   ├── disconnected: bool
│   ├── heartbeat: ms
│   └── visible: bool
├── currentTurn
│   ├── pickIndex: N (0-based)
│   ├── teamPos: N
│   ├── deadline: ms | null
│   └── startedAt: ms
└── picks/{idx}
    ├── playerName: string
    ├── teamId: N
    ├── auto: bool
    ├── by: clientId
    └── at: ms
```

### `rooms/auction-{code}` (auction multi — R20 박힘)

```
rooms/auction-ABCDE
├── hostId: clientId
├── status: "lobby" | "auctioning" | "coach-selection" | "done"
├── seed: number                          # PRNG seed (deterministic shuffle)
├── tournamentSnapshot: { ... }           # tournament 박힘
├── auctionRule: {                        # 셋업 룰 박힘
│   budgetPerTeam, bidUnit, lotDurationSec, antiSnipeExtendSec
├── teamClaims/{teamIdx}: clientId        # 자리 claim
├── teamBudgets/{teamIdx}: number         # host 가 lobby 에서 박은 팀별 시작 pt
├── members/{clientId}
│   ├── nickname: string
│   ├── teamIdx?: N
│   ├── disconnected: bool
│   ├── heartbeat: ms
│   └── visible: bool
├── currentLot
│   ├── idx: N
│   ├── kind: "PLAYER" | "COACH"
│   ├── subjectId: string
│   ├── subjectName: string
│   ├── position: string
│   ├── deadline: ms
│   ├── currentBid: { teamIdx, amount, at } | null
│   ├── extendedCount: N (antiSnipe 연장 횟수)
│   ├── startedAt: ms
│   └── isRelist: bool
├── history/{idx}                         # append-only
│   ├── kind, subjectId, subjectName, position
│   ├── teamIdx, soldPrice
│   ├── reason: "sold" | "relist-N" | "random-after-max-relist" | "discarded-no-slot" | "auto-position"
│   ├── passed: bool
│   └── at: ms
├── relistQueue/{lotId}: N (count)        # 재경매 횟수 (max 2)
├── coachSelection                        # remaining-points 시
│   ├── order: [teamIdx, ...]
│   ├── pos: N
│   ├── assigned/{teamIdx}: { coachId, coachName, at }
│   └── startedAt: ms
└── endedAt: ms
```

## 보안 룰 요약

### Firestore (`firestore.rules`)

- `tournaments/{id}` — admin 만 write, public read
- `streamers/{id}` — admin 만 write, public read
- `mockResults/{id}` — public write (v2 강제 + size cap), public read
- `scrimDays/{date}/games/{id}` — admin 만 write, public read (collectionGroup)
- `admins/{uid}` — super-admin 만 write, 본인 read

### RTDB (`rooms/*`)

```json
{
  "rules": {
    "rooms": {
      ".read": true,
      "$code": { ".write": true }
    }
  }
}
```

→ rooms 외에는 `.write: false`. Admin SDK 가 rules 우회 → server endpoint 가 박음.

자세히는 `docs/firebase-rules.md`.

> [!warning] `rooms/auction-*` 배포 필요
> R20 박힌 auction multi 는 `rooms/auction-{code}` 경로 사용. legacy `rooms/$code` rule 이 cover 하지만 Firebase console deploy 필요.

## v1 → v2 마이그 메모

| v1 (legacy) | v2 (pickzzk) |
|---|---|
| `coachMode: "separate" / "captain" / ...` | `coachAssignment.mode: "none" / ...` |
| `rule: "auction-coach"` 만 | `rule` (legacy 호환) + `pickRule` + `pickAuthority` 축별 |
| 4 stage (closed / open / drafting / done) | 6 stage (pre-launch / pre-open / mock / scrim / final / archived) |
| 4 팀 고정 | `teamCount` 가변 |
| 단일 결과 doc | `mockResults` 누적 + resultType 분기 |

자세히는 `.claude/STAGE_OVERLAP_DESIGN.md`.

## 헷갈리는 점

> [!warning] `rule` 과 `pickRule` 둘 다 박힘
> legacy 호환 위해 둘 다 박음. `rule = pickRule + "-" + pickAuthority`. 새 코드는 axes (`pickRule`, `pickAuthority`) 우선.

> [!warning] `coachMode` 와 `coachAssignment.mode` 둘 다 박힘
> legacy `coachMode` (`separate` / `captain` / `lottery` / `auctioned`) ↔ v2 `coachAssignment.mode` (`none` / `auction-lot` / `lottery` / `remaining-points`).

> [!warning] mockResults v1 / v2 둘 다 read 가능
> 새 write 는 v2 강제 (`validateMockResultV2`). 옛 v1 read 만 (`inferResultType` 으로 snake default).

> [!warning] RTDB 의 `rooms/$code` rule = 모든 코드
> `auction-ABCDE` 도 매치. 별도 룰 필요 X. 단 Firebase console 에 actually deploy 됐는지 확인.
