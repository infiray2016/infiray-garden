## 컴포넌트 패턴

### 1) 라우터 view (1 = 1 페이지)

`src/views/*.vue` — 라우팅 진입점. props 받지 X (route param 만).

### 2) Feature 컴포넌트 (`src/components/<feature>/`)

페이지 안의 UI 묶음. props in / emit out.

예: `src/components/mock/`
```
MockEntryShell.vue
MockAuctionBoard.vue
MockAuctionHouse.vue          ← 매물 카드
MockAuctionTeamCards.vue
MockAuctionHistory.vue
MockAuctionCoachSelection.vue
MockAuctionLobby.vue          ← multi 룸 lobby
MockAuctionSandbox.vue        ← 자유 픽
MockLobby.vue                 ← snake multi lobby
MockBottomBar.vue
MockNicknameField.vue
MockPickerOrderEditor.vue
MockSetupStrip.vue
MockModePicker.vue
MockRoomEntry.vue
```

### 3) Composable (`src/composables/use*.js`)

상태 + 로직 캡슐. Vue reactive 사용. SFC 에서 import.

규칙:
- `use<Name>` 함수
- props 받음 (필요 시)
- ref / computed / watch 사용
- `onMounted` / `onUnmounted` 안 cleanup
- module-level 싱글톤 (한 세션 = 한 인스턴스) 또는 instance per call

### 4) Utils (`src/utils/*.js`)

순수 함수 (no Vue reactive). 테스트 친화.

예: `auctionEngine.js`
```js
export function makePrng(seed) { ... }
export function shuffleInPlace(arr, rand) { ... }
export function buildTeams(tournament, formation, overrides) { ... }
export function buildQueue(tournament, formation, rand) { ... }
```

## 헷갈리는 점

> [!warning] components / views 분리
> - **views** = 라우팅 진입점 (1 = 1 페이지)
> - **components** = view 안의 UI 묶음 (재사용 / 분리)

> [!warning] composable / utils 분리
> - **composable** = Vue reactive (ref / computed / watch / onMounted)
> - **utils** = 순수 함수 (no Vue)
> - utils 는 unit test 쉬움. composable 은 jsdom 필요.

> [!warning] admin views 별도 묶음
> `views/admin/` 안. router path `/admin/*`. 권한 = `useAdminGate` composable.
