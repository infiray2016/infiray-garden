# 게임 업로드 (운영자)

> 운영자가 OCR 결과 직접 업로드. 시청자 제보 우회 — **즉시 반영** (큐 안 거침). [[90_AI/프로젝트/pickzzk/위키/페이지/시청자-제보\|90_AI/프로젝트/pickzzk/위키/페이지/시청자-제보]] 와 같은 OCR 인프라 재사용.

## URL / 뷰

- URL: `/admin/scrim/upload`
- View: `src/views/admin/ScrimUploadView.vue` (또는 admin views/)
- 권한: admin only

## 흐름

```
1. /admin/scrim/upload 진입
   ↓
2. 결과창 / 전적 캡처 업로드
   ↓
3. /api/scrim-parse (Claude Vision) parse
   ↓
4. 운영자가 confirm / 정정 (chip click + alias 학습)
   ↓
5. 직접 박음 → scrimDays/{date}/games/ 에 add
   ↓
6. 활성 홈 / 스크림 DAY 즉시 표시 (onSnapshot)
```

- `useBanRecognition()` — 픽밴 ONNX (공유)

- `useAdminGate()` — 권한 체크

## API

`POST /api/scrim-admin`:
```json
{
  "secret": "$SCRIM_ADMIN_SECRET",
  "action": "addGame",
  "tournamentId": "hojong-cup-5",
  "date": "2026-07-08",
  "kind": "official-scrim",
  "game": { teams, score, picks, bans, kda, mvp, ... },
  "source": "admin"
}
```

→ Admin SDK 가 rules 우회. RTDB / Firestore 직접 write.

자세히는 `docs/firebase-rules.md`.

## 헷갈리는 점

> [!warning] 즉시 반영 = 큐 X
> 운영자 업로드는 audit 박는 거 아닌 즉시 scrimDays/ 박힘. 시청자 제보는 큐 거침.

> [!warning] OCR 인프라 공유
> game-input/ 컴포넌트는 둘 (시청자 / 운영자) 가 같이 사용. props 로 분기 (admin / submit).

> [!warning] kind 운영자가 명시 박음
> 시청자 제보는 stage 보고 추정 (pre-open/mock → inhouse). 운영자는 명시 박음 (정확).
