# 모의 드래프트

> 스네이크 드래프트 시뮬 페이지. solo (manual) / multi (방 기반). [[90_AI/프로젝트/pickzzk/위키/페이지/모의-경매\|모의-경매]] 와 같은 진입 패턴.

## URL / 뷰

- URL: `/mock/draft`
- View: `src/views/MockDraftView.vue`
- 권한: 공개

## 모드

```
manual (수동 4 감독/팀장 직접)
multi (방 기반 — useSnakeMultiRoom RTDB)
```

> [!info] sandbox sub-mode 는 auction 만
> 드래프트는 sub-mode 분기 없음. 룰 = `pickRule='snake'` 박힌 그대로.

## 진행 흐름

1. **MockEntryShell** — 모드 / 닉네임 / 픽 순서 박음
2. **MockLobby** (multi 시) — 자리 claim / time limit / 시작
3. **MockDraftBoard** — 진행 화면

## 픽 순서 (snake)

```
1R: 1, 2, 3, 4 (셋업 순서 또는 사용자 박힌 순서)
2R: 4, 3, 2, 1 (역)
3R: 1, 2, 3, 4 (정)
...
```

- 1R 순서는 셋업에서 picker order 박힘 (`MockPickerOrderEditor.vue`)
- 자세히는 [[90_AI/프로젝트/pickzzk/위키/셋업-룰\|셋업-룰]] / `snakeOrder.js`

## time limit (multi)

- 0 (제한 없음) / 30s / 60s / 90s
- deadline 만료 시 effective host 가 AI 픽 자동 (legacy multi-room pattern)

## composable

- `useMockDraftState(tournament)` — solo / multi 공통 엔진 (TBD — solo + multi 통합인지 별개인지 코드 확인)
- `useSnakeMultiRoom()` — multi 룸 인프라 (legacy, 잘 박힘)
- `useSnakeMultiDraftState()` — multi 상태 (legacy)

## RTDB 스키마 (snake multi)

```
rooms/{code}           # auction 과 다름 (prefix X)
├── status: 'lobby' | 'drafting' | 'done'
├── hostId: clientId
├── captainOrder: [N, N, N, N]
├── timeLimit: 0 | 30 | 60 | 90
├── members/{clientId}
│   ├── captainIndex (N, -1 = 관전자)
│   ├── nickname, disconnected, heartbeat, visible
├── currentTurn
│   ├── pickIndex (0-based)
│   ├── teamPos
│   ├── deadline, startedAt
└── picks/{idx}
    ├── playerName, teamId, auto, by, at
```

자세히는 [[90_AI/프로젝트/pickzzk/위키/데이터-모델\|데이터-모델]].

## 5 trap pattern

[[90_AI/claude/개념/하네스\|하네스]] reference:
- `watch(isEffectiveHost)` writeCurrentTurn guard
- `lastTriggeredPickIndex` + 5s 재시도
- `visibilitychange` `_resyncSeq` 추적
- `Math.ceil((deadline - now) / 1000)` + clamp
- autoPickWorker FIRE abort 시 `console.warn`

자세히는 `docs/legacy-skills/multi-room.md`.

## 결과 저장

`mockResults/{id}`:
- `resultType: 'snake'`
- `picks[]` — round / pickNum / playerId / teamIdx / isCaptain
- `pickerOrder` — 1R 순서

자세히는 [[90_AI/프로젝트/pickzzk/위키/데이터-모델\|데이터-모델]].

## 활성 홈 활용

drafts 누적 → `usePlayerRatings.computeAggregates(results)`:
- snake / sandbox picks 통합 aggregate (auction-sim 별개)
- player 별 pickedCount / pickRate / avgPickRound / avgPickIdx

활성 홈 의 Stage1 매물 평가 / 픽 순서 에 사용 (R20 C12 / R21 누적).

## 헷갈리는 점

> [!warning] auction 과 별개 view
> /mock/auction (경매) ≠ /mock/draft (드래프트). 진입 URL 분리.

> [!warning] snake multi room = legacy 패턴
> R20 C14 이전에 박힌 legacy 패턴. RTDB schema `rooms/{code}` (prefix X). auction 은 `rooms/auction-{code}` (prefix 있음).

> [!warning] sandbox sub-mode 없음
> draft 는 turn-based / time-limit 기반. auction 의 sandbox 같은 자유 픽 모드 X.

> [!warning] picker order = 셋업에서 박힘
> 1R 순서 = `tournament.pickerOrder` 또는 `tournament.captainOrder`. setup 단계에서 운영자가 박음.
