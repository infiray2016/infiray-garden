# 사용법

> pickzzk 로컬 개발 / 빌드 / 배포 / 시청자 사용 / 운영자 사용 가이드.

## 로컬 개발

### 사전 준비

- **Bun 설치** ([bun.sh](https://bun.sh))
- Firebase project 접근 (legacy 와 공유: `draftpick-63456`)
- (옵션) `ANTHROPIC_API_KEY` (AI 기능 시)

### 환경 변수

`.env` (또는 `.env.local`) 박음:

```bash
# Firebase 클라이언트
VITE_FIREBASE_API_KEY=...
VITE_FIREBASE_AUTH_DOMAIN=draftpick-63456.firebaseapp.com
VITE_FIREBASE_PROJECT_ID=draftpick-63456
VITE_FIREBASE_STORAGE_BUCKET=draftpick-63456.appspot.com
VITE_FIREBASE_MESSAGING_SENDER_ID=...
VITE_FIREBASE_APP_ID=...
VITE_FIREBASE_DATABASE_URL=https://draftpick-63456-default-rtdb.firebaseio.com

# 서버 사이드 (API endpoint 작업 시만)
ANTHROPIC_API_KEY=...
SCRIM_ADMIN_SECRET=...
FIREBASE_SERVICE_ACCOUNT='{ ... }'
FIREBASE_DATABASE_URL=...
```

> [!warning] `.env` 박을 때 주의
> git 절대 commit 금지 (`.gitignore` 박혀 있음). Vercel env 박을 때만 노출.

### 개발 서버

```bash
bun run dev               # http://localhost:5173
```

### Dev 모드 fixture (Firebase 없이)

URL 파라미터로 fixture 강제:

```
http://localhost:5173/?stage=mock      # 모의 단계 fixture
http://localhost:5173/?stage=scrim     # 스크림 단계
http://localhost:5173/?stage=final     # 본선
http://localhost:5173/?stage=archived  # 아카이브
http://localhost:5173/?stage=mock&seedDemo=1  # mockResults demo seed (R21 C5)
```

`?seedDemo=1` 추가 시 sessionStorage 에 demo mock 결과 자동 박음 → MockSimulatorCard dense block 시각 확인 가능.

## 검증 (R1 룰)

```bash
bun run lint              # Prettier check + design grep + stylelint
bun run regression        # vitest 전체
bun run build             # production build
bun run verify            # 위 3 개 동시
```

> [!info] `bun run verify` 가 표준
> 코드 변경 후 항상 `verify`. console error/warn 0 + Playwright 3 viewport (375/768/1440) 확인.

### Build 안 될 때

```bash
bun --bun run build       # native Bun runtime 강제 (Node fallback 회피)
```

## Firebase rules 배포

> [!warning] RTDB rules deploy 필요 (R20 박힘)
> `rooms/auction-*` 경로는 user 가 Firebase console 에서 deploy. Claude 못 함.

```
Firebase Console → Realtime Database → 규칙 → docs/firebase-rules.md 의 룰 박음
```

Firestore rules:
```bash
firebase deploy --only firestore:rules     # firestore.rules deploy
firebase deploy --only firestore:indexes   # firestore.indexes.json deploy
```

## 시청자 사용

### 활성 홈

1. `https://pickzzk.app/` 진입 (또는 dev: `localhost:5173/`)
2. 현재 단계에 맞는 카드 봄 (timeline / mock / scrim / final 등)
3. TimelineHero 의 메인 CTA 박힘 (stage 별 다름)

### 게임 결과 제보

1. 좌측 nav `경기 제보 (SUBMIT)` 클릭
2. 결과창 / 전적 스크린샷 업로드
3. AI 가 챔프 / KDA / 결과 parse — 확인 / 정정
4. 제출 → 운영자 승인 큐 진입

### 모의 시뮬

1. 좌측 nav `모의 (SIM)` 클릭 (또는 활성 홈 의 CTA)
2. 모드 선택:
   - **방 기반** = 친구랑 / AI 와 (혼자도 가능)
   - **수동** = 4 감독 모두 직접 (snake) / sandbox (auction sub-mode)
3. 룰 / 닉네임 박음
4. 시뮬 진행

자세히는 [[90_AI/프로젝트/pickzzk/위키/기능/모의-시뮬\|모의-시뮬]] (예정).

### 아카이브

1. 좌측 nav `아카이브 (ARCHIVE)` 클릭
2. 시즌별 결과 모아 보기

## 운영자 사용

### 권한 받기

1. Firebase Auth super-admin 이 `admins/{uid}` 박음
2. `roles[]` 에 권한 추가 (예: `'tournament-admin'` / `'scrim-admin'`)
3. 운영자가 로그인 → sidebar 의 `ADMIN · SUPER` 묶음 노출

### 토너먼트 셋업

1. `/admin/setup` 진입
2. 대회 기본 박음 (name / season / dates)
3. 셋업 룰 박음 ([[90_AI/프로젝트/pickzzk/위키/셋업-룰\|셋업-룰]])
4. 출전 명단 cherry-pick (`/admin/streamers` 에서 박은 마스터 풀)
5. 셋업 완료 → `pre-launch` → `pre-open` advance

### 스트리머 DB 관리

1. `/admin/streamers` 진입
2. 새 스트리머 추가 / 채널 매핑 / 롤 / OW ID 박음
3. 시즌 거듭하며 누적

### 스크림 일정 박음

1. `/admin/schedule` 진입
2. 공식 매치 사전 등록

### 시청자 제보 승인

1. `/admin/submissions` 큐
2. 2 명 합의 / 자가 합의 방지 룰 (`screen-admin-submissions/SKILL.md`)
3. 승인 → `scrimDays/.../games/` promote

## 운영 cadence

> 95%+ 시간 CLOSED.

- **활성 시기 = 대회 1주 전 ~ 종료**:
  - pre-open → mock → scrim → final
  - cron / 자동 폴링 ON
  - 운영자 + 시청자 활발
- **CLOSED 시기 = 대회 종료 ~ 다음 대회**:
  - stage='archived' 또는 'pre-launch'
  - cron OFF (비용 0 지향)
  - 활성 홈 = CLOSED 안내 페이지

## 트러블슈팅

### "Firebase permission_denied"

- RTDB rules 미배포 (`rooms/auction-*` 경로)
- `firebase deploy --only firestore:rules` 안 한 후
- admin 권한 없는 user 가 admin write 시도
- `useAdminGate` 가 redirect 안 함 (코드 버그)

### "console.warn '[multi finalize abort]'"

- multi auction 의 5 trap pattern 발동 (의도된 abort)
- effective host 가 백그라운드 / 권한 X 일 때 발생
- 정상 (silent 안 함 — 디버깅 가시화)

### "kind=undefined / D-NaN"

- timelineEvents 에 다음 milestone at 없음
- fixture 갱신 필요 ([[90_AI/프로젝트/pickzzk/위키/데이터-모델\|데이터-모델]] timelineEvents 참조)

### "Dev 서버에서 mockResults 안 보임"

- Firebase 연결 상태인데 컬렉션 비어있음
- `?seedDemo=1` 로 demo seed (R21 C5)

### "한글 폰트 깨짐"

- Pretendard 폰트 로드 실패
- `style.css` 의 `@font-face` 확인
- 네트워크 / CDN 이슈

| Production | 연결 | Firebase 만 |
| Preview (Vercel) | 연결 | Firebase 만 |
