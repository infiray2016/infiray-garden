# 테스트 검증 체계

> pickzzk 의 회귀 테스트 / 검증 layer 정리. 자동 (unit / smoke / Playwright) + 반자동 (mock-test-runner subagent) + 수동 (브라우저 viewport matrix).

## Layer

| Layer | 도구 | 무엇 | 빈도 |
|---|---|---|---|
| Unit | vitest | composable / util pure logic | 매 commit (`bun run regression`) |
| Smoke | Playwright | dev server 기반 E2E (8 시나리오) | release (`bun run mock:smoke`) |
| Multi smoke | Playwright | RTDB 기반 2-tab multi | release (`bun run mock:smoke:multi`) |
| **mock-test-runner** | subagent (Playwright + MCP) | 실데이터 기반 매트릭스 4 시나리오 + viewport 3 종 | 큰 회귀 의심 시 + push 전 |
| 수동 브라우저 | 직접 | 디자인 톤 + PWA + 모바일 UX | UI 변경 후 |

## 자동 — Unit (vitest)

`tests/unit/*.test.js` — 375 tests (2026-05-17 기준).

대표:
- `auction-engine.test.js` — buildTeams / buildQueue / eligibleTeamIdxsForLot / MAX_RELIST
- `mock-auction-state.test.js` — 솔로 엔진 phase + 유찰 + coach-selection
- `auction-multi-state.test.js` — multi 엔진 finalize/advance + relistQueue
- `use-tournament-setup.test.js` — 셋업 4 케이스 (감독제 snake/auction × captain 4 mode)
- `auction-rule.test.js` — 4 필드 default + normalize + validate

명령: `bun run regression` (=`vitest run`)

## 자동 — Playwright smoke

### Default smoke (5180 dev server 자동 기동, 57 시나리오)

`bun run mock:smoke` → `tests/smoke/mock-simulator.spec.js` + `home-mobile.spec.js` 등. P0 + P1 케이스.

### Multi smoke (RTDB 필요)

`bun run mock:smoke:multi` → `mock-simulator-multi.spec.js`. Firebase RTDB rules 박혀야 동작. 2-client 시나리오.

## 반자동 — mock-test-runner subagent

`Agent({ subagent_type: 'mock-test-runner' })`. 실데이터 기반, RTDB inject 우회 X, 4 시나리오 매트릭스 + viewport 3 종.

### 매트릭스

| 시나리오 | 모드 | 핵심 검증 |
|---|---|---|
| A | draft solo (manual) | 16+픽 / 4팀 × 5R / result dialog |
| B | auction solo (manual auction-sim) | 16 매물 / 4팀 5/5 / auto-position 발동 |
| C | draft multi (host + 2 guests + 1 AI) | RTDB sync / done status / 닉네임 표시 |
| D | auction multi (host + guest 2명) | host start / late-join / leave broadcast / auto-position / 결과 dialog 양 tab 동기 |
| E | viewport 3 종 (375/768/1440) | overflow / 디자인 톤 / 모바일 UX |

### 가드 (BLOCKER 발견 시 즉시 보고)

- placeholder `?` / `감독 —` / 100pt 자동 차감 (1000→900)
- console error 0
- silent abort (`[multi FIRE abort]` 등 warn 3+ 발생)
- 사용자 의도 verbatim 위반 (auto-position spec, 막판 뱃지 자체 X 등)

### 호출 패턴

```ts
Agent({
  subagent_type: 'mock-test-runner',
  description: '회귀 검증',
  prompt: `검증 대상 commit / 시나리오 매트릭스 / 검증 가드 ...`
})
```

자세히는 `.claude/agents/mock-test-runner.md`.

## 회귀 의심 trap (multi-room.md 5 trap + 2026-05-17 추가)

멀티 방 (RTDB 기반 실시간 동기) 에서 반복적으로 잡혀온 함정. 새 multi 작업 시 항상 점검.

| Trap | 내용 | 검증 방법 |
|---|---|---|
| #1 effective host (실호스트) 교체 race | 호스트가 끊겨서 다른 client 가 effective host 로 승격될 때, `writeCurrentTurn` 가드 없으면 deadline 이 무한 reset 됨 | unit / 2-tab |
| #2 silent abort (조용한 실패) | `lastTriggeredPickIndex` 같은 idx 가드를 영구 차단으로 박으면 진행 멈춤 — 5초 후 재시도 허용 필요 | console warn 확인 |
| #3 visibility resync race (탭 visible 복귀 시 동기 race) | 백그라운드에서 visible 복귀 시 여러 resync 가 동시에 발동되어 충돌 — `_resyncSeq` 가드 필요 | manual hidden→visible 전환 |
| #4 clock skew (시계 차이) | client 별 시계가 어긋날 때 deadline 음수 가능 — `Math.ceil` + `[0, timeLimit]` clamp | unit |
| #5 silent abort 로그 누락 | abort 시 `console.warn` 필수 — 디버깅 시 silent 면 추적 X | console 확인 |
| **#6 background tab timer throttling** (2026-05-17 추가) | Chromium 이 background tab 의 `setInterval` 을 5분 idle 후 1/분 으로 throttle → deadline 시각에 정확한 `setTimeout` + visible 복귀 시 즉시 finalize 시도 | manual background 전환 |
