# 멀티 드래프트 (snake)

> snake 모드의 RTDB 멀티. **legacy DraftPick 의 안정 패턴** 그대로 이식 — 다듬어진 5 trap pattern 의 reference.

## 구조

```
src/composables/
├── useSnakeMultiRoom.js          ← 룸 인프라 (legacy)
└── useSnakeMultiDraftState.js    ← 엔진 (legacy)

src/components/mock/
├── MockEntryShell.vue            ← snake / auction 공유 진입
├── MockLobby.vue                 ← snake multi lobby
└── (snake board — 위치 TBD)
```

## RTDB 스키마

```
rooms/{code}            # auction-{code} 와 다름 — prefix 없음 (legacy)
├── status: "lobby" | "drafting" | "done"
├── hostId: clientId
├── captainOrder: [N, N, N, N]    # 1R 순서 (3, 1, 2, 0 등)
├── timeLimit: 0 | 30 | 60 | 90
├── pickerBaseOrder: [N, ...]     # snake 시 1R 순서 (rejoiner 동기화)
├── members/{clientId}
│   ├── captainIndex: N (-1 = 관전자)
│   ├── nickname, disconnected, heartbeat, visible
├── currentTurn
│   ├── pickIndex: N (0-based)
│   ├── teamPos: N (0..teamCount-1)
│   ├── deadline: ms | null
│   └── startedAt: ms
└── picks/{idx}
    ├── playerName, teamId, auto, by, at
```

## 핵심 원칙 (multi-room.md)

### 1) 서버 권한 마감 시각

> Firebase `rooms/{code}/currentTurn.deadline` 이 단일 source. 모든 client 가 같은 절대 시각 (`Date.now()` 기준) 으로 카운트다운.

- 로컬 타이머 worker 안 씀
- 클라이언트는 deadline 표시만, 결정은 effective host

### 2) 협력적 AI 픽 trigger

> 모든 foreground client 가 300 ms 주기로 `isCurrentTurnUnavailable()` / `deadlinePassed` 검사. 단 **Effective Host 한 명만** transaction 으로 AI 픽 실행.

- 다른 client 는 관측만
- 비활성 (백그라운드) 시 host 갈음 안 함 — visibility 기반 분리

### 3) 트랜잭션 원자성

> `multiPickPlayer` = `runTransaction` 기반. `picks/{idx}` 에 이미 값 있으면 abort. 동시 픽 경쟁 시 1 개만 commit.

### 4) Heartbeat + Visibility presence

- `heartbeat` 3s 주기 갱신
- `isMemberAlive` = `disconnected` false + heartbeat 12s 이내
- `visible === false` 멤버 (백그라운드) 는 heartbeat stale skip — Chrome throttling 방지

### 5) Effective Host

- `aliveForegroundIds` 알파벳 첫 번째 = effective host
- 전원 백그라운드면 `alive` 중 첫 번째
- AI 픽 trigger / writeCurrentTurn 등 = effective host 만

### 6) `beforeunload` + onDisconnect

- 탭 닫기 시 즉시 `disconnected: true` 박음 (백업)
- Firebase `onDisconnect.remove()` — 연결 끊기면 자동
- 12s heartbeat timeout 안 기다림 → 빠른 host 인계

## 5 trap pattern (재발 버그)

### 1. `watch(isEffectiveHost)` writeCurrentTurn guard

```js
watch(isEffectiveHost, (amI) => {
  if (!amI) return
  const existing = roomCurrentTurn.value
  if (existing && existing.pickIndex === currentPickIndex.value) return  // 필수
  writeCurrentTurn(...)
})
```

→ guard 없으면 창 간 전환 시마다 effective host flip → writeCurrentTurn → deadline 이 `Date.now() + 30s` 로 계속 리셋 → AI 픽 무한 연장.

### 2. `lastTriggeredPickIndex` 영구 차단 금지

`maybeScheduleAutoPick` 은 `TRIGGER_RETRY_MS` (5s) 기반 재시도:

```js
if (lastTriggeredPickIndex === pickIdx && Date.now() - lastTriggeredAt < 5000) return
```

→ 영구 차단 시 `getAiPick` null / transaction 실패 / `selectedTeam` 일시 null 등으로 silent abort 시 영영 멈춤.

### 3. `visibilitychange` 재동기화 순서 추적

```js
const mySeq = ++_resyncSeq
const snap = await get(...)
if (mySeq !== _resyncSeq) return         // 더 새 호출 시작됨
if (snap.picks.length < current.picks.length) return  // stale
roomData.value = snap.val()
```

→ `_resyncSeq` 없으면 창 간 빠른 전환 시 promise resolve 순서 뒤집혀 오래된 snapshot 이 최신 덮어쓰기 → 픽 사라지고 타이머 리셋.

### 4. `Math.ceil` 기반 timeLeft clock skew

```js
const secs = Math.ceil((deadline - now) / 1000)
return Math.max(0, Math.min(timeLimit.value, secs))  // clamp 필수
```

→ effective host `Date.now()` 와 reader `now.value` 사이 1~100 ms 차로 `ceil(30.05) = 31` 표시 가능. clamp 로 timeLimit 상한 보정.

### 5. autoPickWorker FIRE 핸들러 abort 시 silent 금지

`console.warn('[multi FIRE abort]', ...)` 로 사유 기록. 재발 시 콘솔로 즉시 원인 파악 (not effective host / no team / getAiPick null / transaction uncommitted).

## auction multi 와 차이

[[90_AI/프로젝트/pickzzk/위키/기능/멀티-경매\|멀티-경매]] 와 비교:

| 영역 | snake (legacy) | auction (R20 박힘) |
|---|---|---|
| RTDB path | `rooms/{code}` | `rooms/auction-{code}` |
| turn 모델 | turn-based | timer + 자유 입찰 |
| 트랜잭션 | `multiPickPlayer` (picks/{idx}) | `placeBid` (currentLot.currentBid + antiSnipe) |
| AI trigger | turn 전환 시 | lot 변경 / bid 갱신 시 (jittered) |
| time limit | 0/30/60/90s | lotDurationSec (per lot) + antiSnipe |

- (legacy DraftPick) — 여러 세션 거치며 5 trap 박힘

## 헷갈리는 점

> [!warning] snake / auction RTDB path 분리
> snake = `rooms/{code}`, auction = `rooms/auction-{code}`. 둘 다 같은 RTDB rules 의 `rooms/$code` 매치하지만 prefix 로 분리.

> [!warning] turn-based ≠ 자유 입찰
> snake = 한 명씩 차례. auction = 4 시청자 동시. 메커니즘 완전히 다름.

> [!warning] 5 trap pattern = legacy 출처
> 자세히는 `docs/legacy-skills/multi-room.md`. pickzzk auction multi 도 같은 pattern 적용.

> [!warning] effective host 단일 trigger
> 모든 client trigger 시 race / 중복. effective host 만 박음.
