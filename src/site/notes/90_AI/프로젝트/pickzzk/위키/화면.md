# 화면

> pickzzk 의 모든 view 정리. URL / 누구 / 단계 / 컴포넌트 / 행동.

## 한 눈에

```
시청자 화면 (4 + 1):
  /                           ← 활성 홈 (stage 별 분기)
  /scrim/submit               ← 경기 결과 제보
  /scrim/day/:date            ← 스크림 DAY (read-only)
  /scrim/games/:gameId        ← 게임 detail (read-only)
  /archive/:tournamentId      ← 시즌 아카이브
  /mock/draft                 ← 모의 드래프트
  /mock/auction               ← 모의 경매

운영자 화면 (5):
  /admin/setup                ← 운영자 셋업
  /admin/schedule             ← 공식 스크림 일정
  /admin/scrim/day/:date?     ← 스크림 DAY 편집 (운영자)
  /admin/scrim/upload         ← 게임 결과 업로드
  /admin/streamers            ← 스트리머 DB 관리
  /admin/submissions          ← 시청자 제보 큐
```

## 시청자 화면

### 1) `/` — 활성 홈 (HomeView)

> 시청자 진입점. tournament.stage 따라 카드 매핑.

**stage 별 분기:**

| stage | 표시 |
|---|---|
| `pre-launch` | [[90_AI/프로젝트/pickzzk/위키/페이지/CLOSED\|CLOSED]] 안내 페이지 (정적) |
| `pre-open` | TimelineHero + InhouseResult |
| `mock` | TimelineHero + MockSimulator + InhouseResult |
| `scrim` | TimelineHero + ScrimSchedule + OfficialScrim + UnofficialScrim |
| `final` | TimelineHero + FinalResult + FinalBracket |
| `archived` | [[../아카이브/\|../아카이브/]] 페이지 별도 |

**메인에서 빠진 것** (user verbatim 2026-05-09):
- `ScrimSubmit` (게임 결과 OCR 제보) → 좌측 메뉴 / sidebar nav 에만
- LIVE 매치 카드 → 폐기 (실시간 매치 추적 X — 스크린샷 OCR 기반)

**도메인 룰:**
- 내전 = `pre-open + mock` 단계만 (`kind='inhouse'`). user verbatim: "내전은 모의까지임"
- Mock = `mock` 단계만. "이미 팀은 뽑혔으니까 메인에 둘 만큼 큰 가치 X"
- 스크림 일정 + 공식 + 비공식 = `scrim` 단계만. "스크림 일정은 스크림상태에만"
- 비공식 스크림 = "팀이 정해진 후 정해진 일정 외의 스크림"
- 본선 결과 + Bracket = `final` 단계만

**컴포넌트:**
- `components/active-home/TimelineHero.vue` — 4 step (사전 내전 / 모의 / 스크림 / 본선) + D-day + stage CTA
- `components/active-home/cards/MockSimulatorCard.vue` — 모의 진입 + 누적 통계 dense
- `components/active-home/cards/MockMarketCard.vue` — **mock 단계 매물 평가 surface (R21 C8 신설)**. usePlayerRatings v2 산출 (시뮬 5+ 누적 시 실 rating, 미만 시 placeholder). auction 룰 = `Stage1RatingsAuction` 임베드, snake = `Stage1RatingsSnake` 임베드.
- `components/active-home/cards/InhouseResultCard.vue` — 내전 인사이트
- `components/active-home/cards/ScrimScheduleCard.vue` — 공식 일정
- `components/active-home/cards/ScrimResultCard.vue` — 공식 / 비공식 / 본선 결과 thin
- `components/active-home/cards/FinalBracketCard.vue` — 본선 대진표

**잔여 (Stage1 sub embedded):**
- `components/active-home/Stage1RatingsAuction.vue` — auction grid (MockMarketCard 가 임베드)
- `components/active-home/Stage1RatingsSnake.vue` — snake ranking + R 컷 (MockMarketCard 가 임베드)
- `components/active-home/MvpInline.vue` / `TimelineHero.vue` — 단독 사용

**삭제됨 (R20 C6 마이그 후 dead → R21 C8/C11 정리, 24 종):**

- Stage2/Stage3 sub 17 종: `ActiveHomeStage2/3` + `Stage2*` 8 종 + `Stage3*` 7 종 (R21 C11)

자세히는 [[기능/활성-홈\|기능/활성-홈]] (예정).

### 2) `/scrim/submit` — 시청자 제보 (ScrimSubmitView)

> 게임 결과 OCR 스크린샷 제보. pre-launch 후 모든 단계 가능. 집계는 stage 별 분리.

**흐름:**
1. 결과창 / 전적 페이지 캡쳐 업로드
2. `/api/scrim-parse` (Claude Vision) 가 챔프 / KDA / 결과 parse
3. 사용자가 confirm / 정정
4. `scrimSubmissions/` 컬렉션에 박힘
5. 운영자가 [[/admin/submissions\|/admin/submissions]] 큐에서 승인 → `scrimDays/.../games/` promote

**용도 = stage 별:**
- pre-open / mock → `kind='inhouse'` (내전)
- scrim → `kind='official-scrim'` 또는 `'unofficial-scrim'`
- final → `kind='final'`

자세히는 [[90_AI/프로젝트/pickzzk/위키/기능/시청자-제보\|90_AI/프로젝트/pickzzk/위키/기능/시청자-제보]] / [[90_AI/프로젝트/pickzzk/위키/기능/OCR\|OCR]] (예정).

## 운영자 화면

> 모두 `useAdminGate` (Firebase Auth + roles[] 체크) 필요. 권한 부족 시 redirect.

### 8) `/admin/setup` — 운영자 셋업 (admin/SetupView)

> 토너먼트 새로 박거나 / 활성 토너먼트 룰 변경.

**박는 것:**
1. 대회 기본 (name / season / startsAt / endsAt)
2. 셋업 룰 ([[90_AI/프로젝트/pickzzk/위키/셋업-룰\|셋업-룰]]) — pickRule / pickAuthority / coachAssignment / captainRule / auctionRule / teamCount / picksPerTeam
3. 출전 명단 (streamersDB 에서 cherry-pick)
4. 셋업 완료 → stage advance

자세히는 [[90_AI/프로젝트/pickzzk/위키/페이지/운영자-셋업\|운영자-셋업]] (예정).

### 9) `/admin/schedule` — 공식 스크림 일정

> 운영자가 공식 스크림 매치 사전 등록. `scrimScheduled/{id}` 박힘.

### 10) `/admin/scrim/day/:date?` — 스크림 DAY 편집

> 운영자가 특정 date 의 게임 결과 / 메타 편집.

**components:** `components/admin/scrim-day/`

### 11) `/admin/scrim/upload` — 게임 결과 업로드

> OCR 직접 업로드 (시청자 제보 우회). `components/game-input/` 재사용.

### 12) `/admin/streamers` — 스트리머 DB 관리

> 마스터 컬렉션 (`streamers/{id}`) 관리. 채널 / 롤 / OW ID 통합.

자세히는 [[90_AI/프로젝트/pickzzk/위키/기능/streamerDB\|streamerDB]] (예정).

### 13) `/admin/submissions` — 시청자 제보 큐

## 시청자 nav (좌측 sidebar)

```
VIEWER
├── 홈 (HOME)               → /
├── 경기 제보 (SUBMIT)      → /scrim/submit
├── 모의 (SIM)              → /mock/auction
└── 아카이브 (ARCHIVE)      → /archive/:id (가장 최근 archived)
```

**모바일 (375)** = sidebar 숨김. bottom-nav 4 개 (HOME / SUBMIT / SIM / ARCHIVE) 예정 (R21 후속).

## 운영자 nav (좌측 sidebar — admin 권한 시)

```
ADMIN · SUPER
├── 셋업                   → /admin/setup
├── + 게임 업로드          → /admin/scrim/upload
├── DAY 편집               → /admin/scrim/day
├── 제보 큐                → /admin/submissions
└── 스트리머 DB            → /admin/streamers
```

## 헷갈리는 점

> [!warning] sidebar 의 SUBMIT = 시청자 입장
> 시청자도 게임 결과 제보 가능 (운영자 승인 필요). 운영자 전용 X.

> [!warning] /admin/scrim/upload vs /scrim/submit
> - **/admin/scrim/upload** = 운영자가 OCR 결과 직접 박음 (즉시 반영)
> - **/scrim/submit** = 시청자가 박음 → 큐 → 운영자 승인

> [!warning] stage='archived' = 활성 홈 안 보임
> 아카이브 페이지 별도. 활성 홈은 active stage 4 종 (pre-open / mock / scrim / final) 만.

> [!warning] DevStageBar 는 fixture 만
> 실제 활성 tournament 안 바꿈. dev / demo 용.
