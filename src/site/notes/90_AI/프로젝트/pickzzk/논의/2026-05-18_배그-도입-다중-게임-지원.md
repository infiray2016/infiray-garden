# 배그 도입 + 다중 게임 지원 미리 고민

> 픽지직은 처음부터 롤 (호종컵) 기준으로 박혀 있는데, 미르다요 (인디 스트리머) 가 2026-05-31 에 본인 이름 박은 첫 배그 대회를 연다는 정보가 트리거. 픽지직이 배그도 지원할 수 있나 / 어떻게 박아야 하나 미리 정리. 실제 개발 여부 + 범위는 아직 박지 않음.

## 배경

미르다요 대회는 경매제로 들어가는데, 픽지직의 모의 경매가 미르다요 대회 준비에 의미 있을 수 있는 정보. 다만 미르다요 대회 정확한 spec (팀 수 / 매치 형식 / 결과 점수 룰 / 포지션 슬롯 정의 등) 은 아직 공개 X. 인챈트 가 2024-02 에 박은 자낳대 배그는 추첨제라 픽지직 모의 시뮬과 정합 X — 다 같은 배그 대회라도 형식이 다 다름.

user 가 박은 미리 고민 항목 (verbatim):
- "다른게임 대회는 어떤 형식으로 가야 할지 모르겠네"
- "모의 경매나 드래프트는 작동 했으면 하는데"
- "내전 단계나 이후 단계가 좀 애매 하네"
- "경기결과 조회도 롤이랑은 달라서"
- "셋업이랑 단계도 게임에 따라 달라야 할거 같아서"

이 논의는 코드 변경 0. 박힌 정보 정리 + 옵션 + 미해결 질문 박아두기만. 미르다요 대회 spec 공개 또는 운영 결과 본 후에 결정 박을 자료로.

## 영역별 영향도

게임 본질 차이를 픽지직 영역에 매핑.

### 롤 vs 배그 본질 차이

| 축 | 롤 | 배그 |
|---|---|---|
| 한 게임 단위 | 두 팀 5:5 매치. 승/패 결정 | 16-25 팀 동시 매치. chicken dinner = 1위 |
| 시리즈 / 시즌 | Bo3 / Bo5 시리즈 + 본선 토너먼트 (bracket) | 다수 매치 누적 점수 leaderboard |
| 픽밴 / 챔피언 | 픽밴 페이즈 있음. 게임 핵심 흥미 | 없음 (캐릭터는 외형) |
| 매치 결과 | winner + 10명 KDA + gold + damage + 픽밴 | 16팀 placement + 팀당 4명 kills + 생존 시간 |

### 픽지직 영역별 분류

| 영역 | 영향 | 변경 비용 |
|---|---|---|
| 셋업 (팀 편성 4 룰) | 추상화 가능 — 게임별 팀 크기 + 포지션 슬롯만 다르게 박음 | 중간 |
| 모의 드래프트/경매 | 거의 그대로 살림 — 포지션을 롤 5종에서 배그 4 슬롯 (또는 역할) 으로 | 작음 |
| 내전 / 스크림 단계 | 모델 다시 박아야 — 한 매치에 N 팀 동시. 현재 game = {teamA, teamB} 가정과 안 맞음 | 큼 |
| 본선 / Bracket | 배그는 bracket 없음 — 점수 누적 leaderboard. UI 자체 다시 | 큼 |
| OCR (결과창) | 결과창 ROI / 데이터 항목 / tolerance 룰 처음부터 새로 | 큼 |
| 픽밴 ONNX 자동 인식 | 배그엔 픽밴 자체 없음. 기능 비활성 | 영향 0 |
| 시청자 제보 합의 (R22 server consensus) | gamesMatch tolerance 룰을 게임별 분기 (배그는 placement / kills / 생존시간 비교) | 중간 |
| 지표 (스트리머 DB, 활성 홈 카드) | 셀이 게임별로 완전 다름. 롤 = 챔프별 승률, 배그 = chicken dinner 횟수 / 평균 placement | 큼 |

## 박힐 가능성 있는 결정 후보 9 개

미르다요 대회 spec 보고 정정될 가능성 있음. 지금은 후보.

### 1. schema 분기 (한 컬렉션 + `gameKind` 필드)

배경: 게임 추가할 때 컬렉션 자체 새로 박을지 (`tournaments_lol` + `tournaments_pubg`) 한 컬렉션에 게임 종목 필드 박을지 결정.

선택 후보: 한 컬렉션 + 도큐 안의 `gameKind: 'lol' | 'pubg'` 필드로 분기. 활성 홈 / 셋업 hub / 모의 같은 game-agnostic 화면이 한 쿼리로 처리 가능. 새 게임 (옵치 등) 추가 시 gameKind 값만 추가.

철회 조건: 두 게임의 도큐 shape 가 호환 불가능할 정도로 다르거나 (예: 도큐 크기가 Firestore 1MB 제한 넘김), 게임별 권한 룰이 완전히 달라서 분리해야 할 때.

### 2. 한 시점 한 게임 운영

배경: 같은 시점에 롤 시즌 + 배그 시즌 동시 운영 가능한지 결정.

선택 후보: 같은 시점에 활성 시즌 1개만. 다음 시즌으로 넘어갈 때 게임 전환 가능 (롤 → 배그 → 옵치). schema 자체는 game-agnostic 박혀 있어서 전환 가능, 하지만 같은 시점에는 한 게임만 활성.

철회 조건: 운영 규모 커져서 동시 다 시즌 운영이 매출/시청자 측면에서 의미 있어질 때. 지금 user 가 박은 운영 부담 (개인 시청자 트래커) 으로는 권장 X.

### 3. 메뉴 / 라우트 / 화면 게임별 분기 가능

배경: schema 분기 박으면 화면 분기도 가능한지.

선택 후보: 활성 시즌의 `gameKind` 보고 좌측 메뉴 / 라우트 / 카드 매핑 통째로 다르게 렌더. 같은 도메인 안에서 두 게임 사이트가 사실상 따로 사는 것처럼.

예 (개략):
- 롤 시즌이 활성 → 좌측 메뉴 = 홈 / 셋업 / 모의 / 스트리머 DB / 스크림 DAY / 시리즈 / 픽밴 자동 인식 / 시청자 제보 / 지표
- 배그 시즌이 활성 → 좌측 메뉴 = 홈 / 셋업 / 모의 경매 / 스트리머 DB / 매치데이 / 시즌 leaderboard / 시청자 제보 / 지표
- 픽밴 자동 인식 메뉴는 배그 시즌에선 사라짐. 매치데이 / 시즌 leaderboard 는 롤 시즌에선 사라짐.

### 4. 첫 배그 도입 = 경매제 + 스쿼드 모드 (16팀 64명) 만 지원

배경: 미르다요 대회 = 경매제. 자낳대 = 추첨제. 다른 모드 (듀오/솔로) 도 가능.

선택 후보: 첫 도입은 경매제 + 스쿼드 (4인) 모드 한 가지만. 추첨제 / 듀오 / 솔로 는 후순위. 미르다요 대회가 곧 운영되니 그 spec 정합으로 박음.

철회 조건: 미르다요 대회가 실제로는 추첨 / 자유 픽 다른 형식이거나, 인디 스트리머 대회의 주류 형식이 추첨으로 박히면 추첨제도 같이 박는 게 정합.

### 5. 4 룰 axes (snake/auction × coach/captain) 자체는 game-agnostic 유지

배경: 픽지직 v2 의 핵심 axes 가 게임 무관 박힐 수 있는지.

선택 후보: 4 룰 axes 는 game-agnostic. 픽 룰 자체 (스네이크 / 경매 / 감독제 / 팀장제) 는 게임 따라 의미가 같음. coachAssignment.mode 4종 (none / auction-lot / lottery / remaining-points) 도 그대로 살림.

철회 조건: 배그 인디 대회에서 4 룰 외의 새 픽 형식이 주류로 박히면 axes 자체 확장. 예: 추첨제가 주류면 pickRule axis 에 'lottery' 추가.

### 6. 팀 크기 / 포지션 슬롯 / 팀 수 = 게임별 분기 (tournament.rule 필드)

배경: 게임별로 본질적으로 다른 셋업 spec.

선택 후보: `tournament.rule` 안에 `teamSize` (롤=5, 배그=4) / `positionSlots` (롤=Top/Jungle/Mid/ADC/Support, 배그=A/B/C/D 또는 IGL/Fragger/Sniper/Support) / `teamCount` (롤=4, 배그=16) 필드 박음. 게임 선택 시 default 자동.

철회 조건: 같은 게임 안에서도 대회별로 다양한 spec 박혀야 하면 (예: 롤 4팀이 아닌 8팀 대회) tournament 단위 자유 입력 박힘.

### 7. stage 6 종 game-agnostic 유지 + 내부 흐름만 게임별 분기

배경: stage 자체 (pre-launch / pre-open / mock / scrim / final / archived) 6 종이 두 게임에 다 적용 가능한지.

선택 후보: stage 6 종 외부 frame 은 그대로. 내부 흐름 (scrim / final 단계 안의 매치 모델, 카드 매핑) 만 게임별 분기. 활성 홈의 카드 매트릭스가 stage + gameKind 둘 다 보고 결정.

예:
- 롤 scrim → InhouseResult / OfficialScrimResult / UnofficialScrimResult 카드
- 배그 scrim → MatchDayResult / SeasonLeaderboard 카드
- 롤 final → FinalBracket / FinalResult 카드
- 배그 final → 최종 SeasonLeaderboard / 최종 매치데이 결과

철회 조건: 배그 운영해보고 stage 6 종 frame 자체가 안 맞으면 (예: scrim / final 통합 — 매치데이가 형식 같음) 게임별 stage 자체 분기 검토.

### 8. 배그 포지션 슬롯 정의는 미정 (미르다요 대회 spec 보고 결정)

배경: 배그는 게임 자체가 포지션 강제 X. 셋업 hub 에서 슬롯 정의를 어떻게 박을지.

후보:
- A) 단순 4 슬롯 (A/B/C/D 또는 P1/P2/P3/P4)
- B) 역할 슬롯 (IGL / Fragger / Sniper / Support — 모의 경매에서 역할별 가치 차이 의미 있음)
- C) 운영자가 슬롯 정의 직접 박음 (텍스트 자유 입력)

선택 보류: 미르다요 대회가 역할 강제하면 B, 자유 픽이면 A, 운영자 자유면 C. 대회 spec 보고 결정.

### 9. 개발 시작 시점 결정 미루기

배경: 실제 개발 진입할지 / 언제 진입할지.

선택 후보: 미르다요 대회 (2026-05-31) 운영 결과 본 후 결정. user 가 박은 "실제로 개발을 할지 말지는 아직 정해지지 않았고 범위도 아직 안정해짐" 정합.

철회 조건: 미르다요 대회 직전 (~1-2주 전) 에 user 가 트래커 운영 의지 박히면 즉시 개발 진입. 다만 그 시점에 mockup 박을 시간 충분한지 별도 확인.

## 미해결 질문

미르다요 대회 또는 추가 정보 수집 시점에 답 박을 자료.

1. **미르다요 대회 정확한 spec** — 팀 수 / 매치 형식 (며칠 / 몇 매치) / 우승 결정 룰 (chicken dinner 횟수 / 누적 점수) / 포지션 슬롯 정의 / 출전선수 64명 박힌 명단
2. **배그 결과창 OCR 룰** — 결과 화면의 ROI 위치 / placement / kills / 생존 시간 / 손해 등 항목 추출 룰 / tolerance (R22 의 gamesMatch 같은 합의 판정 룰)
3. **배그 시즌 점수 룰** — 매치당 점수 (placement 점수 + kills 점수) / 누적 방식 / 우승 결정 / 동률 처리
4. **김블루 배린이 챔피언스 spec** — 다른 인디 대회 형식 참고
5. **치지직 치스티벌 배그 spec** — 또 다른 형식 참고
6. **호종컵 5기 (또는 그 이후) 배그 시즌 가능성** — 호종컵 이 배그로 확장될지, 별도 시즌인지
7. **시청자 ★ 평가 시스템 (deferred)** — 배그 도입 시 같이 박힐지, 별도 결정
