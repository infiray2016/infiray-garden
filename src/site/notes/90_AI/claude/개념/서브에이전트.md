# 서브에이전트 (Subagent)

> 메인 [[90_AI/claude/개념/에이전트\|에이전트]] 가 **Task tool 로 호출하는 격리된 에이전트**. 컨텍스트 분리 + 병렬 처리 + 보호 용도. 결과만 메인으로 돌아옴.

## 한 줄 정의

**메인 에이전트가 "이 작업은 별개로 해" 하고 떨어뜨려 보내는 자식 에이전트.** 호출 prompt 만 받고 시작, 결과 text 만 돌려줌. 부모 대화는 안 봄.

## 왜 쓰나?

3 가지 목적:

1. **컨텍스트 보호** — 긴 탐색 / 큰 파일 읽기 결과가 메인 대화에 쌓이지 않음. compact 위험 줄임
2. **격리** — 서브 작업이 의도 외 부수효과 (잘못된 가정 누적) 안 함
3. **병렬** — 독립적인 여러 탐색 동시 실행 (e.g. "이 5 군데 grep 결과 정리")

## 호출 방식

```
Agent tool 호출:
  description: 짧은 설명 (한 줄)
  subagent_type: general-purpose | explore | plan | ...
  prompt: 자체 완결된 task 명세
```

> [!info] prompt 는 자체 완결적
> 서브에이전트는 부모 대화 못 봄. 그래서 prompt 에 다음을 다 박아야:
> - 무엇을 (task)
> - 왜 (motivation / context)
> - 무엇을 해봤는지 (이미 시도한 거)
> - 어떤 형식 결과 원하는지 (보고 길이 / 형식)

## 서브에이전트 종류 (Claude Code)

| 타입 | 도구 | 용도 |
|---|---|---|
| `general-purpose` | 모든 도구 | 일반 자율 작업 (search / 구현 / 검증) |
| `Explore` | Read 위주 | 빠른 코드 탐색 (수정 X) |
| `Plan` | Read 위주 | 설계 plan 작성 (코드 X) |
| 전문 (`code-reviewer` 등) | 도구 제한 | 특화 작업 (리뷰 / 보안 / 성능 등) |

(전문 에이전트는 plugin / project 별로 추가 가능)

## 메인 vs 서브 비교

| 구분 | 메인 에이전트 | 서브에이전트 |
|---|---|---|
| 컨텍스트 | 대화 전체 | 호출 prompt 만 |
| 부모 대화 봄? | 자기가 부모 | 못 봄 |
| 결과 | user 에게 직접 | text → 메인으로 |
| 호출 비용 | 누적 | 호출 단위 (독립) |
| 병렬 가능? | 메인은 1 개 | 여러 개 동시 |
| 도구 | 권한대로 다 | 타입별 제한 |

## 좋은 사용 예

- "이 코드베이스에서 `xxx` 관련 파일 다 찾아줘 + 의존 정리" → `Explore`
- "C14c 의 race + timer 통합 plan MD 박아줘" → `Plan` 또는 `general-purpose`
- "이 5 곳 (a/b/c/d/e) 병렬로 보고 + 각 결과 50 단어로" → 5 개 동시 `Explore`
- "C++ 빌드 에러 자율 해결" → `cpp-build-resolver`
- "리뷰 + 보안 점검" → `code-reviewer` + `security-reviewer` 병렬

## 나쁜 사용 예

- "사용자 질문에 직접 답해" → 메인에서 해야 함 (서브는 답해도 결과만 text 로)
- "10 줄 코드 박아줘" → 굳이 분리할 필요 X (메인이 더 빠름)
- "대화 컨텍스트 알아야 하는 작업" → 서브는 부모 대화 못 봄

## 헷갈리는 점

> [!warning] 결과 = text 만
> 서브에이전트가 코드 박았어도 그 결과는 메인 에이전트의 "tool result" 로 들어옴. 사용자는 안 봄. **메인이 결과 받아서 user 에게 다시 전달해야** 함.

> [!warning] prompt 가 길면 효과 반감
> 컨텍스트 보호 목적이라면 prompt 도 짧게. 너무 길면 메인 대화도 그만큼 사용.

> [!warning] 신뢰 ≠ 검증
> 서브에이전트가 "다 박았어요" 라고 답해도 메인이 직접 git diff / build 검증해야 함 (R1 변경 후 verify).

> [!warning] 병렬 호출 = 1 message 안에 multiple tool calls
> 순차 호출 하면 병렬 X. 한 message 안에 여러 Agent 도구 호출이 진짜 병렬.

## 비용 / 컨텍스트 효과

- 서브에이전트 1 회 호출 = 새 시작점부터 토큰 소비
- 메인은 결과 text 만 받음 → 메인 컨텍스트는 적게 늘어남
- 큰 grep / 큰 파일 읽기 / 긴 plan = 서브에이전트 이득
- 작은 작업은 오히려 메인이 효율

## 실전 패턴 (pickzzk)

- **AS-IS 탐색** = `Explore` 자율 호출 (R4 룰)
- **큰 plan** = `Plan` (`.claude/R20_C14d_PLAN.md` 같은 거)
- **병렬 검색** = "이 5 군데 grep" 한 message 5 호출
- **리뷰** = code-reviewer 호출 (Codex 와는 다름 — Codex 는 external reviewer)
