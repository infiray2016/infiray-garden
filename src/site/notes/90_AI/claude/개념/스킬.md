# 스킬 (Skill)

> **특정 작업 영역의 고밀도 가이드 markdown**. `.claude/skills/<name>/SKILL.md` 또는 `~/.claude/skills/<name>/SKILL.md` 에 박힘. 사용자 입력이 키워드에 매치하면 자동으로 [[90_AI/claude/개념/에이전트\|에이전트]] 컨텍스트에 박힘. 슬래시 (`/<skill>`) 로 명시 호출도 가능.

## 한 줄 정의

**"이 작업 할 때는 이런 패턴으로 박아" 라고 알려주는 도메인 매뉴얼.** [[90_AI/claude/개념/하네스\|하네스]] 가 모든 작업에 적용된다면, 스킬은 작업 영역별 한정.

## 구조

```
.claude/skills/<name>/
├── SKILL.md           ← 본문 (자동 invoke 시 컨텍스트에 박힘)
└── (추가 reference 파일 — references/, examples/ 등)
```

`SKILL.md` 의 YAML frontmatter:

```yaml
---
name: feature-mock-simulator
description: 모의 시뮬 (snake/auction) 작업 시 invoke. user가 "mock", "시뮬", "auction", "snake draft" 언급하면 매치.
---
```

> [!info] description 이 자동 invoke 결정
> Claude 는 `description` 의 keyword 를 사용자 입력과 매치. 잘 박힌 description = 자동 invoke 정확도 ↑

## SKILL.md 본문 패턴 (pickzzk)

```markdown
# <스킬명>

작업 전 `<관련 문서>` 와 `<설계 문서>` 를 먼저 읽는다.

핵심 (도메인 룰 / 박은 결정):
- 가장 헷갈리는 룰
- user verbatim 박은 fact
- 사용 시점

진입 전 체크 (반드시):
1. AS-IS 확인 (R4)
2. 현 상태 (코드 위치 / 현재 약점)

워크플로우:
- Step 0: 도메인 fact 확인
- Step 1: plan MD 박기
- Step 2: 결정 받기 (한 번에 하나)
- Step 3: 구현
- Step 4: 검증 (R1 lint + regression + build)

Done 정의:
- [ ] 체크리스트
```

## 스킬 종류 (스코프 기준)

| 종류 | 위치 | 적용 범위 |
|---|---|---|
| 프로젝트 스킬 | `.claude/skills/<name>/` | 해당 프로젝트만 |
| 글로벌 스킬 | `~/.claude/skills/<name>/` | 모든 프로젝트 |
| 플러그인 스킬 | plugin 내장 | 플러그인 활성 시 |

pickzzk 는 14 개 프로젝트 스킬 (`feature-mock-simulator`, `screen-active-home`, `feature-multi-rtdb`, `screen-admin-setup`, ...) — `CLAUDE.md` 의 routing 표 참조.

## 자동 invoke 조건

1. 사용자 입력에 `description` 의 keyword 매치
2. 매치 시 Claude 가 자동으로 `Skill` 도구 호출 → SKILL.md 가 컨텍스트에 박힘
3. 매치 안 되면 명시 호출 (`/<skill-name>`)

## 스킬 vs 슬래시 커맨드

| 구분 | 스킬 | 슬래시 커맨드 |
|---|---|---|
| 정의 | markdown 가이드 | 명시 invoke 트리거 |
| 호출 | 자동 (description 매치) 또는 슬래시 | 슬래시 (`/<name>`) |
| 본질 | 컨텍스트 박는 도구 | 호출 메커니즘 |
| 관계 | 스킬 = 대상 / 슬래시 = 호출 방법 |

> [!info] 슬래시 = 스킬 또는 built-in
> `/help` / `/clear` 같은 built-in 슬래시도 있고, 스킬을 invoke 하는 슬래시도 있음. 자세히는 [[90_AI/claude/개념/슬래시-커맨드\|슬래시-커맨드]].

## 스킬 vs 하네스

| 구분 | 스킬 | 하네스 |
|---|---|---|
| 적용 | 작업 영역별 | 항상 |
| 위치 | `.claude/skills/<name>/SKILL.md` | `CLAUDE.md` + `.claude/HARNESS.md` |
| invoke | description 매치 또는 슬래시 | 세션 시작 시 자동 |
| 깊이 | 도메인 깊게 | 룰 짧게 (R1~R22) |

## 헷갈리는 점

> [!warning] 자동 invoke ≠ 매번 박힘
> description 이 매치 안 되면 컨텍스트에 안 박힘. 키워드 박을 때 신중.

> [!warning] 1 작업 = 여러 스킬 가능
> "활성 홈" + "Stage 1" 키워드 매치 시 `screen-active-home` + `feature-mock-simulator` 둘 다 invoke 될 수 있음. 충돌 없게 작성.

> [!warning] 스킬은 컨텍스트 비용 있음
> SKILL.md 가 길면 한 번 invoke 마다 토큰 소비. 핵심만 박고 detail 은 reference 파일로 link.

> [!warning] 글로벌 vs 프로젝트
> 글로벌 (`~/.claude/skills/`) 은 모든 프로젝트에 박혀서 의도 외 invoke 가능. 프로젝트 한정이 안전.

## 만들 때 워크플로

1. **반복 작업 영역 식별** — 같은 도메인 (모의 시뮬 / 운영자 셋업 / 스크림 등) 반복 시 스킬 후보
2. **description 박기** — keyword 정확히 (e.g. "mock", "auction-sim", "시뮬")
3. **본문 = 도메인 룰 + 워크플로** — code 가 아닌 룰
4. **R22 시점** — 신규 기능 만들 때 SKILL.md 부터 박음 (구현 시작 전)
5. **메모리와 연동** — 박힌 결정 / verbatim 룰을 스킬에 반영
