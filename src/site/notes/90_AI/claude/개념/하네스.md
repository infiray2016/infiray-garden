# 하네스 (Harness)

> Claude Code 가 **반복적인 실수를 안 하도록 박아둔 룰 체계**. 일종의 안전벨트. 매 세션 시작 시 자동으로 읽혀서 작업 흐름을 제약함.

## 한 줄 정의

**프로젝트 안의 `CLAUDE.md` + `.claude/HARNESS.md` + `.claude/BOOTSTRAP.md` + 훅 / 스킬 / 메모리 가 한 묶음으로 동작하는 시스템.** Claude 가 "이 룰을 지키며 작업한다" 는 컨텍스트를 자동으로 잡아주는 역할.

## 왜 필요한가?

LLM 의 본질적 약점:
- **컨텍스트 망각** — 긴 세션에서 초반에 박힌 룰을 후반에 어김
- **반복 실수** — 같은 버그 / 같은 안 좋은 패턴을 다른 세션에서 또 함
- **추측 — 도메인 룰 모를 때 그럴듯한 추측으로 박음** (R8 verbatim 어김)
- **검증 누락** — 코드 박고 verify 안 돌리고 끝남
- **컨텍스트 부족** — 외부 시스템 (Firebase 규칙 / OCR 룰 / 자낳대 룰 등) 모를 때 직접 코드부터 박음

하네스는 이 약점들을 룰로 박아 매 세션 시작 시 자동 환기시킴.

## 구성 (pickzzk 기준)

```
프로젝트 루트/
├── CLAUDE.md                  ← 제품 비전 / 스택 / 도메인 룰 / 우선순위
├── AGENTS.md                  ← Codex 리뷰어 contract (Claude 는 구현자, Codex 는 리뷰어)
└── .claude/
    ├── BOOTSTRAP.md           ← 세션 시작 시 핵심 룰 짧게 (5~30줄)
    ├── HARNESS.md             ← R1~R22 (반복 실수 방지) 자세히
    ├── HARNESS_APPENDIX.md    ← 부록 (긴 디테일은 여기)
    ├── settings.json          ← 권한 / 자동 승인 / 모델 설정
    ├── CODEX_REVIEW.md        ← Codex 리뷰 큐 (open item)
    ├── BROWSER_TESTING.md     ← Playwright matrix 안내
    ├── REGRESSION.md          ← 회귀 체크리스트
    ├── hooks/                 ← SessionStart / PostToolUse / Stop 스크립트
    └── skills/<name>/SKILL.md ← 14 종 (자동 invoke)
```

> [!info] Source of truth 순서
> 1. `CLAUDE.md` — 제품 컨텍스트
> 2. `.claude/HARNESS.md` — R1~R22 룰
> 3. `.claude/skills/*/SKILL.md` — 도메인별 고밀도 스킬
> 4. `docs/skills/*.md` — 프로젝트 도메인 스킬
> 5. `docs/legacy-skills/*.md` — legacy 이식 / OCR / scrim / multi 작업 전 필수

## R1~R22 룰 — 무엇을 지키나? (pickzzk 패턴)

22 개 룰 모두 `반복적으로 박은 실수` 에서 거꾸로 도출된 거. 대표 :

| 룰 | 핵심 |
|---|---|
| R1 | 변경 후 lint + regression + build 실행 |
| R4 | 큰 작업 전 AS-IS 분석 먼저 |
| R5 | 의미 없는 데이터 user 노출 X (`kind=inhouse` 같은 raw enum 등) |
| R7 | v10 톤 임의로 바꾸지 않음 |
| R8 | user verbatim 박은 fact 정정 받으면 즉시 수용 |
| R10 | 스코프 늘리지 않음 (요청 외 리팩토링 X) |
| R11 | 7 단계 워크플로 (skill 정독 → AS-IS → 설계 → MD plan → 결정 → 구현 → verify) |
| R12 | 신규 화면 설계 먼저 (MD plan / mockup) |
| R13 | 모호한 룰 = 추측 X, 옵션 제시 |
| R14 | 큰 작업 진입 전 `/checkpoint` |
| R15 | docs 동기 (CHANGELOG / README / RETRO / TODOS) |
| R22 | 신규 기능 시 `.claude/skills/<name>/SKILL.md` 작성 (구현 시작 전) |

자세히는 [[../프로젝트/pickzzk/위키/하네스-R-룰\|../프로젝트/pickzzk/위키/하네스-R-룰]] (TODO — 프로젝트별 정리).

## 자동 invoke 메커니즘

세션 시작 시 (SessionStart 훅 / compact 후) 다음이 컨텍스트에 박힘:
- `CLAUDE.md` 전체
- `.claude/BOOTSTRAP.md` 핵심 룰
- 최근 commit 메시지
- git status

작업 중 자동 invoke:
- 사용자 입력에 keyword 매치 시 → 해당 [[90_AI/claude/개념/스킬\|스킬]] auto-invoke
- 파일 편집 후 → PostToolUse 훅 → lint / 검증 안내
- 세션 종료 시 → Stop 훅 → 최종 build verify

## 헷갈리는 점 (자주 헷갈림)

> [!warning] 하네스 ≠ 에이전트
> - **하네스** = 룰 체계 (markdown 문서들)
> - [[90_AI/claude/개념/에이전트\|에이전트]] = 룰을 따르는 실행 주체 (Claude LLM)
> - 하네스가 에이전트의 안전벨트 역할

> [!warning] 하네스 ≠ 스킬
> - **하네스** = 모든 작업에 항상 적용되는 룰 (R1~R22)
> - [[90_AI/claude/개념/스킬\|스킬]] = 특정 작업 영역만 위한 고밀도 가이드 (자동 invoke)
> - 둘 다 markdown 문서. 차이는 적용 범위.

> [!warning] BOOTSTRAP vs HARNESS
> - **BOOTSTRAP.md** = 세션 시작 시 짧게 읽히는 핵심 룰만 (5~30줄)
> - **HARNESS.md** = R1~R22 자세한 설명 (필요시 펼침)
> - 짧게 박힌 BOOTSTRAP 이 사실상 매번 활성, HARNESS 는 reference

> [!warning] AGENTS.md vs CLAUDE.md
> - **CLAUDE.md** = Claude Code (이 도구) 가 읽음
> - **AGENTS.md** = Codex 등 다른 에이전트가 읽음 (리뷰어 contract)
> - pickzzk 는 Claude = 구현자 / Codex = 리뷰어 분리

## 만들 때 워크플로

1. **R 룰 출처는 항상 "박은 실수"** — 가상의 best practice 박지 말고 실제 박힌 실수로부터 룰 추출.
2. **반복 시 = 룰**. 1 번 박힌 실수는 우연, 2 번 박히면 룰화.
3. **메모리 시스템과 연동** — `~/.claude/projects/.../memory/` 의 `feedback_*.md` 가 종종 R 룰로 승격됨.
4. **`/checkpoint` 발동** — 큰 룰 변경 전 항상 체크포인트.
