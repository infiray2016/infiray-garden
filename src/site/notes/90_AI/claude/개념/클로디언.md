# 클로디언 (Claudian)

> **Claude Code를 옵시디언 사이드바에 넣는 커뮤니티 플러그인.** 터미널 없이 볼트 안에서 에이전트를 굴린다.
> 저장소 `YishenTu/claudian` · MIT · ★15,088 · 플러그인 ID `realclaudian`

이 볼트에 **2.2.5 설치·활성화 완료 (2026-09-01)**. 적용하려면 옵시디언을 한 번 재시작해야 한다.

## 무엇인가

볼트 자체가 에이전트의 작업 디렉터리가 된다. 파일 읽기·쓰기·검색·bash 실행·다단계 작업을 사이드바 채팅으로 시킨다.
Claude Code 말고도 Codex · Grok Build · OpenCode · Pi 를 붙일 수 있다.

레지스트리에 포크가 여럿 있다(`claudian-plus`, `oh-my-claudian`, `claudian-scheduler`, `ai-scheduler`, `claudian-mobile`). **원본은 `realclaudian`** 하나다.

## 설정

| 항목 | 값 |
|---|---|
| Claude CLI 경로 | `/Users/hikaru/.local/bin/claude` → `~/.local/share/claude/versions/2.1.238` |
| node | `/Users/hikaru/.nvm/versions/node/v22.23.1/bin/node` (v22.23.1) |
| 최소 앱 버전 | 1.13.0 (설치된 앱 1.13.7 ✅) |
| 데스크톱 전용 | `isDesktopOnly: true` — 모바일에선 안 뜬다 |

자동 탐지가 실패하면 **설정 → Claudian → Advanced → Claude CLI path**에 위 경로를 직접 넣는다.
nvm을 쓰므로 node 경로를 못 찾으면 **설정 → Environment → Custom variables**에 `PATH`를 보태준다.

## 사용법

### 켜기

좌측 리본의 Claudian 아이콘 → 오른쪽에 채팅 패널이 열린다.
커맨드 팔레트(`Cmd+P`)에 등록되는 명령은 **6개뿐**이다 (플러그인 번들에서 확인).

| 명령 | 하는 일 |
|---|---|
| `Open chat view` | 채팅 패널 열기 |
| `Inline edit` | 선택한 텍스트를 그 자리에서 고치기 |
| `New` | 새 탭 |
| `Replace current conversation` | 현재 대화 갈아엎기 |
| `Close current tab` | 탭 닫기 |
| `Copy startup diagnostics` | 안 붙을 때 진단 정보 복사 |

`Inline edit` 에는 기본 단축키가 없다. **설정 → 단축키**에서 하나 지정해두면 편하다.

### 기본 — 그냥 시킨다

볼트 전체가 작업 폴더다. **지금 보고 있는 노트는 자동으로 첨부**되므로 따로 붙일 필요가 없다.

> "리서치 폴더 노트들 프론트매터 `updated` 를 오늘로 바꿔줘"
> "pickzzk 결정 노트 중 2026-05월 것만 목록으로 뽑아줘"
> "이 노트 표를 날짜순으로 정렬해줘"

### 기호 네 개

| 기호 | 뜻 | 예 |
|---|---|---|
| `@` | 파일·폴더·서브에이전트 물기 | `@구현-대조표 요약해줘` |
| `/` | 프롬프트 템플릿 · Claude Code 슬래시 커맨드 | `/compact` |
| `$` | 스킬 호출 | `$browse` · `$make-pdf` |
| `!` | bash 직접 실행 | **기본 꺼짐** (`enableBangBash`) |

`loadUserSettings: true` 라 `~/.claude/skills` 의 스킬이 그대로 딸려온다 — `browse` · `investigate` · `spec` · `make-pdf` · `design-review` · `document-generate` 등.

### 인라인 편집 — 제일 많이 쓴다

노트에서 문단을 드래그로 선택 → 단축키 → 고칠 내용을 말하면 **단어 단위 diff** 로 미리 보여주고 적용 여부를 묻는다. 노트를 떠나지 않고 끝난다.

### 플랜 모드 — `Shift+Tab`

볼트를 건드리기 전에 **계획부터 세우게 한다.** 여러 파일을 고치는 작업은 반드시 이걸 켜고 시킬 것. 아래 [사고 기록](#왜-이걸-쓰나--외부-편집-충돌을-줄인다) 같은 일을 막는 안전장치다.

### 그 밖에

- **탭/세션** — 작업마다 탭을 따로 판다. 단일창/이중창 모드
- **Collab 모드** — 같은 랜 안의 기기끼리 공유 (git 필요, 클라우드 경유 없음)
- **비전** — 이미지를 드래그·붙여넣기·경로로 넘겨 분석
- **MCP** — 플러그인이 따로 관리하지 않고 각 CLI 의 네이티브 MCP 설정을 그대로 쓴다

### 안 붙을 때

`Copy startup diagnostics` 를 실행하면 진단 정보가 클립보드에 담긴다. 대부분은 CLI 경로 또는 `PATH` 문제다 — [설정](#설정) 절 참고.

## 지식저장소 · 위키로 쓰기

> [!info] 클로디언 자체는 지식관리 도구가 아니다
> 공식 README 에는 노트 정리·링크·요약에 대한 **처방된 워크플로가 없다.** 범용 코딩 에이전트를 옵시디언에 얹은 것에 가깝다.
> 위키가 되는 건 **볼트가 작업 폴더**이기 때문이고, 규칙은 네가 줘야 한다.

### 이 볼트의 현재 상태 (2026-09-01 실측)

| | |
|---|---|
| 노트 | 107개 |
| 태그 없는 노트 | **39개 (36%)** |
| 서로 다른 태그 | 83개 |
| 1회만 쓰인 태그 | **52개 (62%)** — `LoL` `ONNX` `R21` `aggregate` `closed` `dev` `incident` `legacy` … |
| 아무도 안 가리키는 고아 노트 | **34개** (pickzzk `결정/` 대부분) |
| 밖으로 링크가 없는 노트 | 32개 |

태그가 83개인데 62%가 한 번씩만 쓰였다 — **분류 체계가 아니라 낙서에 가깝다.** 고아 노트 34개는 그래프 뷰에서 점만 떠 있다.

### 바로 시킬 수 있는 세 가지

**① 태그 체계 정리 — 사서 역할**

> 볼트 전체 태그를 세어서 1~2회만 쓰인 것을 골라줘. 비슷한 것끼리 묶어 20개 안쪽 체계를 제안하고, 확정하면 프론트매터를 일괄로 바꿔줘. 태그 없는 노트 39개에는 내용을 보고 붙여줘.

**② 링크 복구 · MOC 만들기**

> pickzzk `결정/` 노트가 전부 고아다. 주제별로 묶어 허브 노트(MOC)를 만들고, 각 결정 노트에서 관련 결정끼리 서로 링크를 걸어줘.

**③ 쌓인 기록에서 회고 뽑기**

> pickzzk `결정/` 을 시간순으로 읽고, 반복해서 되돌린 결정이나 같은 이유로 실패한 패턴을 찾아줘.

이게 사람이 하면 며칠 걸려서 **결국 안 하게 되는** 종류의 일이다.

### 규칙을 굳혀야 계속 굴러간다

한 번 정리하고 끝나면 다시 흐트러진다. 두 군데에 규칙을 박을 수 있다.

- **볼트 루트 `CLAUDE.md`** — 매 세션 자동으로 읽힌다. **30줄 이내**로 유지할 것 (컨텍스트를 매번 먹는다). 절대 규칙만: 노트 배치, 파일명, 링크 형식, [[90_AI/claude/개념/클로디언#그래도 남는 주의점\|생 HTML 금지]] 같은 것
- **볼트 스코프 스킬** — README 기준 스킬은 *user- and vault-level scopes* 를 모두 읽는다. 반복 작업(주간 정리, 새 노트 템플릿)은 스킬로 빼면 필요할 때만 로드된다

세부 배경은 CLAUDE.md 에 넣지 말고 노트에 두고 링크로 가리킨다 — 이 노트처럼.

## 왜 이걸 쓰나 — 외부 편집 충돌을 줄인다

> [!warning] 이 볼트에서 실제로 터진 사고
> 2026-09-01, 터미널에서 볼트 파일을 고친 뒤 옵시디언에서 폴더를 옮겼더니 **옵시디언의 링크 자동 갱신이 캐시된 옛 문자 위치로 치환**하면서 노트를 훼손했다.
> - 인라인 `<svg>` 한가운데에 `[[링크]]`가 박힘 (3곳)
> - 마크다운 표 한 줄이 통째로 뭉개짐
> - 캔버스 노드 텍스트가 잘림 (`**13[[기록실-역설계|역설계 노트]]`)
>
> 원인은 **옵시디언이 파일을 캐시하고 있는 동안 밖에서 같은 파일을 고친 것**이다.

클로디언은 에이전트를 **옵시디언 프로세스 안에서** 굴리므로 이 충돌이 줄어든다. 볼트 작업은 가능하면 여기서 시키는 게 안전하다.

## 그래도 남는 주의점

1. **에이전트가 볼트에 쓰기 권한을 갖는다.** bash 실행도 된다. 되돌릴 수 없는 작업은 확인하고 시킬 것
2. **[[90_AI/claude/개념/메모리\|LiveSync]]가 동시에 돈다** — 이 볼트는 iCloud + Self-hosted LiveSync 이중 동기화다. 대량 파일 변경은 동기화 충돌을 만들 수 있다
3. **`.obsidian/*.json` 설정은 즉시 반영되지 않는다** — 앱이 시작할 때(또는 그 뷰를 처음 열 때) 읽고 메모리에 들고 있다. 에이전트가 밖에서 고쳐도 재시작 전엔 안 먹는다
4. 노트에 **생 HTML을 넣지 말 것** — 링크 갱신에 훼손된다. 그림은 별도 `.svg` 파일로 두고 `![[파일.svg]]`로 임베드
